# niucloud-admin 二次开发规范与开发文档

> 适用对象：新加入本项目的开发者（快速上手）+ 需要查阅架构约定的开发者（参考手册）
> 框架版本：niucloud-admin SaaS（PHP8 + ThinkPHP8 / Vue3 / Nuxt3 / uni-app）
> 维护说明：本文档基于当前仓库代码梳理，约定如与代码冲突，以代码为准并同步更新本文。

## 一、项目概览

niucloud-admin 是一套**多租户、多站点、多应用、多插件**任意组合的 SaaS 快速开发框架。核心理念是「框架提供底层 + 业务全部以插件（addon）形式开发」，因此**二开 = 写插件**，几乎不直接改动框架核心。

### 1.1 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后端 | PHP8 + ThinkPHP8 + MySQL8 + Redis | 内置 Workerman 消息队列与计划任务 |
| 管理后台 `admin` | Vite + Vue3 + TypeScript + ElementPlus + Pinia + vue-i18n | 平台端 / 站点端管理后台 |
| PC/H5 前台 `web` | Nuxt3 + ElementPlus + WindiCSS + Pinia | 站点前台（SSR 关闭，CSR） |
| 移动端 `uni-app` | uni-app + Vue3 + TS + WindiCSS | 编译 H5 / 微信小程序 / App / 其他小程序 |
| 站点端 `site-uniapp` | uni-app | 站点维度的移动端应用 |

### 1.2 五大工程（仓库根目录）

```
niucloud/            # 仓库根
├── niucloud/        # 【后端】PHP/ThinkPHP8 主工程，addon/ 插件也在这里
├── admin/           # 【前端】管理后台 (Vite+Vue3)
├── web/             # 【前端】PC/H5 站点前台 (Nuxt3)
├── uni-app/         # 【前端】通用移动端 (uni-app)
├── site-uniapp/     # 【前端】站点移动端 (uni-app)
├── docs/            # 设计/规范文档（本文所在目录）
├── scripts/ upgrade/ # 脚本与升级
```

> 关键认知：**一个插件的代码横跨多个工程**。后端插件源码在 `niucloud/addon/<插件名>/`，其中又分别带有 `app/`（后端）、`admin/`、`web/`、`uni-app/` 子目录。前端各工程通过发布脚本把插件前端复制到对应工程的 `addon/` 目录下参与构建。

## 二、环境准备与启动

### 2.1 后端

```bash
cd niucloud
composer install
# 配置数据库：访问 install.php 完成安装（生成 install.lock）
# 或手动导入 app/install/ 下的初始化 SQL 并配置 config/database.php
```

启动消息队列与计划任务（基于 Workerman）：

```bash
php think queue:work        # 消息队列消费
php think cron:schedule start   # 计划任务调度器（start|stop|restart|status）
```

### 2.2 前端

```bash
# admin（管理后台）
cd admin && pnpm install && pnpm dev

# web（Nuxt3 前台）
cd web && pnpm install && pnpm dev

# uni-app（移动端，按目标平台）
cd uni-app && pnpm install
pnpm dev:h5            # H5
pnpm dev:mp-weixin     # 微信小程序
pnpm dev:app           # App
```

各前端通过 `.env.development` 指定后端地址与请求头键名，例如 `admin/.env.development`：

```
VITE_APP_BASE_URL='http://127.0.0.1/adminapi/'
VITE_REQUEST_HEADER_TOKEN_KEY='token'
VITE_REQUEST_HEADER_SITEID_KEY='site-id'
VITE_REQUEST_HEADER_CHANNEL_KEY='Channel'
```

### 2.3 发布到后端

各前端工程根目录有 `publish.cjs`，构建产物会被复制进后端 `niucloud/public/` 下（admin → `public/admin`，web → `public/web` 等），并修正静态资源路径前缀。

## 三、SaaS 多租户 / 多站点核心概念（务必先理解）

这是整个框架最重要的约定，贯穿前后端：

- **`site_id`（站点 ID）是数据隔离的核心维度**。几乎所有业务表都带 `site_id` 字段，所有查询都必须按当前站点过滤。
- 前端每次请求都会在请求头携带 `site-id`（admin/uni-app 用 header，web 用 cookie）与 `token`。
- 后端 `BaseAdminService` 构造时自动从请求中取出并注入：`$this->site_id`、`$this->uid`、`$this->username`、`$this->app_type`，业务代码直接用即可。
- 前台 API 通过 `ApiChannel` 中间件校验 `site_id` 与渠道（wap/web/weapp 等）。

> **铁律**：新建业务表必须有 `site_id`；新写查询必须 `where('site_id', $this->site_id)`，否则会造成跨站点数据串号。

## 四、后端结构与分层

### 4.1 主工程 `niucloud/app/`

```
app/
├── adminapi/       # 管理后台 API（controller / middleware / route）
├── api/            # 前台客户端 API（controller / middleware / route）
├── service/        # 业务逻辑：admin/（管理端） core/（通用核心） api/（前台）
├── model/          # 数据模型（继承 core\base\BaseModel）
├── validate/       # 验证器（继承 think\Validate）
├── dict/           # 数据字典 / 常量
├── listener/       # 事件监听器（handle 方法）
├── job/            # 异步队列任务（继承 core\base\BaseJob）
├── command/        # CLI 命令（队列消费 / 计划任务调度 / 插件安装）
├── lang/           # 多语言（zh-cn / en）
├── install/        # 平台初始化安装
├── upgrade/        # 平台版本升级（vXXX/upgrade.sql + Upgrade.php）
├── event.php       # 事件注册表
├── middleware.php  # 全局中间件注册
├── provider.php service.php common.php
```

### 4.2 核心库 `niucloud/core/`

`base/` 提供所有基类；`pay/ sms/ oauth/ printer/ template/` 等为「可扩展通道」模块，统一采用**基类 + Loader 工厂**模式（如新增支付方式 = 继承 `BasePay`，由 `PayLoader` 加载）；`util/` 为工具集（TokenAuth、雪花 ID、二维码、队列分发等）。

| 基类 | 用途 | 关键能力 |
|------|------|----------|
| `BaseAdminController` | 后台控制器基类 | 统一参数获取、`success()`/`fail()` 响应 |
| `BaseController` | 前台控制器基类 | 同上 |
| `BaseAdminService` | 管理端服务基类 | **自动注入 `site_id`/`uid`/`username`/`app_type`** |
| `BaseService` | 通用服务基类 | 分页 `paginate()` 等 |
| `BaseModel` | 模型基类 | 表名 / 主键 / 字段类型映射 |
| `BaseJob` | 队列任务基类 | `runJob()` 调度 + `failed()` 失败处理 |

### 4.3 后端分层职责（控制器 → 服务 → 模型）

- **Controller**：只做参数接收（`$this->request->params([...])`）、调用 service、`return success(...)`，不写业务逻辑。
- **Service / admin**：管理端业务编排，处理权限、`site_id` 注入、操作人记录，再调用 core 服务。
- **Service / core**：可被 admin/api 复用的纯业务逻辑（推荐把核心规则写在 core，避免重复）。
- **Model**：仅做数据映射与查询作用域。
- **Validate**：输入校验，错误消息走多语言 key。
- **Dict**：状态常量 + `getXxxList()` 静态方法返回带名称的状态字典。

## 五、插件（Addon）机制 —— 二开核心

### 5.1 插件目录结构（以 `addon/hsx_recycle` 为例）

```
addon/<插件名>/
├── Addon.php              # 插件主类：install() / uninstall() / upgrade() 回调
├── info.json              # 插件元数据（必需）
├── app/                   # 【后端】结构与主工程 app/ 完全一致
│   ├── adminapi/controller/ ...  + adminapi/route/route.php
│   ├── api/controller/ ...       + api/route/route.php
│   ├── service/{admin,core,api}/
│   ├── model/ validate/ dict/ listener/ job/ command/ lang/
│   └── dict/menu/{admin.php,site.php}   # 菜单定义
│   └── dict/schedule/schedule.php       # 计划任务定义
├── admin/                 # 【前端】挂载到 admin 工程 (api/views/components/lang/...)
├── web/                   # 【前端】挂载到 web 工程
├── uni-app/               # 【前端】挂载到 uni-app 工程（pages/api/components/locale）
├── package/               # 前端依赖与页面声明（admin-package.json / uni-app-package.json / uni-app-pages.php）
├── sql/                   # install.sql / uninstall.sql / update_x.x.x.sql
├── resource/              # 静态资源（diy 装修、tabbar、报告模板等）
└── docs/ doc/ README.md   # 插件自带文档
```

### 5.2 插件元数据 `info.json`

```json
{
  "title": "二手机报价",
  "desc": "手机回收系统",
  "key": "hsx_recycle",      // 插件唯一标识，与目录名一致
  "version": "0.0.4",         // 版本号，决定升级 SQL 执行范围
  "author": "hsx",
  "type": "app",
  "support_version": "1.2.0"  // 依赖的框架最低版本
}
```

### 5.3 后端命名与继承约定

命名空间统一以 `addon\<插件名>\app\...` 开头。

**控制器**（`app/adminapi/controller/<模块>/Xxx.php`）：

```php
namespace addon\hsx_recycle\app\adminapi\controller\order;

use core\base\BaseAdminController;
use addon\hsx_recycle\app\service\admin\order\RecycleReturnOrderService;
use addon\hsx_recycle\app\validate\RecycleReturnOrderValidate;

class RecycleReturnOrder extends BaseAdminController
{
    protected $service;
    protected $validate;

    public function __construct(\think\App $app)
    {
        parent::__construct($app);
        $this->service  = new RecycleReturnOrderService();
        $this->validate = new RecycleReturnOrderValidate();
    }

    public function lists()
    {
        $params = $this->request->params([
            ['order_no', ''], ['status', ''],
        ]);
        return success($this->service->getList($params));
    }
}
```

**服务**（admin 调 core，core 写核心逻辑）：

```php
namespace addon\hsx_recycle\app\service\admin\order;

use core\base\BaseAdminService;
use addon\hsx_recycle\app\service\core\recycle_order\RecycleReturnOrderService as CoreService;

class RecycleReturnOrderService extends BaseAdminService
{
    private $core;
    public function __construct() { parent::__construct(); $this->core = new CoreService(); }

    public function create(array $data): array
    {
        $data['site_id']       = $this->site_id;   // 基类自动注入
        $data['operator_id']   = $this->uid;
        $data['operator_name'] = $this->username ?? '';
        return $this->core->create($data);
    }
}
```

**模型 / 字典**：模型继承 `core\base\BaseModel` 并声明 `$table`；字典类用大写常量 + `getXxxList()` 返回带 `name/desc` 的状态表。

### 5.4 路由与鉴权

插件路由写在 `app/adminapi/route/route.php`（后台）与 `app/api/route/route.php`（前台），由框架的多应用机制自动加载。控制器以全命名空间字符串绑定：

```php
use think\facade\Route;
use app\adminapi\middleware\{AdminCheckRole, AdminCheckToken, AdminLog};

Route::group('recycle', function () {
    Route::get('recycle_return_order/lists',
        'addon\hsx_recycle\app\adminapi\controller\order\RecycleReturnOrder@lists');
    Route::post('recycle_return_order',
        'addon\hsx_recycle\app\adminapi\controller\order\RecycleReturnOrder@create');
})->middleware([AdminCheckToken::class, AdminCheckRole::class, AdminLog::class]);
```

中间件职责：

| 中间件 | 端 | 作用 |
|--------|----|----|
| `AdminCheckToken` | 后台 | 校验管理员 token，注入 uid/username，校验站点权限 |
| `AdminCheckRole` | 后台 | 基于菜单的权限校验 |
| `AdminLog` | 后台 | 记录操作日志 |
| `ApiChannel` | 前台 | 校验 `site_id` 与渠道（wap/web/weapp） |
| `ApiCheckToken` | 前台 | 校验用户登录（第二参数 `true/false` 控制是否强制登录） |
| `ApiLog` | 前台 | 记录前台 API 日志 |

> 另：`route/app.php` 还会扫描每个插件的 `app/config/route.php`（如存在）并 include，可用于注册非标准路由。

### 5.5 安装 / 卸载 / 升级

三处协同：

1. **SQL 脚本**（`sql/`）：`install.sql` 建表、`uninstall.sql` 删表、`update_x.x.x.sql` 各版本增量。表名用占位符 `{{prefix}}`，安装时替换为真实表前缀。
   ```sql
   CREATE TABLE IF NOT EXISTS `{{prefix}}express_order_record` (
     `id` int NOT NULL AUTO_INCREMENT,
     `site_id` int NOT NULL DEFAULT '0' COMMENT '站点id',
     ...
   );
   ```
2. **`Addon.php` 回调**：写 SQL 之外的初始化逻辑（系统表加字段、同步资源、注册/卸载计划任务等）。
   ```php
   class Addon {
       public function install()   { /* 初始化、注册计划任务 */ return true; }
       public function uninstall() { /* 清理、卸载计划任务 */ return true; }
       public function upgrade()   { /* 升级补偿 */ return true; }
   }
   ```
3. **菜单**：`app/dict/menu/admin.php`（后台菜单）、`app/dict/menu/site.php`（站点菜单）以数组声明，安装时写入 `sys_menu`，并参与权限控制。

### 5.6 事件 / 监听

- 平台事件注册表：`app/event.php`，`listen` 中一个事件名可挂多个监听器，按顺序执行。
- 插件可在自身 `app/event.php` 或 `app/listener/` 下提供监听器，监听器实现 `handle($params)`。
- 触发：`event('PaySuccess', [$data])`。

```php
// 监听器示例
class MemberRegisterListener {
    public function handle($member) {
        CoreMemberService::sendGrowth($member['site_id'], $member['member_id'], 'member_register', []);
        event('MemberLoginAfter', ['site_id' => $member['site_id'], 'member_id' => $member['member_id']]);
    }
}
```

### 5.7 消息队列 Job

```php
namespace addon\hsx_recycle\app\job\order_event;
use core\base\BaseJob;

class ReturnOrderAutoComplete extends BaseJob {
    public function doJob($site_id, $order_id) { /* ... */ return true; }
    public function failed($data) { /* 失败处理 */ }
}
```

分发（`core\util\Queue`）：`Queue::dispatch(Job::class, ['method'=>'doJob','data'=>[...]], $site_id, $biz_id, $delaySeconds)`。需 `php think queue:work` 消费。

### 5.8 计划任务 Schedule

在 `app/dict/schedule/schedule.php` 声明，由 `Addon::install()` 注册、`php think cron:schedule start` 调度：

```php
return [[
    'key'      => 'return_order_auto_complete',
    'name'     => '退货订单自动完成',
    'time'     => ['type' => 'min', 'min' => 30],  // sec|min|hour|day|week|month
    'class'    => 'addon\hsx_recycle\app\job\order_event\ReturnOrderAutoComplete',
    'function' => 'doJob',
]];
```

## 六、前端二开约定

四个前端的共性：**插件前端源码放在 `addon/<插件名>/<端>/`，构建时复制到对应工程的 `addon/` 目录**，再被主工程动态聚合（路由、API、i18n）。请求统一携带 `token` + `site-id`。

### 6.1 admin（管理后台，Vite+Vue3+ElementPlus）

目录：`admin/src/addon/<插件名>/{api,views,components,lang,hooks,constants,types,styles,router}`。

- **路由**：插件在 `src/addon/<插件名>/router/index.ts` 导出 `ROUTE` / `NO_LOGIN_ROUTES`，`src/router` 通过 `import.meta.globEager('@/addon/**/router/index.ts')` 动态合并。
- **API**：统一 `import request from '@/utils/request'`，`request.ts` 拦截器自动注入 token 与 site-id 头。
  ```ts
  export function getDeliveryCompanyList(params = {}) {
    return request.get('recycle/delivery/company/list', { params })
  }
  ```
- **i18n**：`src/lang/i18n.ts` 用 `import.meta.globEager('@/addon/**/lang/zh-cn/common.json')` 合并各插件公共语言；页面级语言按路径懒加载。文件放 `addon/<插件名>/lang/{zh-cn,en}/<page>.json`。
- **ElementPlus**：通过 `unplugin-auto-import` / `unplugin-vue-components` 自动按需引入，无需手动 import。

### 6.2 web（Nuxt3 前台）

目录：`web/addon/<插件名>/{app,api,lang}`；主工程 `app/`、`composables/`、`stores/`、`middleware/`、`layouts/`。请求封装 `utils/request.ts` 从 cookie 取 `siteId`、固定 `Channel='pc'`、带 token。`nuxt.config.ts` 中 `baseURL: '/web/'`、`ssr: false`。

### 6.3 uni-app / site-uniapp（移动端多端）

目录：`uni-app/src/addon/<插件名>/{pages,api,components,locale}`。

- **分包**：插件页面在 `pages.json` 中以 `subPackages` 形式按 `root: "addon/<插件名>"` 注册，提升加载性能。
- **多端编译**：`pnpm build:h5 | build:mp-weixin | build:app`，微信小程序构建时 `publish.cjs` 额外处理自定义组件、多语言、WXML 转义。
- **请求**：`utils/request.ts` 封装 `uni.request`，注入 token / site-id（header），并区分 H5 / 非 H5 的 baseUrl；提供 `get/post/upload`。
- **i18n**：语言标识 `zh-Hans` / `en`，插件语言在 `addon/<插件名>/locale/<locale>/<page>.json`。

### 6.4 请求头与响应码约定（前端通用）

| 请求头 | 含义 | 来源 |
|--------|------|------|
| `token` | 用户/管理员令牌 | 本地存储，登录后写入 |
| `site-id` | 站点标识 | 本地存储 / cookie / 环境变量 |
| `Channel` | 渠道（pc/h5/mp-weixin/app） | 运行环境推断 |

| code | 含义 |
|------|------|
| 1 | 成功 |
| 0 | 业务错误（弹提示） |
| 401 | 未授权（自动登出） |
| 402 | 站点关闭 |
| 403 | 无站点（uni-app 跳转无站点页） |

## 七、命名与编码规范速查

| 类型 | 命名 | 命名空间/位置 | 继承 |
|------|------|--------------|------|
| 后台控制器 | `Xxx`（业务名，PascalCase） | `addon\<key>\app\adminapi\controller\<模块>` | `BaseAdminController` |
| 前台控制器 | `Xxx` | `addon\<key>\app\api\controller\<模块>` | `BaseController` |
| 管理端服务 | `XxxService` | `app\service\admin\<模块>` | `BaseAdminService` |
| 核心服务 | `CoreXxxService` / `XxxService` | `app\service\core\<模块>` | `BaseService` |
| 模型 | 表名 PascalCase | `app\model\<模块>` | `BaseModel` |
| 验证器 | `XxxValidate` | `app\validate\<模块>` | `think\Validate` |
| 字典 | `XxxDict` | `app\dict\<模块>` | — |
| 监听器 | `XxxListener` | `app\listener\<模块>` | — |
| 队列任务 | `XxxJob` / 动作名 | `app\job\<模块>` | `BaseJob` |
| 前端 API | 文件按业务拆分 | `<端>/addon/<key>/api/*.ts` | — |
| 前端页面 | kebab/小写目录 + `.vue` | `<端>/addon/<key>/views(或 pages)` | — |

通用：文件头统一 `declare(strict_types=1);`（后端）；多语言文案不要硬编码，走 i18n key；所有业务查询带 `site_id`。

## 八、实操：新增一个业务模块的完整流程

1. **建表**：在 `addon/<key>/sql/install.sql` 增加 `{{prefix}}xxx`（含 `site_id`、`create_time` 等），并在 `uninstall.sql` 增加 DROP；如对已发布插件升级，新增 `update_<新版本>.sql` 并在 `info.json` 提升 `version`。
2. **模型**：`app/model/<模块>/Xxx.php` 继承 `BaseModel`，声明 `$table`。
3. **字典**：`app/dict/<模块>/XxxDict.php` 定义状态常量与 `getXxxList()`。
4. **核心服务**：`app/service/core/<模块>/XxxService.php` 写业务逻辑。
5. **管理端服务**：`app/service/admin/<模块>/XxxService.php` 注入 `site_id/uid` 后调 core。
6. **验证器**：`app/validate/<模块>/XxxValidate.php`，消息用多语言 key。
7. **控制器**：`app/adminapi/controller/<模块>/Xxx.php` 接参 → 调 service → `success()`。
8. **路由**：在 `app/adminapi/route/route.php` 注册并挂中间件。
9. **菜单**：在 `app/dict/menu/admin.php` 增加菜单项（关联权限）。
10. **前端**：`admin/src/addon/<key>/api/xxx.ts` 写接口、`views/` 写页面、`router/index.ts` 注册路由、`lang/` 加多语言。
11. **（可选）事件 / 队列 / 计划任务**：按 §5.6–5.8 增补。
12. **联调**：后端起 `queue:work` 与 `cron:schedule`，前端 `pnpm dev` 对接。

## 九、现有业务插件地图（参考）

当前仓库的业务主要是**二手机回收 → 质检定价 → ERP/财务 → 商城出货**这条链路，由一组 `hsx_*` / `recycle_*` / `phone_shop` 插件协作：

| 插件 | 作用 |
|------|------|
| `hsx_recycle` | 二手机回收主系统：回收下单、质检、设备流转、退回订单、报价、打印 |
| `hsx_erp` | ERP：入库财务、对账、角色权限、账务模型 |
| `hsx_device_asset` | 设备资产管理 |
| `hsx_phone_query` | 机型/参数查询 |
| `hsx_clipboard_upload` | 拍照/剪贴板上传中台 |
| `phone_shop` | 二手商城：线下出货、部分退货、多站代理铺货与联动 |
| `recycle_quote_spider` | 回收报价爬取（历史价格/趋势/浏览量埋点） |
| `recycle_daheng_quote` | 大恒报价对接 |
| `shop` / `tk_vip` / `tk_wifi` 等 | 通用商城与其他业务插件 |

> `docs/` 目录下已有大量针对该业务的专项设计文档（如《二手机系统整体架构图.svg》《二手商城_ERP对接契约》《审计报告-财务结算模块》等），二开具体业务前建议先查阅对应专项文档。
