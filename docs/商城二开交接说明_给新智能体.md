## 1. 我的诉求（目标）

### 3.2 接入财务（硬性对接契约，必须照此做）

**(a) 往来单位锚 = member_id（最关键，先理解）**
折账是把"同一个客户"的应收和应付互相抵消。所以：
- 商城订单的买家，必须是平台会员，拿得到 **member_id**。
- 你发应收事件时，`counterparty_id` 必须填**这个买家的 member_id**。
- 这样它才能和回收侧"同一个 member_id 的应付"对齐、折账。否则账对不上、折不了。

**(b) 在"订单完成"时发一个事件**
时机：订单**支付完成/履约完成**（以订单为最小颗粒度，一单一笔）。
代码（ThinkPHP，故障隔离，失败不能影响下单）：

```php
try {
    \think\facade\Event::trigger('FinanceReceivableCreated', [
        'event'             => 'finance.receivable.created.v1',
        'event_id'          => 'mall_receivable_' . $orderId, // 幂等键，重复发不会重复记
        'site_id'           => $siteId,
        'counterparty_id'   => $buyerMemberId,   // 买家 member_id（与回收同锚）
        'counterparty_name' => $buyerName,       // 买家名（快照，可空）
        'amount'            => $orderAmount,      // 订单应收金额
        'source_type'       => 'mall_order',
        'source_no'         => $orderNo,          // 订单号（回收侧要据此显示关联了哪个订单）
        'source_device_id'  => $deviceId ?? 0,    // 整机订单带上设备ID，可精确到机；无则 0
        'occurred_at'       => time(),
    ]);
} catch (\Throwable $e) { /* 仅记日志，不要打断下单 */ }
```

**(c) 你的自检清单（做到这四点应收就通了）**
1. 订单能确定唯一买家，且买家 = 平台 member（拿得到 member_id）。
2. 有明确的"订单完成"时机可以挂这个事件。
3. 订单号、金额稳定可取；整机订单最好能关联到设备身份（source_device_id）。
4. 在订单完成处发上面那个事件，故障隔离。

> 完整契约见仓库文件：`niucloud/addon/hsx_erp/docs/应付与结算契约_财务插件接入预留.md`（第 10 节）。可一并发给你参考。

## 4. 架构红线（必须遵守，违反会破坏系统）

1. **不改 niucloud 核心框架**。所有代码只写在 `addon/<你的商城插件>/` 目录内。
2. **插件独立**：跨插件**只发标准事件**（事件名带版本如 `.v1` + `event_id` 幂等），**绝不直接读写别的插件的数据库表**。
3. **优雅降级**：用 `class_exists` 或"发事件没人听=空操作"的方式，保证财务/ERP 不在时商城照常能用。
4. **故障隔离**：所有跨插件副作用都包 try/catch，**失败只记日志，不能回抛打断商城自己的主流程**（下单、支付绝不能因为发事件失败而失败）。
5. **admin 前端双份同步**：如果你改了后台前端，`admin/src/addon/<插件>/...` 的改动要同步复制到 `addon/<插件>/admin/...`（这是本项目的约定）。
6. **不要去改回收/ERP/财务的代码**。你只管商城 + 发那一个应收事件。
