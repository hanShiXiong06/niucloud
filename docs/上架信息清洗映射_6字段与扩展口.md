# 商城上架信息清洗映射 · 6 字段与扩展口

> ERP 上架带 3 样过来:**图片 / 质检报告(qc_info) / 价格**。商城把它们清洗整理,自动映射到商品的 6 个字段,**全给默认,留扩展口**。

## 一、数据从哪来

中台定价完成 `device_asset.price.completed.v1`(payload 含 `images / qc_info(check_summary) / sale_price / model_name / imei …`)
→ 商城 `DeviceAssetPricedListener` → `CoreDeviceIntakeService::saveFromEvent` 落成**待上架货源** `DeviceIntake`(按 `erp_asset_id` 幂等)。

`qc_info` 是关联数组 `{检测项: 值}`,含「容量」「颜色」等(来自中台 `buildCheckSummary`)。

## 二、6 字段映射(目标 → 商城存储)

| # | 字段 | 商城存储 | 默认来源 |
|---|---|---|---|
| 1 | 服务标签 | `goods.service_ids` (JSON) | 配置 `default_service_ids`,空=不挂 |
| 2 | 内存分类 | `goods.memory_group` | 货源 memory，空则 `qc_info.容量`，再归一化(256g→256GB) |
| 3 | 标题 | `goods.goods_name` | 模板 `{brand} {model} {memory} {color}` |
| 4 | 副标题 | `goods.sub_title` | 模板 `{condition} · 一机一检 · {warranty}` |
| 5 | 质检报告 | 进 `goods.goods_desc`(结构化文本);原始 qc 仍存 `goods_sku.device_snapshot` | `qc_info` 清洗成"项：值"列表 |
| 6 | 发货方式 | `goods.delivery_type` (JSON) | 配置 `default_delivery_type`,默认 `['express']` |

## 三、核心引擎

`addon/phone_shop/app/service/core/intake/CoreListingMappingService.php`

- `mapIntake($intake, $overrides, $config)` → 产出 6 字段(+清洗后的 images/cover/price)。
- **优先级:`overrides`(人工表单) > `config`(站点配置) > 内置默认。**
- 工具:`normalizeMemory`(内存归一化+别名)、`render`(占位符模板)、`squeeze`(折叠空格/清悬挂分隔符)、`buildQcReport`(质检报告结构化)、`normalizeImages`。

占位符:`{brand} {model} {memory} {color} {condition} {imei} {warranty}`。

## 四、扩展口(改默认/加非默认,不动代码)

站点配置键 `PHONE_SHOP_LISTING_MAPPING`(存于平台 `CoreConfigService`),可配:

```
title_template          标题模板
subtitle_template       副标题模板
warranty_text           质保话术(默认"七天质保")
default_service_ids[]   默认服务标签
default_label_ids[]     默认角标
default_delivery_type[] 默认发货方式
memory_aliases{}        内存别名映射(如 "8+256":"8GB+256GB")
qc_report_enabled       是否启用质检报告
qc_report_title         质检报告标题
qc_hidden_keys[]        质检报告隐藏项
```

读写接口(已就位):
- `GET  phone_shop/device_intake/mapping_config`
- `POST phone_shop/device_intake/mapping_config`

> ⏳ 站点配置目前仅 API 就位,**尚无设置页 UI**。有非默认需求时再加可视化设置页(或直接告诉我默认值,我写进配置)。

## 五、建品流程(人在环上,全预填)

1. 待上架货源列表 → 点「建品上架」。
2. 弹窗打开即调 `POST device_intake/preview` → 引擎按配置算出 6 字段默认值,**自动预填**(标题/副标题/内存分类/服务标签/发货方式 + 质检报告分项展示 + 详情默认填质检文本)。
3. 店员可**逐项改**(改动即 overrides)。
4. 提交 `POST device_intake/build` → `DeviceIntakeService::build()` 再跑一遍引擎(表单值作 overrides),`GoodsService::add()` 建品 + 补二手机字段 + 回填货源为已建品。
