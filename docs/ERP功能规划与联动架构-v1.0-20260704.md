## 一、产品定位

### 1.1 三种使用模式

| 模式 | 说明 |
|------|------|
| **单机模式** | 门店独立使用，不依赖其他插件，完整的进销存财务闭环 |
| **中台模式** | 作为系统数据中台，统一管理所有渠道的进货、库存、销售、收付款 |
| **联动模式** | 与回收（hsx_recycle）、商城（phone_shop）双向事件打通，自动流转单据 |

三种模式是同一套代码，通过配置和事件监听状态决定生效范围。

### 1.2 核心原则（不得偏离）

1. **一物一码**：每台设备一条 `erp_asset` 记录，所有账挂到设备维度
2. **财务在 ERP 内闭环**：不外拆到其他插件
3. **跨插件只走事件**：ERP 不 use 回收/商城的类，外部插件不写 ERP 的表
4. **错账不涂改**：纠错走反向流水/退货/成本调整，禁止 UPDATE 历史流水
5. **所有钱的动作必须过财务确认队列**

## 二、仓库体系

### 2.1 仓库分类

| 仓库类型 | 上架渠道 | 财务性质 | 说明 |
|---------|---------|---------|------|
| **二手机舱** | 商城（满足三要素后） | 正常进销存 | 主仓，下设库位，按品类分配库管 |
| **同行仓** | 不上架商城 | 正常进销存 | 批发/同行出货，ERP直接开销售单 |
| **代卖仓** | 可上架商城 | 特殊：物权≠店铺 | 货主寄卖，卖出→结算，未卖→退还 |
| **线下门店仓** | 不推商城 | 正常进销存 | 门店现货，ERP线下开单 |

### 2.2 二手机舱内部结构

```
二手机舱
  ├── 库位 A
  │     责任人：张三（苹果品类）
  │     职责：设置苹果设备的销售定价
  ├── 库位 B
  │     责任人：李四（安卓品类）
  │     职责：设置安卓设备的销售定价
  └── 库位 N（可配置）
```

责任人分工可按：**库位 / 仓库 / 品类**，在基础设置里配置，不硬编码。

### 2.3 代卖流程

```
货主送货 → 代卖入库（物权标记=货主）
    │
    ├─ 卖出 → 生成应付（欠货主的钱）→ 财务结算 → 货主收款
    │
    └─ 未卖 → 货主取回 → 关闭代卖单（不产生财务事实）→ 设备退出库存
              如需重新委托 → 重新入库开新代卖单
```

## 三、上架流水线（中台 + ERP 边界）

### 3.1 系统边界划分

| 操作 | 在哪完成 | 负责人 |
|------|---------|-------|
| 回收定价（买入价） | hsx_recycle | 回收员 |
| 采购入库 | hsx_erp | 采购员 |
| 拍照（如需） | 中台 | 专职拍照员 |
| **销售定价（卖出价）** | 中台 / ERP | 库管（按品类分工） |
| 上架触发 | 中台 | 自动（三要素满足后触发） |
| 退货/取消/收付款 | hsx_erp | 财务 |

### 3.2 上架三要素

```
销售价格 > 0（由库管设置）
    AND
照片 ≥ 1 张
    AND
质检报告 OR 描述摘要（满足其一即可）
```

三要素全部满足 → 中台触发 `erp.asset.ready_for_sale` 事件 → 商城自动上架。

### 3.3 设备进入二手机舱后的流转

```
设备入库（二手机舱）
        │
        ├─── 来自回收（有照片 + 有质检报告）
        │         │
        │         └→ 仅需库管定销售价 → 三要素满足 → 推商城
        │
        ├─── 来自回收（无照片 + 有质检报告）
        │         │
        │         └→ 中台补拍 → 库管定价 → 三要素满足 → 推商城
        │
        └─── 直接采购 / 手工入库（无照片、无质检）
                  │
                  └→ 中台补拍 + 补描述 → 库管定价 → 三要素满足 → 推商城
```

### 3.4 工作模式开关（配置项）

| 模式 | 适用场景 | 行为 |
|------|---------|------|
| **团队模式** | 3人以上，有分工 | 入库→拍照→定价分步流转，工作台有待办提示 |
| **小店模式** | 1-2人 | 入库时一次性填完价格+照片+描述，直接就绪，无中间等待 |

同一套代码，配置项控制是否强制分步。

## 四、跨插件联动架构

### 2.1 总体拓扑

```
      ┌────────────────────────────────────────┐
      │              hsx_erp（中台）             │
      │  采购 ─→ 库存 ─→ 销售 ─→ 收付款 ─→ 账目  │
      └──────┬──────────────────────┬──────────┘
             │ 事件（双向）           │ 事件（双向）
             ▼                      ▼
    ┌──────────────┐       ┌──────────────────┐
    │  hsx_recycle │       │   phone_shop      │
    │  回收工单      │       │   商城订单/上架    │
    └──────────────┘       └──────────────────┘
```

### 2.2 回收 → ERP（采购方向）

**触发条件**：回收工单状态流转为"客户确认出售"

```
回收工单确认出售
    │
    ▼ 发出事件：recycle.order.confirmed_sale
    │  payload: { order_id, imei, model, condition, price, customer_id, customer_name }
    │
    ▼ ERP 监听并处理（ErpIntegrationService::handleRecycleConfirmed）
    │
    ├─ 自动创建采购单（source_type=recycle, source_id=order_id）
    ├─ 自动创建 erp_asset（IMEI/型号/成色从 payload 读取）
    ├─ 入库成本 = 回收报价
    ├─ 生成应付（往来对象 = 该客户，欠款状态）
    └─ 写入库存流水（action=purchase_in, source=recycle_order）
```

**ERP 完成打款后**：

```
ERP 财务确认付款
    │
    ▼ 发出事件：erp.payment.confirmed
    │  payload: { asset_id, source_type=recycle, source_id=order_id, amount, paid_at }
    │
    ▼ 回收侧监听
    └─ 更新工单状态：已打款 + 打款金额 + 打款时间
```

### 2.3 ERP → 商城（销售方向）

**触发条件**：中台三要素满足（价格+照片+描述/质检报告）

```
中台三要素就绪
    │
    ▼ 发出事件：erp.asset.ready_for_sale
    │  payload: { asset_id, imei, model, images[], retail_price,
    │             description/quality_report, warehouse_id, channel }
    │
    ▼ 商城侧监听
    └─ 自动创建商品 SKU + 按渠道上架
```

**线上购买开关**（配置项）：

| 开关状态 | 商城行为 | 适用场景 |
|---------|---------|---------|
| OFF（默认） | 商城展示，员工代客开单，不开放自助购买 | 当前客户 |
| ON | 客户可自助在线下单支付 | 未来扩展 |

**商城订单 → ERP（所有财务操作在 ERP 完成）**：

```
商城开单（员工操作 或 客户自助）
    │
    ▼ 发出事件：mall.order.created
    │
    ▼ ERP 处理
    ├─ 自动创建销售单
    ├─ 设备状态 → 已售
    └─ 生成应收（线下=欠款状态；线上已付=已收款状态）

线上支付完成：mall.order.paid → ERP 自动标记已收款，写资金流水，财务只需对账
线下收款：财务在 ERP 手动确认（现金/微信/支付宝）

退货：mall.order.returned → ERP 走销售退货流程 → 设备回库 + 应收反冲
取消：mall.order.cancelled（未发货）→ ERP 撤销销售单 → 设备回库

所有退货/取消/收款操作全部在 ERP 完成，商城只接收状态同步回写。
```

### 2.4 仓库 → 渠道映射规则

| 仓库 | 上架渠道 | 说明 |
|------|---------|------|
| 二手仓 | 商城二手频道 | 入库后自动推送上架 |
| 样机仓 | 不上架 | 仅限借出管理 |
| 批发仓 | 批发渠道（待扩展） | 批量出货 |
| 回收仓 | 不上架 | 暂存待整备，整备完成后转二手仓 |
| 线下门店仓 | 不推商城 | 线下销售，ERP直接开单 |

仓库与渠道的映射在 ERP 基础设置里配置，不硬编码。

## 八、MVP 验收标准

### 单机模式验收（必须通过）

参照架构裁定文档的"一台设备走一生"剧本和十二问验收标准。

### 联动模式验收（P2 后执行）

**回收联动验收**：
1. 回收工单流转为"确认出售" → ERP 自动生成采购单 + 应付
2. ERP 财务确认付款 → 回收工单状态自动变为"已打款"
3. 全程无需手动在两边重复录入

**商城联动验收**：
1. ERP 设备入库（二手仓）→ 商城自动上架
2. 商城线上支付 → ERP 自动生成销售单 + 已收款应收 + 资金流水
3. 财务只需对账，无需手动录收款
4. ERP 线下收款 → 商城订单状态同步为已收款

## 十一、产品设计三原则

> 背景：上一版产品因功能堆叠、用户不知道如何使用而胎死腹中。本版设计必须避免同样的问题。

### 原则一：菜单即动线，不超过 8 项

每个菜单项只回答一个业务问题：

| 菜单 | 回答的问题 |
|------|----------|
| 工作台 | 我今天要做什么？ |
| 采购 | 货怎么进来的？ |
| 库存 | 货在哪里？ |
| 销售 | 货怎么卖出去的？ |
| 应收款 | 谁欠我钱？ |
| 应付款 | 我欠谁钱？ |
| 账目流水 | 钱怎么动的？ |
| 基础设置 | 系统怎么配置的？ |

新能力优先长在现有页面的按钮/抽屉里，**禁止新增菜单**。

### 原则二：财务是命脉，先于功能堆叠验证

每个业务动作上线前，必须回答：
- 这个动作产生应收/应付了吗？金额对吗？
- 资金流水落账了吗？账户余额正确吗？
- 三本流水（库存流水/账目流水/结算明细）都写入了吗？
- 三处对账（应收应付 ⟺ 往来汇总 ⟺ 资金流水）随时能对平吗？

**三处对不平 = 不上线。**

### 原则三：先跑通一台设备的一生，再做宽度

任何新模块上线前，必须先跑通主链路验收剧本：

```
采购开单 → 设备入库 → 中台定价/拍照 → 上架商城
    → 销售开单（或商城开单）→ 财务收款
    → 退货（如需）→ 财务反冲
    → 十二问全部可查
```

主链路断了的功能，不算完成。
