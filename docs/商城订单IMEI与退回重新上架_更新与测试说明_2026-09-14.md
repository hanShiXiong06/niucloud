日期：2026-09-14  
状态：本地代码与回归完成，未部署生产；没有实际调用支付或退款渠道。

## 一、这次的业务结果

本次处理 **phone_shop 商城订单、线下订单与 ERP 原销售退回的闭环**，不是单独添加一个“重新上架”按钮。

- “商城订单”和“线下待处理/线下订单”共用订单列表，列表、详情页和详情抽屉均显示 IMEI；有 SN 时同时显示 SN。
- 新订单优先显示下单时保存的设备快照，不随商品后来修改串号而变化。
- 没有快照的旧订单可以显示当前商品资料，但会明确注明来源，不冒充原成交快照。
- “退回处理”中显示原业务员或线下经手人；缺少信息时提示核对实际交付人，不随意指定人员。
- ERP 是线下现结、挂账订单的退回/结算事实来源；线上支付仍从原商城订单办理原路退款。
- 退回保留原订单、设备明细、原成交金额、历史付款金额，不删除原单，也不将已付款归零。
- 页面保留原成交金额不代表仍需收款；退回提示中的“原单剩余应收”“待退给客户”取自 ERP 当前账务。
- 重新上架只改变商品可售状态，**不创建销售单、采购应付、应收或收款流水**。后续真正被另一笔新订单买走时，才是新成交。

## 二、管理员实际怎么操作

| 当前情况 | 正确操作 | 商品/账务结果 |
| --- | --- | --- |
| 刚拍下，未确认收款、未挂账 | 关闭原订单，或按已有超时设置自动关单 | 下单已在事务内占库；未付款取消在事务内释放，原来仍上架的商品恢复可售。不会新增账目。 |
| 已挂账但未收到钱，客户退回 | 找原业务员核对串号并收回设备 → 在 ERP 原销售单办理退货 | 冲减原未收应收；不凭空生成客户退款。商城原单保留，设备待上架。 |
| 已线下收款，客户退回 | 原业务员接收设备 → ERP 原单退货 → 财务处理退款 | 已收部分进入客户退款应付；默认选择“转财务退款”，不默认当作现金已退。原收款记录保留。 |
| 只收了部分款，客户退回 | ERP 原单退货 | 未收部分冲减应收，已收部分形成退款待办。例如原价5000、已收1000，退回后待退款1000，不是再收5000。 |
| 线上支付后退回 | 原商城订单办理退款 → 全额退款成功且实物实际收回 → 点击设备下方“确认设备已收回” | 恢复一台商城库存，保持待上架。退款中、退款失败或仅部分补偿不能恢复这台库存。 |
| 已经实际收回，准备再次销售 | 业务员核对设备 → 商品管理中上架 | 不再收款、不新建应收。原订单和退款进度仍可追溯。 |
| 同单多台只退一台 | 按原单设备逐台退回 | 不关闭未退设备；全部非赠品设备退回后才关闭原商城订单。 |
| 原退货误操作，需要撤销 | 在 ERP 撤销原退货 | 恢复原商城订单状态并取消可售；若设备已被新订单占用则整笔拒绝，不覆盖新订单。 |

注意：

1. **拍下不是删除商品。** 单台设备下单后库存变为0并退出可售；用户不能趁通知队列尚未处理再次拍下。
2. 挂账也是已成立的销售责任，不能用普通“关闭订单”跳过应收冲减。
3. 财务未退款完成时，关闭原交易不代表退款已支付；需继续处理原退款待办。
4. 设备由原业务员协调接收，系统保留实际接收人的记录；本次没有把权限硬编码成“只有原业务员本人能退货”。
5. ERP 线上退款原有账面冲销与实物接收不同：现在额外检查原商城退款/收回记录，未实际收回会阻止 ERP 再售及商城重新发布。收回确认不再生成新的资金流水。
6. 本次“确认设备已收回”针对单台设备；多数量配件等标品继续使用原售后流程。

## 三、避免重复销售、重复记账的处理

- **同一事务占库：** 商城建单与库存扣减一起提交；库存不足时订单也回滚。ERP 直接销售关联设备时，同事务占用商城库存，不等异步通知。
- **重复通知保护：** 新订单保存占用状态；异步创建/关闭不重复扣减或返还库存。相同退回重复处理不再增库存。
- **原单定位：** 优先用原商城订单ID、原明细ID和ERP资产关联定位；无法唯一对应时停止并给出原因，不按名称猜。
- **旧通知不能释放新订单：** 校验当前ERP状态与其他商城订单占用；原退回重试不能把已被新订单拍下的库存再放出来。
- **迟到出库通知保护：** 出库通知会核对ERP当前原销售单；设备已经退回或再次销售时，旧出库通知不会覆盖当前商城库存。
- **原订单保留：** 不再通过删除订单商品行、把订单金额清零来表现退回。
- **已付款不能普通关单：** 后端拦截已收款、已挂账或非待付款订单的普通关闭请求。
- **迟到支付回调：** 已关闭订单不再被支付回调重新激活或交付；若渠道确实扣款，需要财务核对该流水并办理退款。本次不自动从这一异常回调另发退款，也不提示客户再次付款。
- **发布拦截：** 未确认实物收回时，不能通过ERP发布商城绕过商城收货步骤。
- **更新失败明确报错：** 原单冲突、重复SKU、ERP状态未同步、库存数量异常等情况不静默恢复库存。

7. 先用少量测试订单验证下方验收清单，再开放正常业务。不要通过修改已付订单金额、删除原应收或手动加库存来模拟退回。

## 八、上线后建议验收

1. 找一台真实测试设备，新建未付订单：两个列表都能看到IMEI，另一客户不能再次拍下。
2. 取消未付订单：可再次购买，库存只恢复一台。
3. 确认5000元挂账后退回：原应收减少5000，原单留痕，设备待上架。
4. 已收1000元的5000元订单退回：未收4000冲减，财务待退款1000，不生成第二笔销售。
5. 已付线上订单：按渠道完成退款，实物未收到时不可再售；收到后确认并手动上架。
6. 重新上架后检查ERP应收、应付和资金流水：不应因此增加销售收款记录。
7. 新客户重新购买同一台设备后，重试上一笔退回通知：新订单仍然占库。
8. 核对原业务员、实际接收人、原订单、退货单和退款余额，确认责任可追溯。
