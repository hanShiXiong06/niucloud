## 二、30 秒速记（最高频的规则）

1. **业务只写在 `addon/<插件名>/`**，绝不改 `core/`、主工程 `app/`、框架配置与各端构建/聚合文件（核心区改动需走例外评审）。
2. **每张业务表带 `site_id`，每条查询按 `site_id` 过滤**；`site_id`/操作人由服务端注入，不信任前端。
3. **提交格式**：`type(scope): 中文描述`，`scope` 必须是插件 key（如 `feat(hsx_recycle): 新增快递模块`）。
4. **代码单向向上流转**：`feature/* → dev → test → release → main`，不跳级、不在上游分支直接写业务。
5. **改库必升版**：`info.json` 升 `version` + 新增 `sql/update_<版本>.sql`，同一提交，保持升级链可平滑升级。
6. **禁提**：`vendor/`、`node_modules/`、`dist/`、密钥。

## 三、分支模型一图

```
feature/* fix/*  →  dev  →  test  →  release  →  main      hotfix/*(从 main 切, 修完回流 dev)
  本地开发        集成     测试      预发/灰度    正式生产
                                                official-base(官方基线, 只读保留)
```

详见《仓库与分支规范》。
