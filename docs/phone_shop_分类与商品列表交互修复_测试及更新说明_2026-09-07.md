# 分类与商品列表交互修复

日期：2026-09-07

## 本次结果

1. 后台“分类设置”新增“查看商品需登录”，默认关闭。开启后，分类商品卡片、商品列表点击详情/购买先登录，登录后进入原先选择的商品，不丢失商品 ID。
2. 三级分类布局 3-1 的价格后补充价格类型标识。VIP 只表示“已登录且接口实际返回会员价”，不把所有已登录客户或普通售价标为 VIP；新人价、折扣价沿用各自图标。
3. 二级分类布局 2-2 的购物车数量可直接输入，按键盘完成或失焦保存。加减与输入共用数量校验；0 移出购物车，非整数、库存不足、起购及限购给出明确提示。
4. 商品列表的单列、双列均读取分类配置，取消写死的转发按钮，并与 3-1 使用同一操作按钮组件。

| 分类设置 | 商品列表行为 |
| --- | --- |
| 不显示操作 | 不显示右侧按钮；点击卡片仍可进入详情并遵循登录配置 |
| 查看商品/购买 | 使用后台按钮文案，进入商品详情，再按原购买流程操作 |
| 下载转发 | 使用后台按钮文案，调用已有下载转发功能，保留原转发权益校验 |
| 加入购物车 | 打开已有规格/数量弹窗；顶部显示购物车入口；核销虚拟商品仍进入详情购买 |

配置获取失败时不擅自显示转发或绕过登录规则，页面提示重试。列表每次重新显示时重新获取配置。

“查看商品需登录”是上述入口的导航规则，不是新增的后端数据保密权限；未改动其它入口/API 的访问权限。转发、加购、结算仍执行各自的登录与权益要求。

## 数量准确性

- 输入草稿与购物车实际数量分离，服务端成功后才更新购物车数量和合计。
- 接口失败保留原数量，输入框恢复，解除操作锁，可以重试。
- 键盘完成和失焦连续触发只提交一次；更新中拒绝重复修改并提示。
- 保存成功但刷新购物车失败，保留已确认的新数量，并明确提示刷新核对，不伪装成保存失败。
- 通过其它入口更改购物车后，未编辑状态的输入框显示当前购物车数量，不显示上一次输入草稿。
- 不修改已有订单、商品价格或历史数据。
