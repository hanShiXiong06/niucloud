# 二手机系统 · ERP / 财务 需求整理

> 来源:老板 + 财务团队反馈(2026-06-22)
> 目的:在"核心业务快速上线"与"财务暂不进生产"之间解耦,把反馈拆成可执行需求。

---

## 一、贯穿全局的三条原则

1. **ERP/财务可一键开关**:关闭后,所有 ERP 与财务相关功能隐藏、不参与业务;开启则进入"测试可用"状态。
2. **核心链路必须独立可用、优先上线**:拍照 → 定价 → 进商城 → 上架,这条不依赖 ERP/财务也能完整跑通。
3. **钱以财务为准,账要"活"**:每一笔账都能关联到具体设备;平账这类"手动凑平"基本不用——账目严谨,对不上就是有问题账。

---

## 二、需求清单(按主题分组)

### A. 开关与模式

#### A1 · ERP 总开关(反馈 1)
- **诉求**:加一个配置开关,控制是否启用 ERP 记账。财务问题多,暂不进生产;关闭后,ERP 与财务相关功能全部隐藏、不使用。
- **范围**:站点级配置 `erp_enabled`。关闭时隐藏:ERP 菜单(出库管理、财务中心、往来、资产等)、代下单收银台里"走 ERP 出库/收款"的部分、商城订单的"ERP 托管"行为。开启时全部恢复。
- **要点/决策**:这是一个总闸,ERP 和财务一起开关(按反馈口径)。关闭时收银台如何处理 → 见待确认问题 Q1。
- **优先级**:**P0**(上线前必须,决定能不能先把核心业务推上去)。

#### A2 · 测试模式 + 测试数据清空(反馈 2)
- **诉求**:开启后即"测试可用";正式进生产前,可能要清空测试期产生的数据。
- **范围**:ERP 开启=测试态;另需一个"清空测试数据"的管理动作(高危,要二次确认 + 权限)。
- **要点/决策**:清哪些数据要划清楚 → 见 Q2。回收/拍照/商品这类核心数据通常**保留**,只清 ERP 出库/财务/资金流水/资产台账等测试账。
- **优先级**:**P1**。

#### A3 · 现结功能开关(反馈 4)
- **诉求**:加"现结"开关。开启:非财务人员可当场清账(收款);关闭:下单只生成应收/应付,销售只能加**备注**做参考,最终清账由财务完成。
- **范围**:配置 `allow_instant_settle`。直接作用于已做好的"收银台当场收款 / 出库处理挂单收款":关闭时隐藏收款入口,只挂应收应付,放开一个"备注"字段。
- **要点/决策**:关闭时商城展示单还建不建、备注存哪 → 见 Q3。
- **优先级**:**P0**(财务明确要求的权限边界)。

### B. 核心业务保障

#### B1 · 拍照 → 定价 → 上架 链路独立可用(反馈 3)
- **诉求**:中台正常拍照、定价、进入商城、上架——这条很重要,要快速上线,且不能被 ERP/财务问题拖住。
- **范围**:核查 intake(质检/拍照)→ 定价 → 商品上架 全链路在 `erp_enabled=关` 时无硬依赖、可独立完成。
- **要点/决策**:重点排查"上架/定价"是否在某处强依赖 ERP 资产或财务;若有,做降级(ERP 关时跳过)。
- **优先级**:**P0**。

### C. 财务功能完善

#### C1 · 经营性支出 + 额外收入 的录入与查询(反馈 5)
- **诉求**:经营性费用支出目前只能录、没有查询列表,无法按条件查。需要单独一个 tab,完成**经营性支出**与**额外收入**的录入 + 查询。
- **范围**:财务中心新增 tab「经营收支」:列表 + 筛选(时间/类型/账户/对手方/金额)+ 录入(支出已有 `recordExpense`,需补"额外收入"录入 + 两者的查询接口)。
- **优先级**:**P1**。

#### C2 · 账目做活 · 强制关联设备 · 弱化平账(反馈 6)
- **诉求**:所有账目都是"活的",平账功能基本用不到;账目严谨,对不上=有问题账。核心是**确保每笔账都能关联上设备**。
- **范围**:① 应收/应付/资金流水强化"设备关联"(展示 + 可追溯,缺关联的要能查出来);② 弱化/收起"平账(手动凑平)"入口。
- **要点/决策**:"折账(应付↔应收冲抵)"和"平账(手动凑平)"是两回事,前者是真实业务冲抵、后者才是财务说用不到的——要确认是否连折账一起收 → 见 Q4。
- **优先级**:**P2**(方向性优化,非上线阻塞)。

#### C3 · 整备账目往来化 + 录入对手方/新建主体(反馈 7)
- **诉求**:整备不只是"记一笔支出",要记**这笔账付给谁、向谁支付**,支持账目往来查询,支持录入时新建用户/新建主体。
- **范围**:整备产生的支出改造成"对某对手方的应付"(类比回收应付),进入往来账、可在往来汇总查询;录入时复用 counterparty-select 的"快速建档(对接人 + 主体一步建)"。
- **优先级**:**P2**。

## 三、建议优先级与排期

| 阶段 | 内容 | 目标 |
|---|---|---|
| **P0 · 先上线** | A1 ERP 总开关、A3 现结开关、B1 核心链路独立 | ERP 关闭即可把"拍照→定价→上架→商城"推进生产 |
| **P1 · 紧随** | C1 经营收支 tab、A2 测试数据清空 | 财务可在测试态完整试跑,且能为进生产清场 |
| **P2 · 打磨** | C2 账目做活/关联设备、C3 整备往来化 | 账目严谨化、往来闭环 |

## 四、已拍板的决策(2026-06-22)

- **Q1(A1)→ 决策**:ERP 总开关关闭后,**代下单收银台一并临时隐藏**(不走 B 退化方案)。
- **Q2(A2)→ 决策**:"清空测试数据"**只清账目相关**(财务:应收/应付/结算/资金流水;ERP 资产台账/出库账目口径),**业务流向数据保持不动**(回收单、拍照质检、商品全保留)。必要时由本人直接处理数据库,故此项做成**轻量脚本/可选**,不必复杂化。
- **Q3(A3)→ 决策**:现结**关闭**时,**商城展示单照建**(与现在一致)。销售下单填的**备注**存到展示单上,并**同步带到应收的备注**,方便财务清账时看到参考。
- **Q4(C2)→ 决策**:**折账(应付↔应收冲抵)保留**(真实业务);**不做"手动调余额/平账"入口**——余额永远由真实流水自动算出,账对不上=查问题账,不手动抹平。落地:排查并收掉任何"手动改余额/平账"入口(若存在)。
- **Q5(C3)→ 决策(模型升级)**:**所有钱都挂在设备上**。整备 = 给设备追加一个**子项成本账单**(设备账 = 回收价 + 整备费 + …),整备费同时记一笔"应付整备服务商/师傅"进往来。回收应付、销售应收、整备应付统一都关联设备——这正是反馈 6"账做活·关联设备"的落地形态,作为全局账务模型。
