# 商品页面强制登录入口修复

日期：2026-09-07

## 追加修复：登录页左上角返回与 loading

用户补充的路径：从原页面进入商品分类/列表，触发强制登录，在登录页点击左上角「<」不能正常返回。

原因是入口校验在受限页已经入栈后，又用 `navigateTo` 打开登录页。返回后再次进入受限页，再次触发登录；成功登录时也可能留下重复商品页或登录中间页。

本轮只改以下 **3 份生效源码**，必须一起更新：

| 文件（相对项目根目录） | 修改 |
| --- | --- |
| `uni-app/src/hooks/useLogin.ts` | 增加可选的替换当前页登录方式；默认调用仍保留原来的 `navigateTo`。登录成功后移除连续登录中间页。H5 等待真实路由返回结束，避免提前回调导致跳错页。 |
| `uni-app/src/addon/phone_shop/hooks/useGoodsPageAccess.ts` | 分类、列表、详情的入口校验改用 `redirectTo` 进入登录页；取消登录直接回到来源页，不重新创建来源页；原目标及参数仍保留。 |
| `uni-app/src/addon/phone_shop/components/PhoneGoodsAccessState.vue` | 校验和跳转期间只显示 loading，不展示“正在确认访问权限”“请先登录”等提示；请求真正失败时仍提供原因和重试。 |

后两份文件的插件发布副本也已同步到 `niucloud/addon/phone_shop/uni-app/` 的同名路径。**不能只更新插件副本而遗漏框架的 `uni-app/src/hooks/useLogin.ts`**，否则新的跳转方式不会生效。

没有改头部组件样式、通用路由函数、PHP 或 SQL。H5 和微信小程序均需重新编译发布。下文原来的六份移动端文件是上一轮首次修复的清单，不是本轮追加改动的清单。

## 已确定的原因

用户线上站点 `100005` 的分类配置已经返回 `detail_login_required: 1`，开关已生效，不是需要再次保存后台配置。

原实现只在商品卡片的“点击进入详情”动作中判断登录。`pages/goods/category.vue` 进入页面时仅获取配置并直接渲染分类组件，没有在页面入口判断，因此首页进入 `category?category_id=60` 不会触发登录。原分类页还只在首次加载时获取配置，返回缓存页面时不会重新读取。

另两处遗漏一并修复：直接打开商品列表链接、直接打开商品详情/分享链接，不再依赖上一个页面的点击判断。

## 当前规则

| 场景 | 行为 |
| --- | --- |
| 开关开启，游客进入分类、列表或详情 | 先检查配置，再跳登录；未通过前不展示页面商品内容 |
| 首页进入分类 `category_id=60` | 登录返回地址保留该分类编号，不回到默认分类 |
| 商品详情通过 `goods_id`、`sku_id`、活动或分享参数进入 | 保留原始入口参数，登录后返回原目标 |
| 已经有有效登录会话 | 正常访问，不强迫重复登录 |
| 本地保留了过期 token | 调用现有会员接口验证，401 后仍需登录 |
| 开关关闭 | 游客正常浏览，不额外请求会员校验 |
| 配置请求失败或会员校验断网 | 保持拦截，展示明确原因及重试入口，不默认为关闭 |
| 离开后再次显示页面 | 重新读取配置；旧的迟到请求不再触发错误跳转 |

商城首页仍可打开；后台装修/模板预览沿用原预览流程，不要求编辑人员登录销售端会员。加购、转发、结算仍保留各自的权限检查。

这是商品页面的入口规则，不是新增后端 API 数据访问权限。首页微页面、其他业务页面和现有公开接口的授权范围未改动。
