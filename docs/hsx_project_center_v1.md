# 项目合作中心（hsx_project_center）V1 产品与技术方案

## 1. 产品定位

项目合作中心不是“美团闪购报名表”，而是一套可复用的项目入驻、客户协作和资料审核平台。

美团闪购作为第一个项目模板落地；后续维修团购、租机团购、配件柜、品牌合作等项目只需要配置不同的介绍内容、问答、表单、审核规则和交付步骤，不需要重新开发一套插件。

V1 的核心分工：

- 企业微信群：一客一群、客户沟通、付款二维码、付款截图和沟通留痕。
- 小程序：项目介绍、常见问题、可选 AI 问答、参考示例、资料采集、修改和进度查询。
- 项目合作中心后台：项目配置、群编号、客户绑定、资料工单、字段级审核、任务分派和过程留痕。
- 万能表单：承载动态资料字段和文件上传，不重复开发表单引擎。
- hsx_wecom：承载企业微信凭据、员工绑定、建群能力、消息通知、失败重试和群绑定。
- hsx_ai：承载可选知识库问答；默认关闭，未安装时不影响主流程。
- 牛云通知系统：承载公众号、小程序、短信等可用渠道的状态通知。

## 2. 产品原则

1. 系统不确认付款事实。客户付款后把截图发到群里，财务只需在群内核对，不增加后台操作。
2. 小程序中的“我已付款”只是进入资料填写的业务确认，不代表财务已收款。
3. 资料工单必须绑定群编号、客户会员、手机号和万能表单记录，任何人都能按编号追溯。
4. 驳回必须精确到字段，告诉客户哪一项有问题、为什么、如何重拍或修改。
5. 客户修改时重新扫原二维码或打开原小程序页面即可，不生成新的链接和新的工单。
6. 企业微信自动建群是本项目的标准入口；`hsx_wecom` 未就绪时必须明确阻断并提示配置，人工绑定只作为故障兜底。AI、分销仍为可选能力。
7. 不依赖客户姓名作为唯一标识，手机号是客户主身份，群编号是本次项目协作主标识。

## 3. 核心业务流程

### 3.1 建群前

1. 工作人员在企业微信工作台打开“项目合作中心”。
2. 首次进入时通过企业微信静默 OAuth 识别当前成员 `UserID`，自动绑定当前系统员工账号；后续无需人工配置 UserID。
3. 选择项目、客户、内部协作人员。外部联系人选择器展示当前员工在企业微信中有权访问的客户范围。
4. 系统预占当日群编号，例如 `0819-1`，内部完整编号使用 `20260819-1`。
5. 调用企业微信原生建群界面，工作人员确认后创建客户群。
6. 建群成功后保存 `chat_id`、群编号、客户、负责人和项目关系。
7. 系统生成项目群资料包：项目小程序卡片、付款二维码、简短操作说明。
8. 工作人员确认发送资料包到群内。

> 企业微信不能在服务端静默把客户拉入群。V1 采用“系统选人 + 原生确认建群”，把人工动作压缩到一次确认，同时保持合规和稳定。

### 3.2 客户端

1. 客户从群里的小程序卡片进入项目页。
2. 首屏先讲清楚：项目是什么、费用、准备材料、预计周期、退出规则和风险提示。
3. 客户可切换查看常见问题；开启 AI 后可进一步提问。
4. 客户在群内长按识别付款二维码并付款，把付款截图发送到群里。
5. 客户回到小程序，点击“我已付款，填写资料”。
6. 小程序打开对应万能表单，展示正确示例和错误示例。
7. 提交后生成资料审核工单，并通知指定审核人。
8. 驳回后，小程序首页直接显示待修改字段；客户修改原记录并再次提交。
9. 审核通过后进入后续交付状态，并通知客户和负责人。

### 3.3 审核端

1. 审核人员只看到分配给自己或角色范围内的待办。
2. 列表优先展示群编号、门店、手机号、提交时间、缺失项数量和当前状态。
3. 详情页左侧展示资料，右侧展示参考模板；低分辨率下改为抽屉/分段展示。
4. 每个字段支持：通过、需重填、需重拍、资料不符，并填写问题说明。
5. 部分驳回时只要求客户修改问题字段，其他已通过字段锁定但允许查看。
6. 审核通过和驳回均写审核日志；重复点击必须幂等。
7. 需要人工沟通时，审核员复制群编号，在企业微信检索对应群直接沟通。

## 4. 状态机

### 4.1 群协作状态

`reserved -> created -> active -> completed`

异常分支：

- `reserved -> create_failed`：建群失败，允许用原编号重试。
- `active -> abandoned`：客户明确放弃。
- `active -> dissolved`：客户放弃且确认解散群。

### 4.2 资料工单状态

V1 已实现：`submitted -> reviewing -> approved`

后续交付扩展：`approved -> delivering -> completed`

驳回循环：

`reviewing -> rejected -> submitted -> reviewing`

终止分支：

`draft/submitted/rejected -> abandoned`

规则：

- 同一项目、同一群同时只能存在一个未结束工单。
- 每次重新提交增加 `submit_version`，不新增主工单。
- 审核结论以版本为单位保存，防止客户修改后覆盖历史证据。
- `approved` 之后如需退回，必须执行“撤回审核”动作并填写原因，不能直接改状态。

## 5. 插件边界

### 5.1 hsx_project_center 负责

- 项目配置与发布。
- 群编号生成和业务绑定。
- 项目资料包生成。
- 资料工单、审核规则、审核日志。
- 收益榜文本粘贴、解析和展示。
- 项目知识文档的业务来源。
- 邀请关系在项目业务中的归因。
- 业务事件发布，不直接操作其他插件数据。

### 5.2 hsx_wecom 扩展负责

- 企业微信 JS-SDK 签名。
- 内部员工和外部联系人选择/映射。
- `openEnterpriseChat` 建群调用参数。
- 建群成功后的 `chat_id` 保存回调。
- 客户群查询、群活码和群资料包跳转。
- 企业微信待办通知、发送日志和失败重试。

`hsx_project_center` 不直接保存 CorpSecret，也不直接调用企业微信底层接口。

### 5.3 框架万能表单负责

- 项目动态字段。
- 图片、身份证、营业执照、门店照片、定位等材料。
- 表单记录与字段记录。
- 客户重新编辑原记录。

项目插件只保存 `form_id` 和 `form_record_id`，不复制一套动态字段表。

### 5.4 hsx_ai 可选负责

- 项目知识库检索。
- 基于项目文档回答客户问题。
- 回答必须限定为当前项目知识，不允许编造收益承诺或审核结果。
- 不允许 AI 自动通过资料审核；多模态只能给审核员提供“疑似问题”建议。

### 5.5 通知系统负责

- 资料提交成功。
- 资料被驳回。
- 资料审核通过。
- 项目完成或终止。

发送策略：站内状态为事实源；公众号、小程序、短信按站点已配置渠道发送。通知失败不回滚业务状态，写日志并允许补发。

### 5.6 分销与奖励（默认关闭）

- 邀请注册关系复用框架会员 `pid`，不自建第二套上下级关系。
- 项目完成后发布事实事件，由 `hsx_marketing` 或奖励提供方决定发佣金、积分、成长值或其他奖励。
- 未安装奖励插件时只保留邀请归因，不产生佣金。
- 仅注册不发奖励，默认以“资料审核通过”或“项目完成”为有效转化节点，后台可配置。

## 6. 数据模型

### 6.1 `project_center_project` 项目表

主要字段：

- `id/site_id/project_no/title/subtitle/status/sort`
- `cover/intro_page_id/form_id`
- `payment_qrcode/payment_amount/payment_tips`
- `reviewer_uids/reviewer_role_ids`
- `ai_enabled/ai_scene/knowledge_scope`
- `distribution_enabled/conversion_status/reward_config_json`
- `notice_channels/config_json`
- `create_at/update_at`

说明：项目介绍建议使用项目专属 DIY 页面；常见问题和 AI 入口作为 DIY 组件，不把长篇富文本塞入项目表。

### 6.2 `project_center_group` 群协作表

主要字段：

- `id/site_id/group_no/group_no_full/project_id`
- `member_id/member_mobile/member_name/store_name`
- `wecom_chat_id/wecom_external_userid`
- `owner_uid/collaborator_uids`
- `status/create_mode/error_message`
- `created_at/completed_at/dissolved_at/create_at/update_at`

唯一索引：

- `site_id + group_no_full`
- `site_id + wecom_chat_id`（非空时）

### 6.3 `project_center_application` 资料工单表

主要字段：

- `id/site_id/application_no/project_id/group_id`
- `member_id/member_mobile`
- `form_id/form_record_id/submit_version`
- `status/assignee_uid/assignee_name`
- `payment_declared_at`（仅代表客户点击“我已付款”）
- `submitted_at/reviewed_at/completed_at/abandoned_at`
- `last_reject_summary/create_at/update_at`

唯一约束：同一群同一项目的有效工单由服务层锁控制，避免重复提交。

### 6.4 `project_center_review_log` 审核历史表

主要字段：

- `id/site_id/application_id/submit_version`
- `action/reviewer_uid/reviewer_name`
- `field_issues_json`
- `form_snapshot_json`
- `remark/create_at`

`field_issues_json` 示例：

```json
[
  {
    "field_key": "id_card_back",
    "field_name": "身份证反面",
    "reason_code": "blurred",
    "reason": "图片模糊，证件有效期无法识别",
    "example_image": "..."
  }
]
```

### 6.5 `project_center_income_board` 收益榜展示表

主要字段：

- `id/site_id/project_id/stat_date/title`
- `raw_text/rows_json/status/published_at`
- `operator_uid/create_at/update_at`

后台每天粘贴文本，系统解析 `Top/门店/收益`，先预览校验再发布。该表只负责展示外部数据，不参与本系统财务统计。

## 7. 编号规则

- 客户可见群号：`MMDD-序号`，例如 `0819-1`。
- 系统完整编号：`YYYYMMDD-序号`，例如 `20260819-1`。
- 群名称建议：`0819-1｜门店简称｜手机号后4位`。
- 当日序号通过数据库事务和唯一索引分配，不能使用“先查最大值再加一”的无锁写法。
- 建群失败不释放编号，重试继续使用原编号，避免群与后台错位。

## 8. 页面设计

### 8.1 PC 管理端

一级菜单建议放在“应用”中，不占用业务主导航：

- 项目工作台
- 项目管理
- 资料审核
- 群协作
- 收益展示
- 配置中心

工作台只展示老板和负责人关心的数字：今日新群、待审核、驳回待修改、审核通过、异常任务。点击数字进入对应列表。

### 8.2 企业微信工作台 H5

- 一键建群。
- 今日群列表。
- 按群编号、手机号、门店搜索。
- 复制/发送项目资料包。
- 跳转资料审核详情。

### 8.3 小程序项目页

同一页面完成，不让客户在多个页面来回跳：

1. 项目简介与核心权益。
2. 参与条件和费用。
3. 实际流程时间线。
4. 收益榜滚动展示。
5. 常见问题 / AI 问答切换。
6. 材料清单，点击查看正确和错误示例。
7. “我已付款，填写资料”主按钮。
8. 已提交客户直接显示当前进度和待修改项。

内容较多时使用折叠卡片、底部弹窗和图片预览，不在首屏堆满长文。

## 9. 事件契约

### 9.1 任务通知

资料提交后发布 `HsxBusinessTaskAssigned`：

- `source_plugin = hsx_project_center`
- `source_type = application`
- `stage_key = project_material_review`
- `source_id = application_id`
- `assignee_uid = 审核负责人`
- `target` 同时包含 PC、企业微信 H5 和小程序路径

由 `hsx_wecom` 消费，业务插件不关心企业微信发送实现。

### 9.2 项目转化事实

审核通过或项目完成后发布：

- `HsxProjectApplicationApproved`
- `HsxProjectApplicationCompleted`
- 同时按配置转换为 `HsxMarketingFactRecorded`

事件必须包含全局唯一 `event_id`，奖励插件按事件幂等消费。

### 9.3 AI 知识

项目插件监听 `HsxAiKnowledgeRetrieveRequested`，只返回当前站点、当前项目已发布的知识条目。AI 插件未安装或项目未开启 AI 时，前端隐藏 AI 入口。

## 10. 权限

- 项目管理员：项目配置、表单绑定、人员配置。
- 拉群人员：创建群、查看本人群、发送资料包。
- 资料审核员：查看分配工单、字段审核、驳回、通过。
- 运营负责人：跨人员查看进度、重新分派、异常处理。
- 收益编辑员：粘贴、预览、发布收益榜。
- 超级管理员：撤回审核、终止工单、补发通知、查看操作日志。

前端按钮显示与后端权限必须同时校验，不能只靠菜单隐藏。

数据可见性以后端当前登录 `uid` 为准：普通员工只看到本人负责或协作的客户群，以及分配给本人/本人参与群的资料工单；站点管理员查看全部。前端查询条件不能扩大后端数据范围。

## 11. 异常与补偿

- 建群失败：记录原因，允许原编号重试或切换人工绑定群。
- `chat_id` 回写失败：保留预占记录，提供“绑定现有群”兜底。
- 万能表单提交成功但工单创建失败：使用 `form_record_id` 幂等补建。
- 通知失败：不回滚提交或审核，进入通知重试队列。
- 重复审核：数据库行锁 + 状态校验，第二次返回“已处理”。
- 客户重复扫码：返回原工单和当前状态，不重复创建。
- 插件未安装：
  - 无 hsx_wecom：自动建群入口明确提示安装配置；已有群可由有权限人员使用手工绑定兜底。
  - 无 hsx_ai：隐藏 AI，保留 FAQ。
  - 无 hsx_marketing/tk_vip：隐藏分销奖励，保留业务主流程。

## 12. 开发阶段

### 阶段一：主流程与自动建群闭环

- 项目配置、项目页、万能表单绑定。
- 群编号预占、系统选人、企业微信原生确认建群、`chat_id` 自动回写。
- 手工绑定只保留为异常兜底。
- 资料工单、字段级驳回、重新提交、审核通过。
- 牛云通知、企微审核待办。
- 收益榜文本粘贴和展示。

### 阶段二：企业微信运营提效

- 项目资料包生成和一键发送。
- 群活码/既有群绑定能力。

### 阶段三：智能化与增长

- AI 项目问答、知识文档维护。
- 多模态材料质量预检，仅作提示。
- 分销开关、邀请二维码、转化事实和奖励联动。
- 审核效率、驳回原因、转化漏斗统计。

## 13. V1 验收标准

1. 工作人员能为客户生成唯一群编号并创建或绑定客户群。
2. 群内能一次性发送项目入口、付款码和操作说明。
3. 客户能在一个小程序页面看懂项目、查看示例并提交资料。
4. 同一客户重复进入不会产生重复工单。
5. 审核员能按字段驳回，客户只修改问题字段。
6. 资料提交、驳回、通过均有明确状态与通知留痕。
7. 可通过群编号、手机号、门店名查询完整链路。
8. 企业微信、AI 或奖励插件缺失时，主流程仍可人工完成。
9. 所有关键写操作具备幂等、日志和失败补偿。
10. 后台和移动端在 150% 缩放及窄屏下仍能正常操作。
