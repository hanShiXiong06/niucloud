# 管理端小程序自营商品筛选修复

## 根因

管理端小程序商品列表把自营筛选写成 `source=100024`，代理写成 `source=100005`，并且只给编号为 100024 的站点显示归属切换。

实际建表和新增商品逻辑允许本站自建商品的 `source` 为空字符串。精确查询 `source=100024` 会漏掉这些正常的自营商品；换一个主站或子站编号，也不应该修改前端常量。

后台管理接口已有 `proxy_type` 契约，电脑管理端正在使用。此次管理端小程序对齐这套契约，不改后端查询、不回填商品来源。

## 修复内容

- 自营：发送 `proxy_type=self`，由后端按当前站点和配置的主站判定。
- 代理：发送 `proxy_type=proxy`，不写死主站编号。
- 全部：不发送 `proxy_type` 或 `source` 筛选条件，仍由后端限制当前登录站点。
- 首次请求默认自营，不等接口返回后才设置条件。主站按既有后端逻辑忽略自营筛选。
- 是否显示归属切换由返回的 `is_master_site` 判断，不依赖固定站点编号。
- 原有 IMEI、商品名称、分类、价格、上下架、库龄、排序和翻页逻辑保留。

## 用户验收

1. 用反馈问题的站点账号进入管理端小程序商品列表，搜索一台明确属于自营的设备。
2. 打开筛选，切换自营、代理、全部，确认结果分别对应，全部为两类合并。
3. 切换归属后再搜索 IMEI、切换上下架状态或翻页，确认筛选不会丢失。
4. 如结果仍不一致，提供当前请求的参数和响应；重点确认请求是管理接口且自营参数为 `proxy_type=self`，没有同时携带旧的 `source=100024`。
