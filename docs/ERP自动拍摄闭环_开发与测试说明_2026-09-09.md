# ERP 自动拍摄闭环：开发与测试说明

日期：2026-09-09。范围：`phone-inspector` 工位、`hsx_device_asset` 拍照中台、`hsx_erp` 图片交接，以及管理移动端手机补拍。

## 1. 产品原则

自动拍摄的价值是减少人工操作、提高合格图片的产出效率。手机是工位故障、瑕疵细节补拍时的兜底，不再要求两套完整流程都走一遍。

日常主流程：**选中设备或扫描完整串号 → 放入拍摄台 → 开始自动拍摄 → 提示后翻面 → 选图/调整首图 → ERP 确认接收 → 拍下一台。**

- 首次才配置工位地址和连接码，以后记住设置，不再反复录入设备信息。
- 默认快速单帧；HDR 为显式选项，不默认增加多曝光处理时间。
- 相机预设、原图、手机补拍等次要内容折叠，主操作保持明确。
- 照片先完成真实上传及设备绑定，再请求 ERP 接收。没有业务回执就不能显示完成。
- ERP 来源设备的成本、价格、上架责任仍由 ERP 管理；拍照不能顺带改价或自动发布。
- 没有接入 ERP 的独立中台设备，保留原有拍照后定价流程。

## 2. 入口与操作

### 管理后台

1. ERP → 库存中心 → 对设备发起拍摄 → **进入自动拍摄**。
2. 或进入“拍照定价”页面，在顶部扫描/输入完整 IMEI、SN 或资产编号，回车进入拍摄。
3. 第一次展开“工位连接与拍摄设置”，填本机服务地址及连接码；连接码在拍照电脑的“ERP 连接”页面获取。
4. 放好当前设备，点击“开始自动拍摄”。连接和任务准备本身不会触发快门。
5. 正面拍完提示翻面，用户明确确认后才继续背面。
6. 默认保留全部图片；取消不需要的图片，可指定首图。点击“采用 N 张，提交 ERP”。
7. 看到 ERP 接收确认后点击“拍下一台”，返回列表并把焦点交还扫码输入框。

工位地址使用本机地址（默认 `http://127.0.0.1:5200`），本轮未开放局域网远程控制。浏览器若要求本地网络访问授权，需由操作者允许；浏览器限制或连接失败时，页面提供手机兜底提示。

### 手机兜底

- 正常切换：点击“停止自动拍摄，手机补拍”，先保存选中的自动照片，再停止本轮，展开手机入口。
- 工位失联：明确提醒先确认转台已停止、设备可安全取下；未回传的原图仍在工位本地。此时不假装已上传。
- 手机补拍复用当前有效拍摄任务，保留自动回传的图片；补齐后在手机或后台统一确认。
- 修正旧二维码指向销售端 `/wap` 的问题。新二维码由后端生成，进入 `/adminapp/{site_id}/...` 管理端，并携带设备 ID。
- 手机需正常登录、有对应拍摄权限；这不是公开免登录的上传入口。
- ERP 图片交接后，移动端“已完成”指向 ERP 设备详情，不再引导到中台重复定价；不把中台尚未更新的销售价显示成 ERP 的真实价格。

## 3. 关键提示和结果

| 场景 | 用户看到什么 | 系统怎么处理 |
| --- | --- | --- |
| 首次未连接 | 未连接工位、填写连接码或用手机拍摄 | 不触发拍摄 |
| 相机/转台断开 | 明确设备未就绪、检查工位 | 不静默切换到模拟图片 |
| 空托盘检测不通过 | 检查托盘；仅确认设备已放好后可跳过本次检测 | 不直接推进角度 |
| 单角度失败 | 当前角度失败，重试或手机补拍 | 保留已拍照片，不跳过失败角度 |
| 正面完成 | 请翻面 | 等待用户确认，不自行重置正面流程 |
| 拍摄中暂停 | 拍完当前张后暂停 | 这是软暂停，不冒充硬件急停 |
| 上传中 | 回传进度及等待业务系统确认 | 图片先上传，再绑定，再交接 |
| 部分回传失败 | 已保存部分保留，可重试 | 已取得成功回执的图片复用，不重复绑定 |
| ERP 接收失败 | 图片已保存，但 ERP 尚未接收 | 回滚交接状态；不要求重拍 |
| ERP 成功、本地回执失败 | 业务系统已确认，本机回执待恢复 | 不要求再次向 ERP 提交，浏览器保留完成信息 |
| 其他窗口已经确认 | 刷新查看；调整请开始新一轮 | 阻止旧窗口覆盖已确认的另一组选图 |
| 已售/已离库 | 回 ERP 核对设备状态 | 阻止照片回写 |
| 已交商城/已上架后换图 | 先在 ERP 处理撤回/下架 | 不绕过商城交接边界 |
| 开发模拟 | 明确“开发模拟” | 不创建正式 ERP 拍摄任务，不允许提交模拟图片 |

图片回传复用依赖工位照片标识、任务 ID 和已有扩展信息。若文件存储请求本身已成功但网络响应完全丢失，重试可能留下未绑定的存储副本；本次保证业务媒体不重复绑定，不声称云存储上传天然具备端到端幂等。

## 4. 责任和数据保存

### 工位

- 本地任务绑定系统来源、站点、设备、拍摄任务；当前工位有未结束设备时不能直接抢占。
- 一步一请求，当前角度执行完成才推进；允许恢复同一任务及其前后面进度。
- 本轮角度和处理参数保存在已有 `extra_json`，恢复任务不随新预设改变。
- 每次拍摄使用独立目录，源图与处理图分开保存；重拍不覆盖原图。
- 单帧源图：`photos/{inspection_id}/{face}_{angle}_{唯一值}/original.jpg`；处理图另存 `processed.jpg`。
- HDR 的 `original.jpg` 是后处理前的合成源图，各曝光原始帧另保存在同次目录的 `exposures/`；界面明确区分。
- 顶部相机图片改为持久保存，不再依赖临时文件。
- 默认关闭支架修补和定向红色增强，保留正常预设/白平衡能力；不以美化掩盖设备瑕疵。
- 原图仍占用拍摄电脑本地空间，本次没有自动清理原图，也没有把原图全量上传云端。

### 拍照中台

- 自动拍摄与手机补拍复用一个有效任务。
- 图片携带稳定标识，在已有扩展信息中保存业务绑定回执。
- 选中的图片 ID、顺序与 ERP 交接回执保存在现有扩展字段中。
- ERP 来源在成功回执后进入 `erp_handoff`（已交 ERP），归入中台已完成。
- 未关联 ERP 的设备仍进入中台待定价。

### ERP

- 使用同步事件契约 `device_asset.photos.completed.v1` 接收选图。
- 校验当前站点、ERP 设备及设备编号；确认图片不属于已离库设备。
- 只更新销售图片、对应资料状态和业务日志，沿用现有仓库规则判断下一步。
- 图片齐全但价格缺失时继续待定价，不自动上架。
- 采购成本、整备费用、应付、销售价格均不在这次图片交接中修改。

## 5. 效率验收口径

目前界面记录“拍摄与处理耗时”和“本次上传与交接耗时”。这两个数字不包含全部人工放置、翻面、选图等待，也未覆盖所有辅助检查时间，**不能直接当作完整单台处理时长**。

相机到场后，建议用同一批至少 10 台设备，在相同照片要求和可接受画质下对比自动拍摄与手机拍摄，记录：

- 从选中设备到 ERP 确认收到合格图片的总时间。
- 人工实际操作时间。
- 合格图片数量、补拍比例、误绑定次数。
- 一轮连续处理的中位耗时及较慢设备耗时。

只有合格率不下降、整体处理更快或显著减少人工占用，自动拍摄才算达到目标。不要以模拟数据耗时或单次快门速度验收。
