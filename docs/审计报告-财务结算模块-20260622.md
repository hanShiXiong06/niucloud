## A. 架构师视角 · 财务结算的验收标准(站会计角度)

会计打开任意一台设备 / 一笔账,应该**在一个地方**就看全这几件事,不用跳菜单拼:

1. 这台从哪买的、花了多少(回收应付),挂在这台设备上;
2. 中途加了哪些成本(整备/补差价),每笔可追溯;
3. 卖给谁、应收多少;
4. **收款收了几笔、每笔进哪个账户**(分笔要看得见)、有没有折账;
5. 已收多少、未收多少;
6. 这三处永远对得上:**应收应付明细 ⟺ 往来汇总 ⟺ 资金流水**;
7. 已作废(退货/取消)的账,绝不进汇总/看板/余额。

## B. 测试员视角 · 逐条审计结果

### 发现 #1 ★ 全链路看不到"销售收款"流水 —— 已修
- **现象**:客户分两笔给钱,设备全链路只显示一条结算(还可能"现金¥0"),看不到分两笔、各进哪个账户;要查得回出库菜单。
- **根因**:`DeviceTraceService::collectFinanceEvents` 拉资金流水时,过滤条件只取 `source_type IN ('recycle_order','recycle_device')`(回收付款侧),**把销售收款侧的流水挡在外面**(销售收款以 `source_no=出库单号` 记账)。证据:`DeviceTraceService.php:336`(改前)。
- **修法**:按本台设备的应付/应收来源单号,反查并逐笔带出资金流水(去重),收款/付款每笔一行显示账户+金额+单号。证据:`DeviceTraceService.php` collectFinanceEvents 末尾(已改)。
- **状态**:✅ 已修,两挂载点同源。前端重拉全链路即可看到分笔。

### 验证 #2 ✓ 结算"全额标结"逻辑正确(没瞎改)
- **疑点**:`settle()` 调 `markSettled` 直接把 `settled_amount=amount`、status=settled(`FinanceSettlementService.php:892` 附近),怀疑会不会把"只收了一部分"的账误标全结。
- **结论**:**不是 bug**。`plan()` 里 offset+现金 始终覆盖所选项的全部未结额(`plan()` 计算 offset=min(应付,应收)、netCash=差额),所以被选中的每笔确实全额结清,标全结是对的。部分核销另有 `applyPartial`(供预付折抵用),逻辑独立且正确。
- **状态**:✓ 确认正确,不动。

### 验证 #3 ✓ 汇总/看板/余额已排除作废(没瞎改)
- **疑点**:之前在"全链路/出库详情"修过"作废应收被算进未收"的 bug,担心汇总/看板/往来余额也有同样问题。
- **结论**:**没有**。`getSummary`/`getBoard`/`getCounterpartyBalance` 取数都用 `status IN (pending,partial)` 过滤(`FinanceCounterpartyBalanceService.php:97/132/261/548`),天然排除了作废和已结清。
- **状态**:✓ 确认正确,不动。(之前的 void bug 只在"按单号/设备求和"的两处,已修。)

### 发现 #4 ◆ 多账户结算:结算记录行看不到"分了哪几笔" —— 已记录,未改
- **现象**:多账户收款时,结算记录里是一行(方式=现金、户头空、金额=合计),看不到"分两笔、各进哪个账户";分笔明细只在资金流水里。和你说的痛点同类。
- **根因**:多账户走 `settle(record_cash=false, 无 capital_account_id)`,所以结算单 `account_name=''`、`capital_account_id=0`;真正的分笔是 `emitAndSettleNow` 在 settle 之后逐笔记进资金流水(`source_no=出库单号`),结算单本身不带这些账户。
- **建议修法**(留你定夺,我没动,因属共享收款链路、你在睡):结算单详情(`getDetail`)里,通过"结算→核销的应收→其来源单号→资金流水"把那几笔分笔带出来展示;或让 `emitAndSettleNow` 给分笔流水补盖 `settlement_no`,让结算单能直接挂上分笔。
- **状态**:◆ 仅记录。属"看不全"同类,优先级中,建议下一轮修。

### 回归点 #5 ⚠ 现结收银台的多次"已售"事件,需在测试环境回归
- **背景**:我近期为"任何入口收款都闭环"做了改动——`settle` 收齐后会发"已售"事件通知商城下架+标完成;`fillPrice`、`createOutbound` 也各有发。现结收银台一单可能触发 2 次"已售"事件。
- **分析**:两次都应是幂等的(下架重复无害、finalize 只对"待支付"单生效、对已完成单是空操作)。但这是我自己改的,**测试员不该自证清白**。
- **状态**:⚠ 需在测试环境用"现结收银台开一单"实测一遍,确认商城订单状态、商品下架都只发生一次、结果正确。已列入测试脚本。

## D. 验收测试脚本(你/财务照着跑)

拿一台真机,在**测试环境**走一遍,每步打勾:

1. 入库 → 设备台账有 + 一笔回收应付(挂这台、金额对)
2. 定价 → 有售价
3. (可选)整备 → 设备子账多一条整备成本 + 一笔应付整备方
4. 上架 → 商城可见可卖
5. 卖出 → 一笔销售应收 + 商城展示单(待支付)
6. **分两笔收款**(微信一笔、支付宝一笔)→
   - 资金账户:两个账户各进一笔 ✓
   - **全链路:能看到这两笔(各账户各金额)** ✓ ← 本次修复点
   - 应收结清、商城展示单变"已完成"、商品下架 ✓ ← #5 回归点
7. 折账场景:有应付又有应收时结算 → 全链路有独立"结算/折账"行
8. 退货场景:退一台 → 那笔应收作废,**未收不含它**(汇总/看板/全链路都不算)✓
9. 三处对账:应收应付明细 ⟺ 往来汇总 ⟺ 资金流水,金额对得上 ✓

任一步对不上 = 抓到一笔问题账(去查,不手动抹平)。
