# ERP 整备流程与角色规则

## 产品结论

- “整备”是在库设备的业务状态，不是仓库。设备处于待整备、整备中、整备异常时仍属于库存，但不可销售、不可上架。
- 整备仓不作为系统概念。设备完成整备后默认保留原仓库和库位；未修好时，完工登记人可将设备转入异常仓、同行仓或其他实际位置。
- 定价阶段只需要标记“需要整备”。实际修了哪些项目、分别由哪家服务商完成、花了多少钱，以整备完成时的最终清单为准。
- 整备费用不允许通过普通“成本调整”直接录入。只有登记整备完工时才增加设备成本，并按设备、按项目、按服务商生成应付。

## 状态与操作

1. `无需整备`：设备可继续执行所在仓库的拍照、定价和销售规则。
2. `待整备`：由定价、质检或有权限的员工标记；设备进入整备队列并暂停销售。
3. `整备中`：员工点击“开始整备”。简易模式只记录开始事实；外送模式还记录交给哪家整备商及交接批次。
4. `整备完成`：扫码或进入设备登记最终项目、实际费用和去向。系统更新设备成本、生成整备应付并恢复仓库后续规则。
5. `整备异常`：部分修复或修复失败。设备保持不可售，必须明确原因并选择异常仓或其他处理位置后再继续。

## 两种跟踪模板

- 简易登记：适合小团队。开始整备时不要求选择服务商，完成时一次填写最终项目、服务商和费用。
- 外送追踪：适合整备量较大的团队。可将一筐设备批量交给同一家整备商，系统记录当前外部保管方；完成时仍以逐台最终清单结算。

系统提供默认模板，企业可在“基础配置 → 业务规则”中修改。模板只减少操作，不削弱设备级成本和账务审计。

## 角色职责

- 质检员 / 定价员：判断设备是否需要整备，不负责确认最终费用。
- 普通业务员工：按权限查看整备队列、批量开始整备、扫码登记返回设备。
- 库位负责人 / 仓库负责人：处理整备完成后的仓库、库位及异常去向。
- 财务：在应付款中核对设备、整备项目、服务商和凭证，完成实际付款；不在整备页面直接改账。
- 店长 / 主管：在工作台查看积压提醒和整备量，决定是否调整人员或服务商。

小团队可以由同一个账号承担多个职责；中大型团队再通过权限与数据范围拆分，业务状态本身不因团队规模改变。

## 提醒规则

- 默认当日新增待整备达到 25 台时，在 PC 和移动工作台提醒。
- 提醒只用于提示，不阻断业务。
- 用户可以选择“今天不再提醒”或“永久关闭”；永久关闭后可在业务规则中重新开启并调整阈值。

## 异常与审计

- 设备整备完成前不能销售或推送拍照、商城。
- 完工是敏感操作，需要二次确认；已形成成本和应付后不能普通删除，后续冲销应走红字或财务调整流程。
- 无费用整备也必须保留完工流水；多服务商项目分别生成应付，避免将整备费混入原采购供应商应付。
- 外部拍照或商城同步失败不回滚本地整备完工事实，保留失败状态供重试。
