# ERP 与商城库存无损关联：更新与测试说明

日期：2026-09-14  
状态：本地实现及回归完成，未部署到生产，未处理生产历史订单。

## 一、这次解决什么

现有业务中，同一台手机可能由回收入库到 ERP，随后又被导出、手动导入商城，商城 SKU 与 ERP 设备没有建立关联。

原来的商城原生商品销售渠道主要记录销售、成本快照和收付款事实，没有把商城设备串号完整传入 ERP，也不会自动复用同串号的 ERP 原库存。因此会出现：

- 商城有 IMEI，ERP 成交明细却缺少串号。
- 商城已成交，ERP 原设备仍然显示在库。
- 财务再次补录设备，增加工作量，也有重复建账风险。
- 商城原生成交应收列表漏算台数，显示“0 台”。
- 补关联后若再按当前 SKU 重新判断订单来源，重复支付通知可能走错销售渠道。

本次不是删除 ERP 重来，也不是强行覆盖商城商品，而是“核对身份 → 复用原资产或确认期初 → 保留原账 → 补齐销售出库”。

## 二、管理员入口和操作

### 1. 还没卖出的商城库存

后台：**ERP → 期初建账 → 商城库存对账 → 有库存待关联**。

1. 按完整串号或商品名称查询；查询本身不写数据。
2. 查看每台设备的商城成本、ERP 成本和处理原因。
3. 选择需要处理的记录，点击确认。
4. 仅“需确认期初”的设备要求选择实际仓库、库位、期初日期，并确认页面显示的成本。
5. 查看逐台结果；失败项保留明确原因，可重新预览。

建议先核对少量样本，确认原设备、仓库和成本正确后再分批处理。页面每页 20 条，接口每次最多确认 50 条；不是一个按钮后台盲扫全站。

| 预览结果 | 确认后的实际效果 |
| --- | --- |
| 可关联原库存 | 复用同站点唯一匹配的 ERP 设备，保留原成本、采购应付和付款，不重复入库。 |
| 需确认期初 | ERP 没有该设备，按已确认的商城成本建立自有期初库存并关联 SKU，不生成采购应付。 |
| 已关联 | 不重复建账；可勾选“包含已关联”查看。 |
| 需人工核对 | 显示缺串号、重复记录、成本缺失、物权不符、已售、整备未完成等具体原因，不自动覆盖。 |

### 2. 已经产生应收的商城订单

后台：**ERP → 应收管理 → 该笔应收详情 → 核对商城设备**。

确认会在原销售明细上补齐设备、成本与销售出库，不重建这笔应收，不改变应收金额、已结算金额及原结算记录。

例如反馈的订单 `20260913736612861652992`，上线后从该应收详情核对：

- 若商城串号唯一对应 ERP 原库存：选择关联，保留原采购/付款，补齐原设备销售出库。
- 若 ERP 完全没有该设备，且真实成本已确认：确认期初，再补齐该次出库。
- 若出现多个同串号资产、串号不完整、已有退款等情况：先核对原因，系统不猜、不删记录。

**原应收 7680 元不会因这次设备关联再生成一笔。本文不表示该线上订单已经修复；生产订单尚未操作。**

旧订单没有串号快照时，会明确标注“当前商城商品（旧订单无串号快照，请核对）”，需要管理员确认，不能宣称当前商品资料就是当时的不可变成交事实。

### 3. 线上已收款，没有待收应收单

后台：**ERP → 期初建账 → 商城库存对账 → 已成交待核对**。

此入口包含未关联资产的商城原生成交，既可处理挂账，也可找到已线上付款的订单。可按商城订单号查找，不需要为了补库存另建应收。

### 4. 今后新成交

- 下单时保存设备串号、ERP 关联和自营/代理来源快照。
- 已经预先关联的设备，沿用标准 ERP 销售流程。
- 原生商城设备尚未关联，但存在唯一有效 ERP 原库存时，成交同步会自动复用该设备并出库。
- 未匹配、重复、状态冲突等情况，保存真实销售/财务事实和可见的“库存待核对”原因，管理员到上述入口处理。
- 不会在付款回调中自动编造期初成本或采购应付。
- 重复支付通知继续依据原订单快照和已有幂等记录处理；不会因为 SKU 后来被关联就再建另一笔销售。
- 挂账使用原确认时间，线上付款使用原支付时间，避免将日期字符串转换成错误年份或在重试时改变成交日期。

## 三、重要边界

### 本次保留哪些数据

- 不清空 ERP，不删除重复串号资产，不批量删除商城数据。
- 关联原库存时保留原采购成本、整备成本、采购应付和付款；销售利润按原 ERP 已确认总成本计算。
- 不修改商城售价、图片、分类。
- 库存关联与商城绑定在同一台设备的事务内完成；绑定失败，该台新增资产和流水一并回滚。
- 逐台提交，某台失败不会把同批已成功设备误报成全部失败。
- 预览后商品、成本或 ERP 状态发生变化时，要求重新预览。
- 出入库与资金通知复用现有收件箱/发件箱；外层事务未提交时不提前派发。

### 不会自动替用户决定的事情

- 不按商品标题、串号尾号或跨站公共商品编号猜测设备。
- 只处理本站自营的一台一串号设备，不将代理货当成本公司库存。
- 多数量标品、历史同串号多次回购、重复 ERP 资产、已退货/已撤回销售，必须先核对。
- ERP 已有设备但成本未确认，不把成本缺失当成零成本利润。
- 找不到 ERP 设备时，期初成本必须真实且大于零；不能拿销售价充当成本。
- 存量库存使用商城当前成本；已有订单使用订单成本快照。**旧订单成本快照为零时，修改当前商品成本不会自动改写旧成交成本。**需要核实真实成本，使用已有人工补录/期初流程，再核对设备关联。若原 ERP 设备存在且成本有效，则直接复用原成本，无需重填。
- 期初只是登记已拥有的设备，不证明供应商款已付，也不自动清偿原应付。
- 本次不是双向自动覆盖所有商品资料，也没有后台自动清理历史异常。

### 数据库场景

1. 唯一匹配回收原资产，保留原采购应付和已付金额；原整备成本不丢失。
2. 预览不产生写入。
3. 未匹配设备显式确认期初，校验仓库/库位/日期，不生成采购应付。
4. 重复确认不重复建立库存或流水。
5. 预览后成本变化，旧确认令牌失效。
6. 重复串号、代理货、非法输入不可盲目关联。
7. 旧商城应收已有部分收款，补设备后原应收逐字段不变。
8. 旧 SKU 已关联、但成交明细未出库，仍可继续补齐出库，不能误显示“已全部完成”。
9. 应收串号检索、台数及资料完整状态正确。
10. 新原生成交自动关联原 ERP 库存；支付重放不产生第二笔销售/应收。
11. 缺库存时保留真实销售和 IMEI，显示待核对；确认后期初入库与销售出库成对。
12. 线上成交 7680 元，手续费 46.08 元、净到账 7633.92 元；重试不重复收款或手续费。
13. 全额线上退款恢复同一 ERP 资产与成本；退款重试不重复冲销资金。
14. 预先关联的 SKU 正常走原 ERP 销售渠道，挂账确认时间不被伪造成支付时间。
15. 线上已收款、没有应收单的成交可从“已成交待核对”处理，不追加一笔待收。
16. 商城拒绝绑定时，该台 ERP 新资产和入库台账全部回滚。
17. 下单后当前商品串号与原快照冲突，不错误出库；问题明确可查。
18. 外层事务内出站消息保持待处理，不提前对外派发。

## 七、上线后验收重点

先选“商城有完整 IMEI、ERP 已有唯一同串号库存”的一台设备：

1. 关联前记录商城售价、ERP 成本和原采购应付/付款。
2. 预览应显示“可关联原库存”，不能显示需要重建采购。
3. 确认后 ERP 资产数量不增加，商城 SKU 建立关联。
4. 销售后，ERP 同一资产出库，成本包含原整备费用；只有一套正确的销售/资金记录。
5. 再处理反馈中的历史应收，检查原应收金额及已结算金额不变，串号和设备台数补齐。
6. 检查发件箱/队列状态，确认商品售出/退回状态同步成功；失败应处理重试，不另建采购或重复补收款。

如任何一步存在歧义，先停止确认该台，保留原记录核对。无损过渡的原则是“保留已发生的账，只补缺失的设备链路”，不是让系统猜测成本或删除冲突数据。
