# 二手机 ERP 产品需求完成度清单

更新日期：2026-07-12  
版本：0.0.1（开发期，不升级版本号）

## 一、已形成可执行闭环

### 1. 采购、库存、销售与设备级账务

- 采购、付款、折账、采购退货均以设备为最小核算颗粒度。
- 采购退货先判断设备是否已结算：未结算直接冲销应付；已结算生成退款应收。
- 已销售、已退货、整备中等不可采购退货场景由后端统一拦截，前端展示不可操作原因。
- 销售出库生成设备级应收；销售退货生成设备级退款应付。
- 售后补差作为独立应付事实处理，补差会减少设备实际销售净额和毛利。
- 账目事实、实际资金流水、结算/折账记录分层展示，避免同一笔业务被用户误认为发生两次现金收支。
- 每笔真实收付款支持凭证图片，列表与详情可查看。

### 2. 经营收支

- 支持房租、水电、宽带、办公用品等无设备经营收支。
- 支出/收入类型动态化，并与业务来源分离。
- 待结算生成应收/应付，立即结算必须选择资金账户。
- 无设备账单不再展示“已选设备”等无意义区域。

### 3. 整备流程

- 整备不是仓库，是设备处于在库期间的业务状态。
- 状态链路：待整备 → 整备中 → 已完成 / 整备失败。
- 简易模式只记录开始和完成；外修跟踪模式可记录机器在哪个整备商手中。
- 整备完成支持多整备商、多项目、多费用，系统汇总成本并分别生成应付。
- 修好后默认回到预定仓库/库位；修不好可转异常仓或其他仓。
- 整备中设备禁止销售、采购退货和重复发起整备。
- 首页支持待整备/整备中提醒、阈值提醒，并可关闭当天或永久关闭。

### 4. PC 与移动管理端共同能力

- 采购、销售、采购退货、销售退货、应收应付、库存、串号追踪等核心口径共用后端服务。
- 返回列表/工作台时通过页面刷新 Hook 重新拉取数据。
- 敏感动作统一二次确认；请求操作提供 loading，防止重复提交。
- 长编号支持省略、查看全文和复制；弹窗/抽屉支持内容滚动。
- 串号追踪按同一 IMEI 的多次入库记录倒序展示，并可查看采购、销售、售后、退货链路。

## 二、本轮补齐：ERP 与商城分类

### 1. 数据原则

- ERP 分类和商城分类各自使用独立自增主键，不拼接站点 ID，也不共享主键。
- 新增 `erp_category_mapping` 映射表，以 `site_id + provider + 双端分类 ID` 建立稳定绑定。
- 多站点天然隔离；插件卸载重装后可以按分类路径重新校准映射。

### 2. 两种首次使用方式

- 已使用商城的老客户：选择“已有商城分类，导入并绑定”。商城分类导入 ERP，ERP 生成自己的分类 ID。
- 新客户：选择“ERP 为主，同步到商城”。在 ERP 建分类，商城生成自己的分类 ID 并写入映射。
- 初始化后：使用“双向校准”；系统补齐、更新和绑定，不自动删除任一端分类。

### 3. 插件联动

- 分类提供器、拉取、推送均通过牛云事件 Hook 装配。
- 未安装商城插件时，ERP 只展示本地分类，不引用商城类。
- 安装商城后，ERP 使用本地稳定分类 ID；规格和成色仍可使用商城提供的资料。
- ERP 新增或编辑分类后按配置实时推送商城；商城侧若提供分类变更事件则实时回写，当前商城版本也可通过“双向校准”拉取其新增和修改。
- PC 采购开单改为级联分类选择；移动端复用三级分类弹层。

## 三、已具备基础但仍需继续产品化

### 1. 回收插件联动（部分完成）

- 已有：回收确认出售后通过统一入库事件进入 ERP，生成采购、资产和设备级应付；ERP 结算可回调来源插件。
- 已有：回收来源、渠道等字典通过 Hook 动态装配。
- 待继续：把收款码、账户信息和更完整的设备付款回显统一到来源插件；补齐异常重试的运营可视化。

### 2. 商城联动（部分完成）

- 已有：商城真实付款订单可把关联资产送入 ERP 销售核心；ERP 出库/退回可通过领域事件更新商城设备状态。
- 已有：销售渠道根据商城插件安装情况动态出现。
- 当前产品决策：线上收款入口关闭，只走 ERP 线下收款；商城订单只读展示购买与退货状态。
- 待继续：商城历史订单设备化改造、只读订单详情和退货状态完整回显。

### 3. 拍照定价与上架（部分完成）

- 已有：设备入库后可进入拍照、补分类规格、定销售价和上架状态。
- 待继续：把质检报告、图片、销售价和商城商品的一物一码同步做成完整运营队列。

### 4. 往来主体（部分完成）

- 已有：主体选择组件、分页加载、主体多角色标签、新增主体入口。
- 待继续：主体分组管理、整备商快捷分组、会员账号与无账号主体的统一编辑页。

## 四、尚未进入本轮代码交付

### 1. 团队模式与角色模板

计划提供首次启用模板，而不是强制每家公司使用相同岗位：

- 极简模式：老板/管理员兼任采购、仓库、销售和财务。
- 标准门店：业务、库位负责人、财务、主管。
- 分工模式：质检/定价、库位负责人、拍照运营、接待制单、财务、店长。
- 支持模板创建后再自定义权限；同一个员工可以承担多个角色。

当前角色职责已经在产品规则中明确，但“首次选择模板并自动生成权限”尚未开发。

### 2. 员工 KPI 与提成（基础 KPI 已完成）

- 已支持按员工统计销售额、销售毛利、采购台次、质检台次和财务结算额，并可配置目标值、权重和启停；PC 与移动工作台均可查看。
- 库位负责人、接待/制单、拍照、质检等过程责任人已有部分数据基础。
- 利润阶梯、亏损处理、库龄调价、接待费和多人协作“提成”尚未形成可配置引擎。
- 在规则定稿前不把固定提成逻辑写死到交易主链路。

### 3. 仓库/库位负责人和数据权限

- 仓库、库位、设备流转已具备。
- 仓库负责人看全仓、库位负责人看指定库位，以及休假代管规则尚未完成权限化。

## 五、验收口径

- 分类同步不得共享或覆盖双端主键。
- 同步失败必须保留错误，允许再次校准；不得静默丢分类。
- 分类删除不做自动跨插件级联删除，避免误删已上架商城商品。
- 所有交易、退货、整备和财务状态以后端为唯一口径，PC 与移动端只负责展示和操作。
- 设备是否已销售不影响原采购应付是否结清；整备费用不得混入采购本金。
- 历史业务记录保存来源、渠道和分类快照，插件卸载后仍可读。
