# 出货渠道架构：ERP × 商城（phone_shop）联动设计

> 核心原则：**ERP 是主体,可独立运行直接出货(同行渠道)。商城只是 ERP 的一个出货渠道。**
> 装了商城 → 多出"商城渠道"；没装 → 没有这个选项。两者通过**事件**联动,职责分离。

---

## 一、现状架构（已读代码确认）

1. **插件探测靠 `class_exists`**：ERP 用 `class_exists('\addon\hsx_device_asset\...')` / `\addon\hsx_recycle\...` 判断中台/回收是否安装,独立可运行。判断商城同理(`\addon\phone_shop\...`)。
2. **ERP ↔ 商城 纯事件驱动**：
   - 卖出：ERP 出库成交 → `erp.asset.sold.v1` → 商城 `ErpAssetSoldListener::onSold` → `CoreOfflineSaleService::createSaleOrder`(建商城订单,sold/locked)。
   - 退回：ERP 退回 → `erp.asset.returned.v1` → `onReturned` → `returnSaleItemByAsset`。
3. **`sale_destination`(mall商城仓 / peer同行仓 / consignment代卖)** 已是核心维度。商城销路设备委托中台拍照定价(`delegated_to_mid`),再上架商城。
4. **部分退货商城侧已实现**：`returnSaleItemByAsset` = 删订单项 + 重算订单金额 + 商品翻回在售(`sale_status=available,status=1,stock=1`) + 退空则关单。**只差 ERP 侧没有"逐台退回"入口与事件发射。**
5. **商城暂无独立"线下开单/卖货"入口**：`createSaleOrder` 注释为"ERP出库回流/商城开单共用",但目前只有 ERP 回流在调用。

## 二、职责划分（关键架构决策）

| 设备所在 | 出货渠道 | 操作入口 | 责任人 |
|---|---|---|---|
| **在商城**(有 GoodsSku、sale_destination=mall) | 商城出货 | **商城·线下开单/卖货**(待建) | 商城店员 |
| **不在商城** | 同行出货 | **ERP·就地出库**(已有) | ERP 操作员 |

- **ERP 直接出库 = 同行渠道**。(已撤掉之前误加的"商城/同行"radio——ERP 直出本就是同行。)
- **商城出货发生在商城侧**,通过事件回流 ERP 打"商城渠道"标。
- **"商城渠道"这个维度/筛选,只在 phone_shop 安装时出现**(class_exists 条件化);没装则 ERP 只有同行。

## 三、商城·线下开单/卖货（✅ 已实现,非走新页而是挂在商品列表）

**最终实现比原计划更轻**:不另起页面,而是把"卖货"动作挂在**商城商品列表**上,完全符合"店员在商城找到这台商品就直接卖/挂单"。

- 入口:`admin/src/addon/phone_shop/views/goods/list.vue`
  - 每行 **「开单卖出」**(`canSell`= 在售 + 关联ERP设备才显示)。
  - 顶部 **「批量开单卖出」**(勾选多台可开单的机)。
- 弹窗:`views/goods/components/sell-dialog.vue`——多台清单 + 逐台/统一改价 + 客户选择(`counterparty-select`,无主体自动建) + 现结/挂账卡片 + 多账户收款。
- 提交:`api/erp_outbound.ts` → `erp/outbound/create`,**`sale_channel:'mall'`**。
- 后端:ERP `createOutbound` 已完整支持 mall 渠道——出库 + 生成 `erp_mall_sale`(商城销售)应收 + `syncMallSaleOrder`/`erp.asset.sold.v1` 回流自动建本商城订单(现结→FINISH,挂单→WAIT_PAY)。

> 结论:**商城线下出货 = 复用 ERP 出库(mall 渠道),商城侧只提供选货+开单 UI**。不需要单独的 `shop.asset.sold.v1` 反向事件;ERP 出库内已直连 `CoreOfflineSaleService::createSaleOrder`(class_exists 守卫)。先前设计里的"商城→ERP 反向事件 + ERP 新监听器"已被这条更简链路取代。

## 四、部分退货（双向）

客户买 N 台只留 M 台,退回 N−M：退回的**不收钱、设备翻回在售重新上架、订单只留客户要的、账目只算留下的**。

- **ERP 侧(✅ 已实现)**:出库单 `list.vue` 有「整单退回」(`doCancel`);**挂单结算流程**直接是"留下的填价 / 退回的勾选退回"(`is_returned`/`return_selected`,`留 M 台 / 退回 N−M 台`),路由 `outbound/:id/partial_return`。退回后作废其应收 + 设备翻回可售 + 发 `erp.asset.returned.v1` → 商城 `syncMallReturned`/`returnSaleItemByAsset` 自动同步(删项+重算+翻回在售+退空关单)。
- **商城侧(⬜ 唯一未建)**:商城订单详情**店面端发起**的逐台"退货"按钮。`returnSaleItemByAsset` 后端已就绪,缺的是:① 商城 return-by-asset 接口/路由;② 调 ERP 把该台应收作废 + 设备翻回可售(可复用 ERP `partial_return`/作废逻辑,再靠 `erp.asset.returned.v1` 回同步);③ 订单详情 UI 按钮。
- 两边都通过事件互通,口径一致。

## 五、安装前 / 安装后（联动形态）

| | 未装商城 | 装了商城 |
|---|---|---|
| ERP 出货渠道 | 仅"同行出货" | 同行 + 商城(商城货走商城侧) |
| 财务/看板渠道维度 | 无"商城销售"分类 | 多"商城销售"分类(`erp_mall_sale`) |
| 商城线下卖货入口 | 无 | 有 |
| 退货 | ERP 内部 | ERP ↔ 商城 双向 |

实现要点：所有"商城相关"的选项/列/统计,都用 `class_exists('\addon\phone_shop\...')` 守卫,未装时隐藏,ERP 独立运行不受影响。

## 六、落地进度（对齐实况）

1. ✅ ERP 就地出库回归同行;批量跨页选择 + 多设备检索;应收 `erp_mall_sale` 渠道标 + FinanceDict 映射。
2. ✅ 商城线下卖货:商品列表「开单卖出 / 批量开单卖出」+ sell-dialog → `erp/outbound/create(mall)`,ERP 出库内直连回流建单。**(无需反向事件,链路更简)**
3. 🟡 部分退货:**ERP 侧已全(整单退回 + 挂单留M退N + partial_return + 自动同步商城)**;**仅缺商城订单详情店面端发起的逐台退货按钮**(见第四节)。
4. ✅(天然) 渠道维度:`erp_mall_sale → 商城销售` 纯映射;未装商城就无此数据,标签永不出现,数据层已天然条件化。UI 若要显式隐藏筛选项可后续 class_exists 守卫(非必需)。
5. 🟡 挂单建单:经 sell-dialog 卖在售商品(必有 SKU)→ 挂单会正常建商城 WAIT_PAY 单。先前"挂单无单"多为 ERP 就地出库一台**未上架商城**的设备(`no_mall_goods`,属正常)。

### 现在唯一的待建项
**商城订单详情·店面端逐台退货**(第四节商城侧 ①②③)。ERP 侧退货已可端到端跑通并自动同步商城,故此项为"补齐第二个发起入口",非阻塞。

## 七、保留的底层（已就绪,供上面复用）

- 出库 `createOutbound` 已支持 `sale_channel`(peer/mall)→ 应收 `erp_peer_sale`/`erp_mall_sale` + 备注按渠道。
- `FinanceDict`:`erp_mall_sale → 商城销售`、`erp_peer_sale → 同行销售`。
- 商城 `createSaleOrder`(现结/挂单)、`returnSaleItemByAsset`(退货)已就绪。
- 事件:`erp.asset.sold.v1` / `erp.asset.returned.v1` 已通。
