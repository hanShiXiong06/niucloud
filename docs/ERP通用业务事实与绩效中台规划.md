# ERP 通用业务事实与绩效中台规划

更新日期：2026-07-12
状态：产品架构已确认，待进入开发排期

## 一、产品定位

ERP 是财务与经营事实中台，不接管各业务插件自身的订单 CRUD。

- 回收、会员卡、贴膜、维修、配件等插件各自管理业务流程。
- 业务插件把不可争议的业务事实、人员归属和款项事实提交给 ERP。
- ERP 统一形成应收、应付、收付款、成本、利润、绩效事实和结算结果。
- 业务规则变化只能重新计算绩效，不得修改原始业务事实。

## 二、四层抽象

### 1. 业务事实

记录来源插件、业务类型、来源单号、数量、销售额、成本、利润、发生时间和状态。

业务事实必须具备稳定的来源唯一键，重复请求不得重复入账。退款、退货、返工和作废通过反向事实冲销，不覆盖原记录。

### 2. 人员归属

一项业务允许关联多个人员和角色，例如销售人、回收人、签收人、质检人、定价人、维修技师、接单人和财务确认人。

人员事实保存员工 UID、姓名快照、角色、发生时间和来源依据。分成比例不是人员事实，属于后续绩效规则。

### 3. 绩效规则

规则按站点配置，允许覆盖到业务类型、岗位和个人：

- 固定计件金额；
- 销售额或利润比例；
- 阶梯提成与目标奖励；
- 多人协作分摊；
- 库龄超期扣分与调价任务；
- 固定工资、员工提成、承包和合伙分成。

### 4. 绩效结果

根据业务事实和规则生成可审计的绩效流水。支持日聚合、月结算、封账、补发和跨期冲减。

当天退货不计有效绩效；跨天退货生成负向调整。工资周期封账后不篡改历史，在下一周期冲减或补发。

## 三、建议数据模型

| 数据表 | 职责 |
| --- | --- |
| `erp_business_fact` | 通用业务事实主表 |
| `erp_business_fact_actor` | 事实关联人员及角色 |
| `erp_performance_rule` | 站点绩效规则与适用范围 |
| `erp_performance_ledger` | 正向、冲减和调整绩效流水 |
| `erp_payroll_period` | 工资结算周期与封账状态 |
| `erp_payroll_adjustment` | 跨期补发、冲减和人工复核 |

具体表结构应在开发前结合现有 `ErpFinanceFactRequested`、结算流水和 KPI 模块评审，避免重复建设第二套财务事实。

## 四、业务示例

### 会员卡

A 销售 20 张、单价 200 元。不可变事实是数量 20、销售额 4000、销售人 A、业务状态有效。每张固定提成、超额阶梯或销售额比例均由门店规则决定。

### 维修

维修单记录服务收入、配件成本、其他成本、维修利润、技师和接单人。员工可使用固定工资加利润提成；承包或合伙模式则形成独立分成规则及应收应付事实。

配件销售可以使用标品商品和库存；维修服务必须使用维修工单，不伪装成普通商品。

### 二手机

回收插件进入 ERP 时应携带回收人、签收人、质检人、定价人及时间快照；销售时记录销售人。有效销售、利润、退货和库龄共同决定绩效。

## 五、库存经营指标

- 平均库存周转天数；
- 目标天数内售出率；
- 超龄设备数量和库存金额；
- 调价后再次超龄数量；
- 实际销售净额、毛利和退货率。

设备总库龄持续累计。门店可配置例如每 5 天生成一次调价任务，调价只重置下一次提醒时间，不重置设备库龄。

## 六、实施顺序

1. 定义通用业务事实与人员贡献事实协议 v1。
2. 在 ERP 建立事实、人员和绩效流水基础表。
3. 先用回收与销售链路验证签收、质检、定价、销售和退货冲减。
4. 开发可配置绩效规则与日聚合任务。
5. 再接入会员卡、维修和配件插件适配器。

当前 ERP 独立 Beta 上线不依赖本规划全部完成。本规划属于后续财务中台扩展能力，不应阻塞基础采购、库存、销售和财务闭环试点。
