# 二手机 ERP 全量验收与上线评估报告

日期：2026-07-12  
版本：0.0.1（开发阶段）  
验收范围：ERP 后端、PC 管理端、移动管理端、回收/商城联动基础契约、数据库迁移、核心 UI/UX

## 一、结论先行

### 1. 上线结论

**当前结论：核心业务已具备 UAT / 小范围试点条件，但不建议立即无条件正式商用上线。**

本次没有发现新的设备级金额错乱、重复应收应付或退货后仍可销售等 P0 数据问题。采购、现结、应收应付、折账、采购退货、销售退货、经营收支、幂等和插件事件的自动化检查均通过，现有测试数据在采购、库存、销售、财务页面之间能够对上。

正式上线前仍有 4 个必须关闭的门槛：

1. **凭证图片上传通道异常**：腾讯 COS 多次出现 `cURL error 52: Empty reply from server`。财务凭证、整备凭证无法稳定上传时，不满足商用审计要求。
2. **移动端真实登录验收未完成**：当前移动端测试账号返回“账号或密码错误”，只能完成源码编译与共享接口契约检查，不能代替真实登录后的全流程验收。
3. **PC 串号追踪弹窗存在异步加载异常**：接口已正确返回 7 条数据，但当前开发服务中弹窗出现 loading 不结束。后端数据和操作人字段正确，PC 展示链路仍需在干净服务进程中复验。
4. **并发锁风险需要压测**：日志中出现过 `Lock wait timeout exceeded`，发生在快速创建往来主体/会员编号场景。正式上线前需要并发测试并确认事务粒度和重试策略。

建议发布路径：**预发布环境 → 真实账号 PC/移动双端 UAT → 资金与退货专项回归 → 3~5 家门店灰度 → 正式发布**。

## 六、代码与架构审查

### 做得较好的部分

- 核心交易继续以设备为最小颗粒度，采购单/销售单只作为批次。
- 后端服务是状态和账务唯一口径，PC/移动端不各自计算财务结果。
- 跨插件使用事件 Hook 与来源快照，不直接耦合商城/回收插件内部表。
- 金额变更、退货、收付款和整备完工普遍使用事务、幂等键和二次确认。
- 资金事实、账目事实、库存流水分层，避免重复计账。
- PC 源码与插件镜像 API 保持一致；主要业务页面双份同步。
- 凭证上传已形成公共组件和字段契约。

### 需要优化的代码面

1. **类型检查门禁不可用**：先修复 site-uniapp tsconfig 对生成 `.vue.js` 的处理，再把 `npm run type-check` 加入 CI。
2. **PC 与插件镜像仍是双份源码**：长期手工同步容易漂移。建议插件目录作为唯一源码，通过发布脚本同步到开发目录并校验 hash。
3. **异步请求缺少统一超时与取消**：串号弹窗暴露出请求完成信号不稳定的问题。建议请求 Hook 增加超时、AbortController、重复请求取消和 loading 兜底关闭。
4. **大服务类过重**：`ErpFinanceService`、`ErpStockService` 已承担较多查询、聚合、结算和展示契约。后续按 DashboardQuery、FinanceSettlement、AssetLifecycle 等领域拆分。
5. **运行日志噪声较大**：日志中大量 `DEBUG：>>>>>>>>>` 被记录为 error，降低真实异常可见度。生产环境应关闭 trace debug 并分级记录。
6. **环境文件有未清理空白**：`admin/.env.development` 存在尾随空格，且环境文件与业务代码混在未提交改动中，发布前需单独核对。
