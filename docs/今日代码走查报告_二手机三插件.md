### 2.2 员工考核看板（2354bbb1）
- **做了**：后端 `getStaffKpiBoard` 只读聚合(计数+各环节时效+金额),前端看板页 + 权重可调评分。

- **改进**：评分为"团队内相对归一",筛选范围变则分数变(设计如此,已在页面说明)。

### 2.3 下游流转回流（89d2744f）

- **风险**：依赖 ERP 的 Outbox 队列把 `ready_for_photo` 投出去(需队列 worker 在跑)。
- **改进**：`downstream_*` 5 列是"别的域状态镜像",**属于宽表瘦身的首要清理对象**——改为按需向 ERP/中台查询更干净。

### 2.4 定价对接 ERP 仓库 / 仓库业务类型 / 级联（feb29f39 / d0550022 / 51b226e5 等）
- **做了**：ERP 仓库加 `business_type`(商城/同行/报废/暂存);定价"销售去向"改为 **仓库/库位级联**,选仓按类型自动带出流向;ERP 未装回退固定渠道;`erp_connected` 区分"未接入/已接入无仓库"。
- **风险**：跨插件取仓库走 `event('GetErpWarehouseList')` + `class_exists` 直连兜底——**双保险,较稳**。
- **评价**：这块设计干净,是"模式感知"的好样板。

### 2.5 弹窗性能 / 重复请求（717f5d8f / c99b970e / 043a16f5 / d3ef6e0c）

### 2.7 打款自动入库 A1（3bbe4966 / b8fa0caf / d35b576d）⚠️ 重点
- **做了**：**确认回收**(`recycle()`/`batchRecycle()`)提交后自动 `dispatch` 入库事件 → ERP 监听 `receive()` 后追加"自动确认入库到定价选定仓位"(库位未选则取首个启用库位);全程故障隔离,失败回退"待入库"人工处理。
- **风险(最高)**:
  - 改动了**确认回收主流程**(在 commit 后追加同步,batch 模式整批提交后统一同步,避免嵌套事务副作用)——逻辑正确但**务必在你实例回归**:确认回收→ERP在库→中台待拍照,且失败不影响回收。
  - 自动确认走 `confirmInboundByAsset`(admin 服务,用 `$this->uid`),在事件监听上下文中运行;站点/用户上下文取自当前请求,**需验证多设备/批量场景**。
- **已验证**:你已确认"商城类型→进中台拍照"跑通。
- **改进**:目前自动确认要求仓库有库位;无库位仓会回退待入库(合理但需知晓)。

### 2.8 cron 崩溃修复（263a96bb）
