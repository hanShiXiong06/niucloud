# ERP 独立 Beta 上线范围与门槛

更新日期：2026-07-12
发布定位：ERP Beta 1.0，小范围独立试点

## 一、独立上线原则

ERP 必须可以在未安装回收、商城、报价、会员卡或维修插件时独立安装、编译和运行。

- 分类、规格、成色、往来主体、仓库和库位均有 ERP 本地数据承接。
- 跨插件能力全部通过事件 Hook 可选装配；无人监听时返回空能力，不得报类缺失或页面编译错误。
- ERP 前端不得直接 import 其他业务插件组件、API 或工具。
- 历史来源快照在来源插件卸载后仍可读取。

## 二、Beta 1.0 承诺范围

- 采购录入、设备级入库、现结和挂账；
- 库存档案、仓库库位、串号追踪和成本调整；
- 销售出库、应收和收款；
- 采购退货、销售退货与售后补差；
- 应收、应付、资金账户、结算、折账和凭证；
- 房租、水电等无设备经营收支；
- PC 与移动管理端核心业务入口；
- 分类、规格、成色和设备命名规则；
- 基础经营看板与员工 KPI 统计。

## 三、非独立安装必需能力

以下属于可选增强，不得成为 ERP 安装前置条件：

- 回收订单自动入库、付款接管和状态回流；
- 商城分类同步、订单入站和一物一码上架；
- 会员卡、贴膜、维修及配件业务；
- 通用绩效提成与工资结算引擎。

未安装对应插件时，相关来源选项、同步按钮和提示应自动隐藏或明确显示“未启用”，不能出现 404、空白页和静态 import 报错。

## 四、上线门槛

### 必须完成

1. 使用全新站点只安装 ERP，完成安装、菜单权限、数据库迁移和卸载重装测试。
2. PC 与移动端真实登录完成采购、付款、销售、收款、退货和折账全链路。
3. 使用 3 至 5 台设备核对库存数量、成本、应收应付和资金流水。
4. 验证重复提交、返回页面刷新、空状态、异常提示和操作 loading。
5. 完成数据库备份与版本回滚演练。

### 已知发布风险

- 移动端仍需有效账号完成登录态逐页视觉验收。
- 财务凭证上传依赖的对象存储需要稳定性复验。
- 串号追踪异步 loading 需要在干净服务进程中复验。
- 往来主体快速创建场景需要并发锁和重试验证。

## 五、试点策略

- 第一阶段选择 1 至 3 家熟悉业务、愿意反馈的门店。
- 使用测试资金账户或每日人工对账，不直接无人值守跑正式财务。
- 每日核对库存、应收、应付、收付款和退货冲销。
- 所有异常保留来源单号、请求 ID、操作人和错误日志。
- Beta 期间只修复数据正确性、主流程阻断和高频易用性问题，避免同时扩张过多新业务。

## 六、版本说明

“Beta 1.0”是对外产品发布标签。插件 `info.json`、数据库升级脚本和安装包版本应在正式打包前统一升级，不能只修改页面文案。

推荐发布顺序：开发分支验收 → `dev` → `test` → `release` → 小范围部署。Beta 验收通过后再评估进入正式 1.0。
