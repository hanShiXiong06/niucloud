# 设计说明 · 账务模型 + 角色待办工作台

> 配套《需求整理-ERP财务反馈-20260622》。本页锁定口径,作为施工蓝本。

---

## 一、不可破的护栏(先记这几条,后面都围着它转)

1. **余额永远由真实流水自动算出**——任何地方都不提供"手动改余额/平账"。账对不上 = 去查问题账,不抹平。
2. **核对只标记、不删账**——财务复核打勾只改"看过没看过",绝不改钱、不改余额、不从往来删除。
3. **子账涉及钱,必挂真实应付/应收/流水**——追加成本/收入不是"改个数字",而是记一笔真实发生的钱,顺带挂到设备。
4. **交易账挂设备,经营账不挂设备**——回收/销售/整备 等交易账强制关联设备;房租/水电/工资/额外收入 等经营账单独成类、不挂设备。
5. **折账保留,手动平账不做**——折账(应付↔应收真实冲抵)是业务,留;手动凑平不做。

## 二、账务模型

### 2.1 两个"确定账目准确"的操作(各管一半,互不越界)

| 操作 | 管什么 | 是否动钱 | 产物 |
|---|---|---|---|
| **结算(打款 / 要账)** | 钱到位没有 | **动钱** | 收/付/折账 → 资金流水、应收应付结清 |
| **核对(财务最后复核)** | 这笔账本身对不对(金额/归属/设备/成本利润) | **不动钱** | 一个"已对账"标记 + 操作日志 |

> 钱对(结算)+ 账对(核对)= 账目准确。
> 从程序角度:核对是"提前防住"还是"事后追查"的分界——它**结构上就不能藏钱**,只能做视图筛选,所以安全靠的是设计本身,不是靠人自觉、也不是只靠日志。

### 2.2 设备子账(让账"活"的机制)

- 每台设备挂一个**子账本**,可追加 **+/−** 明细 = 成本或利润的增减(整备费、补差价、其它支出/收入…)。
- **设备利润 = 售价 − 回收价 − Σ成本子账 + Σ收入子账**,全由真实明细算出,从不手改原始值;要纠错走**冲销 + 重记**。
- 每条子账可追溯:金额、加减、原因、经手人、时间;涉及钱的同时落对应应付/应收/流水(护栏3)。
- 整备(需求7)就是这套的一个实例:整备费 = 设备一条 + 成本子账 + 一笔"应付整备服务商"进往来。

### 2.3 设备账目生命周期(一物一码,全程在某个角色队列里)

```
回收(应付) → 质检/拍照 → 定价 → 上架 → 卖出(应收) → 收款(结算) → 核对(对账) → 结束
           └─ 整备/补差价 等子账可在任意阶段追加(挂设备 + 挂应付/应收)
```
在"结束"之前,这台设备永远落在某个角色的待办里,谁也漏不掉。

## 三、角色 → 核心动作 → 待办卡 矩阵

> 原则:**先定动作(动词),再挂数字**;每张卡可点击直达那批待处理列表。

| 角色 | 核心动作(待办卡) | 卡上显示 |
|---|---|---|
| 质检 / 中台 | 待拍照、待质检 | 台数 |
| 定价 | 待定价 | 台数 |
| 运营 / 上架 | 待上架 | 台数 |
| 销售 / 收银 | 我开的挂账待收款 | 笔数 + 金额 |
| 仓库 | 待入库、待出库、待拍照(require_photo) | 台数 |
| **财务** | 待收款、待付款、待结算、**收款待核验**、待对账 | 笔数 + 金额 |

财务"收款待核验"卡的细分(**两层为限**,主卡 + 一层下钻/悬浮):

- 现结:xx 笔 / xx 元
- 挂账:xx 笔 / xx 元

---

## 四、待办工作台设计原则

1. **可点击直达**:每张卡 = 一个动作 + 笔数(+金额),点了跳到那批列表去处理。
2. **颗粒度两层为限**:主卡 + 一层下钻看细分,不在首页平铺三四层。
3. **口径不重不漏**:每层细分加起来必须能对上总数。
4. **砍卡标准**:对每张卡问"点了它能直接处理一批东西吗?"——能则留,不能(只是好看数字)则砍。
5. **性能**:细分=聚合查询,首页别一次算十几个 count/sum;能合并/缓存就合并缓存。

## 五、施工顺序

**轨道一 · 保上线(优先级最高,先于轨道二):**
- 验证核心链路(拍照→定价→上架→商城)真的不依赖 ERP/财务,可独立跑通 → 这是上线唯一硬前提。

**轨道二 · 完善财务(每步小、可独立验证):**
1. **核对 primitive**:复核标记 + 日志 + 筛选(待核验/已核验),不删账。← 待办"收款待核验"的地基,先做。
2. **设备子账(+/−)**:可追溯成本/利润子账,涉及钱挂应付/应收;整备往来化(需求7)一并落。
3. **角色待办工作台**:聚合层。先做财务卡(核对落地后即可),再扩到质检/定价/上架/仓库。
4. **经营支出 + 额外收入 tab**(需求5):独立,随时插。
5. **现结门控**(收款设置开关接到行为上):独立、小,收尾。

> 道理:先有"状态"(核对、子账),才能在上面做"待办聚合";顺序反了卡片就是空的。
