# 顺丰直连：两种业务的接入与升级说明

日期：2026-10-02。范围：新增顺丰通道；不替换快递100、快递鸟或易速。

## 先说明做到哪一步

| 产品 | 本次提供 | 不能混为一谈的结果 |
| --- | --- | --- |
| 电子面单 | 商城取号、查原单、获取与鉴权下载 PDF、重取 PDF、取消原运单、交件后确认商城发货 | 取号不等于出纸；PDF 生成不等于已交件或已揽收 |
| 上门取件 | 回收业务预约、保存原请求、明确失败兜底、原单查询、原单取消、沿用回收状态与牛云 notice | 下单受理不等于派员成功；目前未接入顺丰派员/取件推送验签，不能宣称此部分已全闭环 |

本次没有新增数据库表、字段或修改框架文件。复用已安装的物流任务表和系统配置存储；未迁移历史记录。配置、启用状态、接口权限分别管理。两个产品都使用本站自己的账号，客户不选择渠道。

## 一、管理员准备什么

从顺丰开放平台已经创建的应用获取：

1. 顾客编码 Client Code / partnerID。
2. 当前环境的校验码 Check Word。沙箱和生产不能混用。
3. 本站已开通的快件产品。当前首期提供顺丰特快、顺丰标快两个国内产品预设，目录不代表账号已经开通。
4. 运费方式。寄付可月结或现结；月结填写已经授权的10位卡号；到付不提交寄方月结号；第三方付须有对应授权。
5. 电子面单另需顺丰云打印2.0的模板编码，不能填快递100模板ID。到顺丰控制台「开发者对接 → 查看 API → 基础通用 API → 云打印面单转PDF接口 → 查看」，复制当前应用实际分配的模板编码。不要照抄接口测试工具中的请求示例，也不要使用其他账号的模板。上门取件不需要打印模板。

顺丰侧接口：

- 两种产品都需要：`EXP_RECE_CREATE_ORDER`、`EXP_RECE_SEARCH_ORDER_RESP`、`EXP_RECE_UPDATE_ORDER`。
- 电子面单另需：`COM_RECE_CLOUD_PRINT_WAYBILLS`。
- 上门取件后续派员闭环需：`PushOrderState`，并确认当前账号实际使用的推送格式和鉴权方式。不能直接把未验签的公网回调作为业务事实。

顺丰明确说明只有预约上门订单才推送调度状态。当前代码不会接收未经认证的派员、取消或揽收消息。此部分需取得官方账号对应的推送鉴权约定、联调后再开放；不是只填一个网址就已经完成。

## 二、电子面单怎么用

### 1. 配置物流

入口：`/site/hsx_express/config?provider=sf_direct&scene=waybill`。

选择环境，填写本站账号、产品、付款方式和模板。第一次填写账号或切换环境，系统会停用并要求重新确认，防止把旧凭据带入新账号。

保存并检查只做本地必填项和格式检查，不下单、不扣费，不证明正式权限、网点或打印机可用。校验码加密存储，页面只显示已保存和星号；空白保留原值。

### 2. 商城选择新通道

入口：`/site/phone_shop/delivery/electronic_sheet/config`，选择“顺丰直连（PDF 本地打印）”。原有快递鸟、快递100继续保留。

商城物流公司应存在唯一的顺丰记录，快递公司编码 `express_no` 为 `SF`。不会要求为了直连顺丰填写快递100的账号。

### 3. 从订单发货

选真实待发货订单与本次发货商品 → 核对真实寄收件地址和重量 → 申请电子面单 → 点击“打印面单”（无需先下载）→ 在打印窗口选择打印机，检查条码并贴单 → 实际交给快递后确认商城发货。

“打印面单”读取已经生成的原单 PDF，在页面内预览并尝试自动打开浏览器打印窗口；不会重新取号或确认发货。若浏览器阻止自动弹出，使用预览底部“打开打印窗口”或 PDF 内的打印图标。首次请核对打印机、纸张及缩放设置；下载按钮保留为备用。当前不是免电脑的硬件云打印，也不会绕过浏览器确认直接出纸。

本次只改管理端插件文件，不修改公共框架、PHP 或数据库。插件源码与 `admin/src/addon` 对应文件均已同步：

- `hsx_components/admin/components/HsxPdfPrint/index.vue`：新增可复用 PDF 打印按钮，复用 HsxButton、HsxDialog；不依赖具体快递商。
- `phone_shop/admin/views/order/components/provider-waybill-panel.vue`：商城发货弹窗的“打印面单”，下载改为备用。
- `hsx_express/admin/views/tasks/index.vue`：物流任务详情提供相同的打印入口。
- `hsx_express/admin/components/sf-config-panel.vue`：更新操作指引。

管理端需重新打包并部署；只覆盖后端 PHP 不会出现新按钮，不需要执行 SQL。不要遗漏新增的 `hsx_components` 组件。

验证结果：`verify_pdf_print.cjs` 41 项通过、`verify_admin_ui.cjs` 68 项通过，真实 Vue 组件隔离打包通过，`git diff --check` 通过。覆盖原 PDF 复用、加载提示、无效响应、过期/取消/无权限状态、重复加载不重复打印、取消后重试、切换包裹或关闭时丢弃迟到响应，以及本地临时 URL 清理。未修改取号、财务、库存或发货确认流程。

浏览器隔离预览已显示一页 100×150 mm 假面单，无真实姓名、地址或运单。当前受控浏览器未能确认原生打印对话框实际显示，因此不能把单元测试调用 `print()` 当作实体打印验收。未调用顺丰、未真实取号、未实际出纸、未发布线上。上线验收仍需在门店 Windows Chrome/Edge 点击“打印面单”，确认打印窗口、打印机及纸张，打印后核对条码；取消打印应保留原单且不确认发货。

- 同一包裹已有未取消任务时，继续原通道、原账号、原申请，不因配置换了而重新申请。
- 沙箱任务不能确认真实商城发货；把本站已知沙箱单号手工粘贴到发货入口也会被拦截。
- 已知本站顺丰任务须匹配原订单与商品，不得用另一个订单的单号确认发货。
- 打印机是否实际出纸需要工作人员确认；本次不发送硬件云打印任务。
- 每次按一个包裹处理，不支持在一次请求里随意合并多个独立包裹。

### 4. 失败怎样处理

| 情况 | 正确操作 |
| --- | --- |
| 顺丰明确拒绝，例如白名单、权限、月结或预约时间错误 | 看原因，修正后从业务入口重试；未将拒绝显示为成功 |
| 超时、重复订单提示、响应无法确认 | 查原单，不重新取号、不换渠道重下 |
| 已取到运单，PDF失败 | 只重取原单 PDF；不创建新运单 |
| 模板填错 | 在相同账号、相同环境下修正模板，再重取原单 PDF；不改原运单与月结关系 |
| PDF过期 | 重取原单 PDF；下载地址和token不会裸露给前端 |
| 取消请求超时 | 重试确认原单取消；只有原单明确取消后才能重新申请 |
| 顺丰仍返回含糊取消结果 | 保留待核实，联系顺丰核实原订单编号；不能当作已取消或直接重下 |

取消运单不等于取消商城业务订单，不退款、不冲销应收、不恢复库存。退货资金动作仍走既有退回/退款流程。

## 三、回收上门取件怎么用

1. 入口：`/site/hsx_express/config?provider=sf_direct&scene=pickup`，独立配置上门取件。
2. 返回 `/site/third_party/express_order` 选择“顺丰直连”。无需再复制一遍校验码、月结号。
3. 站点管理员设置收件地址及回收业务参数；客户只填写寄件信息和未来的预约时段。
4. 回收下单按站点设置请求顺丰上门取件，记录稳定的原请求编号。
5. 建单最多显示“已受理”，不显示“已派员”。没有顺丰返回的取件人电话，不编造或用门店电话冒充。
6. 明确拒绝后沿用回收失败提示和自行寄件入口；结果不明先核实，禁止同时预约与自寄造成重复派员。
7. 查原单、取消使用原站点、原账号和原环境；停用新预约不等于取消历史预约。账号已变更且原账号无法核实，会明确阻止调用其他账号。

生产回收入口拒绝沙箱预约，不会用测试运单更新客户的真实回收订单。当前上门取件没有接入报价、改约、账户余额查询和派员推送，不会把未报价说成免费。

### 通知范围

继续通过牛云现有 notice 事件发送，不新增另一个通知管理系统。通知还取决于站点模板开通和客户订阅资格。本次不会为了看起来完整而在“已受理”时发送虚假的派员成功消息。

### 派员推送还需要顺丰确认什么

由平台开发人员向顺丰当前应用的接口支持确认 `PushOrderState`，不是让终端客户填写技术参数：

1. 当前应用使用 JSON、表单还是 XML 推送；给出脱敏请求样例，包括请求头。
2. 如何认证推送来源：实际签名字段、签名原文顺序、编码方式、所用凭据、时间戳与重放校验规则。需要可校验的官方约定，不能猜一个 `sign` 或 `verifyCode` 字段。
3. 开通范围、沙箱测试方法、重试及确认响应规则；是否提供重复或乱序推送样例。
4. 派员成功、取消、取件完成分别由哪些状态码确认；取件员电话和预约时间的返回条件。

取得约定后，由开发人员在插件内实现验签、原订单与本站匹配、重复消息去重、乱序保护，再接入既有取件状态和 notice。最后用一笔获授权的真实预约验收“已受理 → 已派员 → 已取件”，核对客户页面与通知。不要向客服或文档中发送校验码原文。

## 五、验收标准

- 面单：原单唯一、金额/库存不受取号影响；PDF能打开，现场打印可扫描；实际交件后商城发货成功。
- 取件：预约、失败、自寄边界准确；明确取消可结束；派员推送尚待安全联调，未完成前不能验收为全自动取件闭环。
- 两种业务互不启停、互不借用凭据，切换服务商不改历史任务。
- 正式权限、费用、快递员联系、真实取件、打印出纸和客户收到通知，需要单独实单验收，mock通过不等于这些已发生。
