# hsx_express 1.0.0 手动部署与更新清单

日期：2026-09-30。

## 本次更新边界

- 新增独立插件 `hsx_express`，提供快递100电子面单、电脑打印文件、云打印任务、原单补打及取消。
- 商城 `phone_shop` 增加可选物流能力注册与调用，原快递鸟仍可使用。
- 回收 `hsx_recycle` 仅增加可选传输桥接；预约、状态、回调、通知、历史记录仍由回收插件管理。
- **新增一张表：`实际前缀_hsx_express_task`**。不修改商城订单、商品、回收、ERP、库存或财务表结构；不迁移旧运单。
- 本轮不修改公共框架文件。复用现有 `hsx_components`、配置存储、事件、菜单权限、notice 及商城发货流程。
- 本轮不包含线下订单退回/退款功能；新打单入口位于商城现有订单发货弹窗，不将回收预约和电子面单混为一笔订单。

### 增量修复：orderId 超长、配置页折叠与密钥已保存状态

适用于已经安装上述版本的站点。本次 **不新增表或字段、不需要 SQL、不修改框架或 phone_shop**。

**先修复取号报错，后端覆盖以下 3 个文件即可，不需要前端打包：**

```text
niucloud/addon/hsx_express/app/service/core/LogisticsService.php
niucloud/addon/hsx_express/app/service/core/Kuaidi100Client.php
niucloud/addon/hsx_express/app/api/controller/Callback.php
```

- 原因：旧代码生成 `HX + 14位时间 + 20位随机数`，合计 36 位，直接发送为 `orderId`；此次服务商明确返回“orderId长度范围为2-32”。不是快递100 Key 的填写问题，也不是商城业务订单号过长。
- 新请求生成 32 位任务号，并在发送前校验长度；超限不调用外部接口，不截断旧编号，不移除 `reorder=false` 防重复保护。
- 回调同时识别新 32 位和原 36 位任务号。已有记录、订单号、账号、历史任务身份保持不变。
- 更新上述文件后按部署方式刷新 PHP OPcache / 常驻进程；不要清空任务表或业务数据。
- 对已明确标为“未取号”的这笔失败记录，更新后回到**原商城订单**重新申请一次即可，系统保留失败记录并新建一次有效长度的尝试。结果待核实、已经取号的任务不能以此方式换编号重下，应继续核实原任务。
- 此修复解决的是请求编号限制，不表示账号权限、网点、产品或打印已经真实验收通过。

**配置页优化另外更新下列 2 个前端源文件，并同步运行镜像后打包管理端：**

```text
niucloud/addon/hsx_express/admin/views/config/index.vue
niucloud/addon/hsx_express/admin/components/saved-credential-input.vue
admin/src/addon/hsx_express/views/config/index.vue
admin/src/addon/hsx_express/components/saved-credential-input.vue
```

- `saved-credential-input.vue` 是本次新增的插件内组件，不能只上传配置页，否则构建缺少依赖。
- 快递100 Key / Secret 与快递公司面单账号分区；中通明确显示“中通快递打单 Key（partnerKey）”。
- 已保存凭据显示 `****** · 已保存 · 更换`，不回传密钥原文。取消或留空保留原值；掩码本身不进入保存表单。
- 方案、字段说明、回调、首单指引和已通过检查按需展开；未通过检查仍直接显示。云打印会自动展开必填回调配置。
- 不需要重新填写已保存的账号，不会因为更新页面自动改动线上配置。仅后端修复与页面更新可分开部署。

本次回归脚本及测试结果见《2026-09-30_测试报告》。线上真实取号、费用及实际出纸仍需由操作人员核对。

### 同版补充：中通起步与多承运商配置

- 不再限定顺丰、京东；快递100国内网点面单参考目录、产品及账号要求在插件内维护，选中通只要求中通资料。
- 新增字典文件 `app/dict/waybill/carriers.json` 及解析类 `app/service/core/WaybillCarrierCatalog.php`。覆盖插件时两者必须一起上传；不能只更新页面。
- `ConfigService.php` 按所选承运商检查配置；`WaybillProtocol.php` 按字典传入账号和固定标识；`LogisticsService.php` 按承运商能力控制取消，并返回快递名称和明确提示。
- 商城 `CoreOrderDeliveryService.php` 修正实际物流发货分支的面单校验位置：原来误放在虚拟发货分支，现在确认快递发货前校验，阻止已取消、状态不明、单号或公司不匹配的面单。
- 前端同步更新物流插件的配置页、任务页、`utils/presentation.ts`，以及商城 `provider-waybill-panel.vue`；源码和运行镜像均须一致后重新构建管理端。
- **这次补充不新增任何表或数据库字段，不需要额外 SQL。** 首次安装新插件仍需上文所述 `hsx_express_task` 表、插件登记与站点授权。不要把“此次无额外 SQL”理解为首次安装不建表。

### 同版补充：物流配置通过，商城仍只有快递鸟

2026-09-30 对 `gl.hsxbk.top` 的只读排查确认：商城电子面单配置接口没有返回 `providers`，页面加载的 `electronic_sheet_config-c22ff51f.js` 也没有服务商选择逻辑。这表示该环境的商城配套前后端尚未部署到位，不是中通账号填写错误。

`hsx_express` 的“配置项已齐全”只检查物流插件自己的必填项和格式，不代表商城已接入。**只更新物流插件不够，还必须更新下文列出的商城后端文件和管理端页面，并构建发布管理端。** 只替换配置页虽然可能显示选项，但不能补齐取号、打印、取消与确认发货链路。

可以在浏览器网络面板查看 `/adminapi/phone_shop/electronic_sheet/config` 的响应来区分问题；分享排查信息时遮盖账号及密钥：

| 接口/页面现象 | 含义 | 处理 |
| --- | --- | --- |
| `data` 中没有 `providers` | 商城后端仍是旧接口 | 更新本清单列出的 `phone_shop` 后端配套文件，再按部署流程刷新应用缓存/常驻进程 |
| `providers` 有 `hsx_express_kuaidi100`，页面却没有“快递100（物流服务）” | 管理端构建产物或浏览器缓存未更新 | 核对 `admin/src` 镜像，重新构建发布后强制刷新页面 |
| `providers` 只有 `kdbird` | 当前接口没有发现可用的扩展服务商 | 检查 `hsx_express` 是否完成安装、当前站点授权及事件缓存；不要绕过站点授权强行展示 |
| 配置请求失败 | 配置没有成功读取 | 根据具体错误排查权限或接口；页面禁止保存，避免覆盖原配置，支持重试 |

本次管理端会针对这些情况显示对应提示，不再无提示地只留下快递鸟。已有快递100账号无需重新录入，也不需要因此开通顺丰或购买快递鸟。**这次接入检查补充无新增 SQL、无公共框架改动。**

## 一、部署前

1. 备份目标站点数据库、下文涉及的文件及当前管理端构建产物。不要用开发库覆盖正式库。
2. 确认目标库实际前缀。不同部署可能为 `saas_`、`phone_` 或其他值，不能照抄另一套系统。
3. 检查现有 `.env` 的 `app.auth_key` 已配置，并妥善备份。**不要为本插件随意重置原密钥**；密钥用于加密物流凭据和原任务账号快照，更换后旧任务可能无法解密。
4. 现有 PHP 需可用 OpenSSL、PDO MySQL、mbstring；复用项目已经安装的 GuzzleHTTP，不需要额外安装网上的 PHP 示例项目。
5. 请先在一个测试/试点站点完成配置和实际发货验收，再授权其他站点。

## 三、数据库及插件注册

### 第一次安装（建议）

上传新插件后，在平台「应用管理」完成 **物流服务 / hsx_express** 的本地安装，再授权给试点站点。框架安装器会自动替换 SQL 表前缀、注册插件和导入菜单。只上传文件或只建表，事件监听不会必然生效。

### 需要手工执行 SQL 时

原始文件：`niucloud/addon/hsx_express/sql/install.sql`。

文件中的 `{{prefix}}` 是安装器占位符。手工 SQL 工具不会替换它，可在 `niucloud/` 目录运行以下 **只输出 SQL** 的命令，审查后再导入对应数据库：

```sh
php addon/hsx_express/scripts/render_install_sql.php --prefix=saas_
```

把 `saas_` 换为目标库实际前缀。输出仅为 `CREATE TABLE IF NOT EXISTS`，不清空已有记录。不执行 `uninstall.sql`，不删除历史任务。

`sql/upgrade_1.0.0.sql` 与首版建表 SQL 相同，供人工部署使用；**不要把建表成功当成插件已安装和已授权**。首次仍需要平台插件登记及站点授权。

本版不是对某个已发布 `hsx_express` 旧表的字段迁移。如果目标库曾放过非本版试验表，请先比对结构，不要靠 `IF NOT EXISTS` 掩盖字段缺失。

## 四、刷新菜单、权限和管理端

在后端 `niucloud/` 目录执行已有框架命令：

```sh
php think menu --addon=hsx_express
php think menu --addon=phone_shop
```

然后按当前项目的部署方式清理应用路由/事件缓存；有常驻 PHP 进程或 OPcache 时按运维流程重载。不要直接清空整个 `runtime/`，其中可能存在日志和其他业务文件。

平台给试点站点授权新插件；站点管理员给员工分配：

- 配置维护：`hsx_express_config` 及保存/检查权限。
- 运单查看：`hsx_express_tasks`、任务详情。
- 操作权限：补打、取消、恢复原申请分别分配，不必让所有人都能取消。
- 商城发货：原发货权限及新增 `phone_shop_order_waybill_task`。

在 `admin/` 使用当前锁定依赖打包，不需要升级 Vue、Element Plus：

```sh
npm run build
```

构建读取的是 `admin/src/`。`niucloud/addon/phone_shop/admin/` 是插件分发源码，只更新这一份不会直接改变已经上线的页面；需将本清单涉及的文件同步到 `admin/src/addon/phone_shop/` 后再构建。

当前项目的 `npm run build` 会在 Vite 构建成功后执行 `publish.cjs`，将构建结果发布到 `niucloud/public/admin/`。若在本地打包再上传，需按既有部署流程整体发布匹配的管理端产物，不要只复制一个带哈希的 JS 文件；如在服务器构建，先备份当前产物并安排适当的发布时段。不要为了这个问题删除锁文件或升级依赖。

发布后让管理员重新登录刷新菜单权限。本轮不涉及小程序页面改动，不需要为了本插件重打小程序。

## 五、部署后检查入口

1. `/site/hsx_express/config`：选择电脑/云打印，再选择本站已开通的快递（当前可先选中通），按动态字段填写本站账号，保存并检查；无需提前取得顺丰资料。
2. `/site/phone_shop/delivery/electronic_sheet/config`：确认出现“快递100（物流服务）”，选中并保存；刷新后仍保持选中。对应配置接口应包含 `providers`，保存后的 `interface_type` 为 `hsx_express_kuaidi100`。页面不再要求填写快递鸟账号或配置快递鸟的本地打印控件。
3. 商城默认发货地址与物流公司配置要完整；快递公司电子面单编码优先匹配，缺失或重复会阻止取号并提示。中通的快递100编码为 `zhongtong`，不要将快递鸟编码混填到快递100编码字段。
4. `/site/phone_shop/order/index`：打开真实待发货订单，选商品申请面单，打印，实际交件后确认发货。
5. `/site/hsx_express/tasks`：核查单号、取号/打印状态、异常及操作日志。
6. 回收仍使用 `/site/third_party/express_order` 的账号与产品配置；未授权新插件的站点继续原传输，不会自动改用商城账号。

详细账号来源及各角色操作见《快速上手与业务验收》。配置检查只检必填和格式，不能承诺账号权限、价格、线路、实际出纸或客户收到了通知。

## 六、回退和停用

- 先停止新取号，不要在有结果待核实任务时切换服务商重新申请。
- 有未完成运单时保留新插件、原账号和任务表，以便查询、补打或取消。
- 后续新业务可以恢复选择原快递鸟，但前提是原快递鸟配置本身有效。
- 卸载不删任务记录；不要删除任务表或重置 `app.auth_key`。卸载导致的旧任务不可操作，应先恢复原插件再处理，不能换渠道冒充原单。
- 不承诺外部已产生的运单或费用能通过回滚代码撤销；须按快递渠道实际结果处理。

## 七、将来再接其他服务商

- 商城只认 `PhoneShopElectronicSheetProviders` 能力注册事件，按管理员选择的一个 provider 执行，不广播下单。
- provider 实现取号、查询本地任务、补打、取消及订单互斥锁；账号和协议细节留在提供该能力的插件内。
- 业务在取消或恢复前通过 `HsxExpressTaskOperationGuard` 明确授权，不能让通用任务页绕过商城已交件/已退款的限制。
- 回收只通过 `HsxExpressTransportRegistry` 选择可选传输层；不把预约业务状态交给面单插件。
- 新增其他商城/业务时需要实现对应业务适配与权限，不宣称只安装物流插件就能自动接通所有业务。
- 原有快递鸟的接口逻辑保留，不因安装本插件自动迁移。原渠道的实际权限与费用仍需自行开通确认。
