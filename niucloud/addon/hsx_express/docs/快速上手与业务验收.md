# 物流服务：快速上手与业务验收

适用范围：`hsx_express` 物流服务、`phone_shop` 商城发货、`hsx_recycle` 回收上门取件。

## 先选一种方案，不要一次配置所有服务

| 方案 | 适合谁 | 需要准备 | 不需要准备 |
| --- | --- | --- | --- |
| 电脑打印面单（建议先跑通） | 已有电脑和可打印快递面单的打印机 | 本站快递100电子面单 API 账号、快递公司面单账号、V2 面单模板 | 快递100云打印机、回收寄件账号 |
| 云打印机自动打印 | 门店已准备兼容快递100的云打印机，需要多人远程打单 | 上述账号、模板，以及已绑定的设备码 | 本机 Lodop 打印控件 |
| 回收上门取件 | 客户在小程序预约快递上门，门店不打印面单 | 本站快递100上门取件服务账号、固定承运商、寄付/到付安排、公开回调 | 电子面单模板、云打印机 |

第一期建议：先用一台设备、一笔真实商城订单跑通“电脑打印”；确认业务和成本后，再切换到云打印。选择方案不会自动开通快递100服务，不会自动下单或扣费。

已有快递鸟的站点可继续使用原配置，不要求迁移。新站点也不必为了使用快递100先购买快递鸟。

**快递100是接口服务商，中通、顺丰等是承运商。只需配置本站当前已开通的一家，不要求先有顺丰资料。** 一个站点当前使用一套已选承运商配置，不让终端客户选择渠道。

## 当前先用中通跑通

1. 打开 `/site/hsx_express/config`，选择“电脑打印面单”，快递公司选择“中通快递”。已有兼容云打印设备时也可选择云打印。
2. 填写本站快递100 **Key、Secret**，这是接口账号，与中通面单账号分开。
3. 只需要向中通签约网点或客户经理取得下列三项资料，不需要顺丰月结账号、顾客编码或校验码。

| 页面字段 | 快递100接口字段 | 从哪里拿 |
| --- | --- | --- |
| 电子面单账号 | `partnerId` | 中通网点提供的面单账号 |
| 打单密钥 | `partnerKey` | 与该账号配套的中通打单密钥 |
| 网点编码 | `net` | 开通该面单账号的中通网点 |

中通固定标识 `code=ztoOpen` 由系统按官方字典填写，页面不会要求申请或手填。

4. 从产品列表选择**该账号实际开通**的中通产品，选择约定的寄付、到付或月结方式。列表只是官方目录，并不代表所有选项都已获授权。
5. 在快递100模板管理中取得对应中通的 V2 面单模板 ID。使用云打印时再填兼容打印机设备码和公开 HTTPS 回调根地址。
6. 勾选开通确认，启用并“保存并检查配置”。配置检查不下单、不收费，也不核验真实账号权限。
7. 在商城电子面单设置中选择“快递100（物流服务）”；商城物流公司中中通的快递100编码应唯一对应 `zhongtong`，同时配置默认寄件地址。
8. 从一笔确实需要发出的商城订单申请面单、打印、实际交件，再确认发货。真实取号可能计费，不要拿真实客户信息随意试单。

以后开通顺丰，再切换到“顺丰速运”填写顺丰自己的账号、产品、模板。切换时清空当前表单的承运商账号、产品及模板，并关闭启用、取消开通确认，避免串用；快递100接口账号和打印机资料保留。保存切换后，原中通任务仍使用其加密保存的原账号处理，不会被改成顺丰运单。

本版内置官方国内网点面单参考目录，按所选公司动态显示参数、产品及付款方式，并非只支持中通或顺丰。目录中账号参数不完整、产品缺失或不返回面单文件的公司会明确提示并阻止启用，不能把“可在目录搜到”当成“已经联调可用”。第三方平台授权账号（如菜鸟、淘宝）和国际专用接口不在当前网点账号方案内；尚未开通的公司不影响现在使用中通。

## 一、谁负责准备什么

### 平台部署人员

1. 安装物流插件，执行配套安装 SQL；更新商城通用扩展文件并打包管理端。
2. 给需要使用的站点分配插件及菜单权限。只上传目录不等于已经安装并授权给站点。
3. 核实 SaaS 的公开 HTTPS 根地址可从公网访问，不能使用 localhost。
4. 保管部署密钥及数据库备份。密钥变更会影响原凭据解密，应先按部署说明处理。

### 站点管理员

1. 选择本站的使用方案。
2. 用本站自己的快递100账号开通对应 API 产品；上门取件和电子面单不是同一种服务权限。
3. 联系快递公司或快递100确认面单账号、已开通的快递产品、结算方式、可寄物品及揽收安排。
4. 配置本站账号、模板和可选打印机，执行配置检查。
5. 安排一笔可实际发出的订单验收，不要拿真实客户地址做无目的试单。

### 门店发货人员

核对设备、包裹和收件地址，申请面单，核对打印内容，贴单并交给快递；实际交件后才在商城确认发货。

## 二、配置中的信息从哪里获取

| 页面信息 | 获取位置或负责人 | 注意事项 |
| --- | --- | --- |
| 快递100 Key、Secret | 快递100企业管理后台；找不到时联系对应账号客户经理 | 不是微信密钥，也不是快递公司的月结账号 |
| 快递公司 | 系统提供的官方参考目录中选择 | 目录有该公司，不等于本站已开通 |
| 快递产品 | 选择快递公司后从产品列表选择 | 不要求手写“顺丰标快”等任意名称；实际权限、线路仍由渠道确认 |
| 面单账户/月结账号 | 快递公司当地网点、客户经理或官方账号申请流程 | 有月结账号不等于电子面单 API 权限已经开通 |
| 面单密码、密钥等 | 依据所选快递公司的参数说明索取 | 只填写该快递公司要求的字段，不把同一个账号复制到所有字段 |
| 运费支付方式 | 按与快递公司签约约定选择 | 接口服务费、运费、硬件费用是不同项目；未知费用不等于免费 |
| V2 面单模板编号 | 快递100企业后台的电子面单模板配置 | 模板须与快递公司匹配，不混用 V1 模板 |
| 云打印设备码 | 打印机输出的设备码及设备绑定页面 | 普通 USB 打印机不能仅填一个编号就变成云打印机 |
| 公开回调根地址 | 平台部署人员提供 SaaS 的 HTTPS 根地址 | 系统根据任务生成完整回调，不让门店手拼参数 |

- [电子面单 V2 接口、打印回调及原单补打](https://api.kuaidi100.com/document/dianzimiandanV2)
- [快递公司账号字段、产品名称和支付方式字典](https://api.kuaidi100.com/document/5f0ff6e82977d50a94e10237)
- [电子面单账号申请指南](https://api.kuaidi100.com/document/zhanghaoshenqingzhinan)
- [Key 获取指引](https://api.kuaidi100.com/document/chakankey)

产品参考目录随插件维护，不是账号实时授权清单。套餐价格、接口权限、快递费、硬件兼容性以实际合同及服务商当时说明为准。

## 三、商城发货的完整操作

1. 管理员在“物流服务 → 接入与上手”选择电脑或云打印，保存本站账号并检查配置。
2. 在商城电子面单设置中选择“快递100（物流服务）”。原快递鸟可保留，未选择的渠道不会参与下单。
3. 发货人员打开待发货订单，选择本次发出的设备，核对承运商、寄件地址、收件地址和重量。
4. 明确确认后申请面单。这一步可能产生真实运单和服务费用，系统不会把配置检查当成试单。
5. 电脑方案：打开返回的 PDF/图片面单，用浏览器或系统打印；云打印方案：查看打印任务结果，并确认打印机实际出纸。
6. 核对单号、地址和设备后贴单、交件，再在商城确认发货。取号成功或云打印请求受理，都不等于实际交件。
7. 单号回到商城包裹记录；异常在物流任务中查看。客户发货通知继续使用商城及牛云原有 notice 链路，不增加第二套通知参数管理。

不要反复点击“申请面单”来补打。补打必须使用已保存的原任务。官方对原单补打有时间与次数限制，超过限制时应联系客服，不通过重新取号规避。

## 四、回收上门取件的完整操作

1. 在回收“第三方服务 → 上门取件服务”配置寄件账号。面单账号不能直接代替寄件账号。
2. 管理员固定承运商、产品、结算方式及预约规则；客户无需自己选择供应商。
3. 客户提交回收订单并选择上门取件时段。
4. 页面按真实结果显示预约是否受理、单号及取件安排；快递员姓名、电话、时间仅在渠道提供后显示，不填造默认值。
5. 按现有牛云消息管理获取并开启“回收预约取件状态通知”；客户通知授权、渠道响应和收件人实际收到是三个独立验收项。
6. 明确失败时，提示客户联系门店或自行寄件。结果待核实则先核对原预约，避免同时再叫一位快递员。

上门取件仍使用回收业务自己的订单、回调、通知和状态管理；不会因为安装物流插件而重建历史预约或更换原渠道。

## 五、异常怎么处理

| 看到的情况 | 现在意味着什么 | 应该怎么做 |
| --- | --- | --- |
| 配置不完整 | 尚未满足本地必填/格式检查 | 按提示补齐对应字段；没有发起真实下单 |
| 配置检查通过 | 本地配置完整 | 继续做真实试单；不代表账号权限、余额或线路有效 |
| 渠道明确拒绝 | 返回了明确失败原因 | 核对权限、账号、产品、地址，按提示处理，不能只反复点击 |
| 请求结果待核实 | 请求可能已经送达渠道，但本站未得到可靠结果 | 保留任务号和业务订单号，等回调或联系快递100核实；禁止自动换渠道、重复取号 |
| 显示“恢复原申请” | 原取号结果未知，且仍在系统允许的原编号恢复窗口内 | 确认包裹仍需寄出后，沿用原账号、原编号申请；已有成功结果时复用原单，原请求未受理时可能首次取号并计费，不是只读查询 |
| 有运单但打印失败 | 取号和打印是两个结果 | 检查纸张、设备和网络，使用原任务补打，不重新下单 |
| 打印待确认超过 90 秒 | 尚未得到明确打印结果，不代表没有出纸 | 先检查打印机和原面单；系统允许后可显式确认补打原单，可能再次出纸，不会自动连打 |
| 浏览器打开了面单 | 面单文件可访问 | 仍需确认实际出纸；系统不假装知道物理打印结果 |
| 运单已取消 | 渠道确认取消该运单 | 不再使用原单发货；不代表商城订单被取消或客户已退款 |
| 不支持接口取消 | 所选快递的官方能力字典未支持自动取消 | 任务页不显示可用的自动取消入口；联系承运商或快递100处理，不能假装取消成功 |
| 已实际交件后需要取消 | 可能需要拦截、退回等承运商操作 | 联系快递公司处理，不把“取消面单”当成物流拦截 |
| 更换服务商或账号 | 后续新任务使用新设置 | 原任务仍按原渠道和账号处理，不把旧任务交给新账号重试 |

原编号恢复采用快递100的 `reorder=false` 机制。官方去重窗口为 48 小时，本系统保守限制为原申请提交后 47 小时内；超过窗口不再自动请求，须联系渠道核实。恢复成功仍需人工检查面单、贴单及实际交件。

取消结果待核实没有“强制成功”按钮；仅凭超时或工作人员猜测不能把渠道状态改为已取消。此类超时需渠道人工协助，不能承诺全部异常都能纯自动解决。

## 六、验收不能只看“操作成功”

上线前逐项打勾：

- [ ] 新插件安装完成，当前站点有权限，配置和任务页面可打开。
- [ ] 配置失败能准确指出字段，保存不会清空未修改的密钥。
- [ ] 选择中通时仅要求中通面单账号、打单密钥、网点编码；无顺丰资料也可通过本地配置检查。
- [ ] 切换承运商不会混用账号、产品或模板；原任务仍显示原快递并使用原账号。
- [ ] 一笔真实商城订单成功取得单号，刷新或重复点击不生成第二个任务。
- [ ] 面单能实际打印，内容和收件地址正确；云打印还须检查实体出纸。
- [ ] 打印失败能够从原任务处理，不把订单自动标记成已交件。
- [ ] 实际交件并确认发货后，商城单号、包裹、设备和客户通知一致。
- [ ] 未交件的测试面单按渠道规则成功取消；没有产生重复业务订单。
- [ ] 超时能显示待核实，不允许盲目再次取号。
- [ ] 不同站点看不到彼此的任务、账号和地址。
- [ ] 回收原有预约、回调、通知不受影响；有取件业务的站点另做一次真实预约验收。

本地模拟测试能验证代码和异常分支，但不能替代实际账号、签约产品、真实运力、纸张打印和通知送达验收。
