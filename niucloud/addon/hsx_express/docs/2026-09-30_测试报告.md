## 核心业务断言

### 增量修复：取号编号限制与配置页易用性

客户实测返回“未取号：orderId长度范围为2-32”。代码核对确认：原任务号为 36 位，并原样作为接口 `orderId`。本次将新任务缩为 32 位，发送前检查长度，回调保留对已存在 36 位记录的识别；不截断已发送编号、不改历史记录、不移除防重复取号。

本次实际重新执行并通过：物流后端 257 项、插件 UI 68 项、商城后端接入 63 项、商城 UI 46 项、回收传输桥接 19 项，以及独立浏览器脚本。3 个变更 PHP 文件语法检查通过；源码与运行镜像一致，差异空白检查通过。上表其他数据库专项等项目为同版此前执行结果，不是此次重复执行。

新增或补充断言：

- 新生成、实际请求与持久化任务号一致，长度为 32；回调 URL 使用同一编号。
- 缺失、空、1 位、33 位、旧 36 位和非字符串请求编号均在发请求前拦截；2 位与 32 位边界可通过，不擅自截断或重新生成编号。
- 新旧回调编号均能通过格式检查；路径片段、尾随换行及其他长度被拒绝。
- 已确定失败的原 36 位任务保留，重新从原业务申请生成独立的 32 位尝试；已有成功/未知任务重复点击仍不重复请求。
- 读取后 Key、Secret、快递公司密钥可见 `******` 和“已保存”；掩码不作为输入值，旧密钥原文不在页面 DOM。
- 点击“更换”才输入新值；取消更换或不修改时提交空值保留原凭据；显式替换后刷新为已保存状态。测试保存接口模拟后端的掩码和保留规则，不使用真实账号。
- 中通的 `partnerKey` 使用明确中文标签；切到其他快递不显示旧公司的已保存密钥。尚未保存时切回原公司，仍可识别服务端原有密钥。
- 说明与已通过检查默认折叠，未通过项直接显示；回调表单折叠后保留未保存输入；云打印自动展开回调配置。
- 读取失败禁止保存和切换打印方式，可直接重试读取，避免空配置覆盖旧凭据。

没有访问真实下单接口、写生产配置、执行 SQL 或发布线上。账号填对、获得运单、实体打印是后续独立验收，不能由这些本地结果替代。

### 本轮修正：按承运商配置，中通无需顺丰资料

- 字典快照来源为快递100官方国内网点面单参数及产品表；共 72 个目录项，52 项具备当前页面要求的账号字段、产品与返回面单能力。此数量只表示目录覆盖及本地参数完整性，不代表 52 家都已真实取号/打印验收。
- 中通只校验电子面单账号、打单密钥、网点编码；固定 `code=ztoOpen` 由服务端字典传入，不要求提供顺丰凭据。
- 未选承运商时不默认套用顺丰；未知公司、未列出的产品、该公司不支持的到付方式不能绕过检查启用。
- 缺账号字典、缺产品选项、仅快递方打印而不返回面单文件等情况明确提示并阻止启用。
- 模拟中通取号成功、同包裹重复点击复用、取消请求参数完整；切换为顺丰后，原中通任务取消仍发送原中通账号、网点编码及固定标识。
- 商城注册的承运商、中通取号结果、本站快递100公司编码匹配及实际 `express()` 发货分支均贯通；改成顺丰配置后，查询原中通任务仍按 `zhongtong` 匹配，不读取顺丰或快递鸟编码。
- 取消能力没有明确支持的快递不开放接口取消，并给出联系渠道处理的提示。
- 前端切换公司后清空承运商账号、产品及模板，撤销开通确认和启用；共享快递100 Key/Secret、打印机资料保留。服务端同样隔离旧公司凭据，不信任前端清空。

### 本轮修正：物流发货校验位置

此前代码检查发现面单校验误放到 `virtual()`（虚拟发货），实际 `express()`（快递发货）未经过该校验。已将校验放入实际快递分支，且在写入包裹、修改订单商品之前执行；非快递配送不能携带扩展面单参数。

新增回归直接调用真实 `CoreOrderDeliveryService::express()`，只替换数据模型与写入动作：已取消、取号待核实、取消待核实、单号不匹配、快递公司不匹配、错误发货方式及重发场景均被阻止；有效面单及原手动发货路径通过。没有真实修改商城订单或财务。

### 凭据与站点边界

- 每个站点保存自己的配置，不共用其他站点账号。
- 密钥加密保存，读取返回掩码；编辑留空保留原值。
- 原任务保留加密的原账号、收发地址快照，更换当前设置不会改变原任务。
- 跨站任务无法查看或操作。
- 无部署密钥、参数不完整、服务商能力缺失时明确阻止，不执行外部请求。

### 取号与重复操作

- 同订单同商品集合重进、重按，不产生第二次取号请求。
- 同订单重叠商品集合不能拆换选择后重复取号。
- 提供商使用原任务号及 `reorder=false`；无自动换渠道或网络重试。
- 明确失败或取消成功后才能新建独立尝试，旧记录保留。
- 超时落为待核实，不冒充取号失败。
- 恢复原申请需要显式确认、业务许可，并限制在原提交后 47 小时内；使用原账号和原编号，返回 `30011` 时恢复原任务，不新增尝试。

### 并发与发货

- MySQL 两条连接对同站点同订单锁互斥，异常后释放锁。
- 创建面单先拿锁再读取订单；等待锁期间被发货/关闭，不能继续新取号。
- 所有物流发货路径参与可选 provider 的订单锁，含手填单号和切回旧渠道后的发货。
- 取号、打印、回调都不自动修改订单发货/库存/财务状态。
- 确认交件时校验该包裹面单有效、单号及承运商一致。
- 已交件不能从任务中心绕过业务守卫取消；关闭、退款、已发货订单不能恢复取号。

### 打印、取消及回调

- 补打原单，不新取运单号；沿用原账号和打印方式。
- 打印结果待确认在冷却期内不能连点补打，超过 90 秒后仍需明确确认已检查出纸情况。
- 原单补打有时间/次数限制，超过限制不通过重新取号规避。
- 取消带原账号相关参数与承运商订单标识；未获得明确成功仍待核实。
- 回调验签、任务匹配；重复/延迟失败回调不将成功状态降级，已取消任务不被旧打印回调复活。
- 面单链接只允许快递100官方 HTTP(S) 域名，不执行原始 HTML，不接受伪造域名、脚本链接或带账号密码的链接。

### 回收与原功能

- 未安装/未授权新插件的站点继续原快递传输。
- 回收沙箱不误调正式传输。
- 回收使用原预约账号和请求结构，不读取商城面单账号。
- 多个传输处理器注册冲突时明确失败，不同时下单。
- 共享传输出错后不暗中回落再请求一遍。
- 回收原有 notice、回调和业务状态仍由原插件负责。
