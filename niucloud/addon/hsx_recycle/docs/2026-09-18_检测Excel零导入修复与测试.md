# 检测 Excel 零导入修复与测试

## 本次问题

用户返回 `done=true`，但 `templates/bindings/rows_done/skipped_exists` 全部为 0。这只能说明扫描结束，不能说明导入成功。

代码定位到：

- 检测目录的 XLSX 解析器使用无命名空间的 `children()` 和 `cell->v`，带 XML 前缀的单元格会被读空。已用真实 XLSX 文件复现并验证修复。
- 读取固定 `sheet1.xml`，没有按工作簿关系定位实际首个工作表；稀疏行号还可能导致提前结束。
- 原后台遇到零条也保存“完成”并删除上传文件；前端只判断 `done`，没有判断实际处理结果。
- “Excel 中没有可导入的质检选项”来自另一个入口：选项级别导入。原实现强制只读“级别标注”工作表，工作表被改名时会读到空表。

**还未拿到用户本次原始 Excel。上述缺陷已验证，但不能据此断言用户这份文件一定采用了带前缀的 XML。** 本地页面可见的批次也不是用户返回的批次 3。本次没有改写旧批次记录或重导业务数据。

## 使用方式与提示

| 入口 | 需要的内容 | 本次行为 |
| --- | --- | --- |
| 检测目录 → 导入 Excel | 首个工作表前六列依次为：型号、产品ID、检测项、分类、默认选项、全部选项；同型号连续排列 | 支持 XLSX、XLS、CSV；文件校验通过后才进入实际导入 |
| 选项级别 → 导入标注 | 系统导出后标注的协作表，必须有系统选项ID、选项文本、建议级别、确认状态 | 优先读取“级别标注”；改名后按必要表头定位唯一候选表；仍须预检和人工确认 |

- 两种表传错入口时，提示应该去哪里导入，不再只说“没有数据”。
- 空表、只有表头、缺少型号或检测项：明确失败。
- 后台实际处理 0 行：失败，并保留异常信息，不再返回成功完成。
- 追加模式全部已存在：合法结束，提示“已有模板，跳过，没有新增”。
- 新建模板但没有绑定型号：提示核对产品ID与本站型号字典。
- 前端保留详细错误，显示红色失败状态；最近导入新增“失败原因”，长文本可悬浮查看。
- 非完成请求游标不前进时停止循环，避免持续空转。
- 扫描进度与有效处理行数分开显示，空行不冒充导入成果。

## 数据保护边界

- 所有改动在 `hsx_recycle` 插件内，未改框架。
- 没有新增表、字段或升级 SQL；使用批次表已有的 `status/error_message` 字段。
- 覆盖模式先校验文件，再清理；同一分片的模板、绑定、字典及进度在事务中提交。
- 首片覆盖写入失败会回滚，原模板和绑定保留。
- **分批导入不是整份文件的跨请求事务。** 后续分片失败时，前面已经提交的分片不会自动撤销。本次没有扩展为全量迁移/回滚工程。
- 不按文件中的任意 ID 跨站匹配，不跳过原有的文本核对、本站归属及“已确认”校验。
