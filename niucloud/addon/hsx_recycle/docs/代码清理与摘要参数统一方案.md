## 一、设备摘要参数统一(已完成)

### 1.1 统一契约

前端提交设备时统一携带：

```jsonc
{
  "imei": "",
  "model": "苹果 iPhone 17 Pro",
  "initial_price": 0,
  "category_id": 6,
  "category_path": [1, 2, 3, 6],     // 完整分类 id 路径
  "check_template_id": 13178,        // 型号触发的质检模板
  "summary": {                        // 质检摘要：field_key => value（最多 5 个）
    "capacity": "1", "color": "1", "f18": "1",
    "warranty_info": "990", "package_type": "1"
  }
}
```

`addDevice`（添加设备）与 `order_sign`（签收）使用**同一份契约**。

### 1.2 统一存储口径

所有后端接收处统一调用新增的 `DeviceSummaryHelper`，落库口径完全一致：

- `info.goods_category` = 分类 id 路径
- `info[field_key]` = 各摘要值（平铺，供质检/列表反显）
- `info.sign_summary` = `{ field_key: value }`（反显主数据源）
- `info.check_meta.battery / battery_num` = 电池（若提供）
- 设备保留列 `capacity / color / system_version / warranty_info` 从 summary 回填
- 设备列 `check_template_id`

| `app/service/core/recycle_order/DeviceSummaryHelper.php` | 新增：统一的摘要/分类路径/info 构建助手 |

前端：`admin/src/addon/hsx_recycle/components/device-entry/`（DeviceEntryList / DeviceEntryCard / CheckSummaryDialog / useCheckMeta 等）统一发送 `summary` 映射并从 `info.sign_summary` 反显。

## 二、order/ 与 recycle_order/ 双轨重复（结论）

经路由可达性分析：

- **adminapi 路由**：63 条全部指向 `app/adminapi/controller/order/*`；`app/adminapi/controller/recycle_order/*` 被引用 **0 条** → 该套为死代码。
- **api 路由（用户端）**：使用 `app/api/controller/recycle_order/*`，**活的，保留**（与 adminapi 的 recycle_order 是不同目录）。
- **服务层**：`admin/order/*` 为 live；`admin/recycle_order/` 下 `RecycleDeviceService`、`RecycleReturnDeviceService` 被 live 的 `RecycleOrderCheckService / RecycleOrderPriceService` 引用 → **保留**。

## 三、可安全删除清单（闭环死岛，零 LIVE 引用）

```bash
cd niucloud/addon/hsx_recycle
git rm app/adminapi/controller/recycle_order/RecycleOrder.php
git rm app/adminapi/controller/recycle_order/1RecycleDevice.php
git rm app/service/admin/recycle_order/RecycleOrderService.php
git rm app/service/admin/order/RecycleOrderSignService.php
```

- `recycle_order/RecycleOrder.php`：adminapi 无路由引用。
- `recycle_order/1RecycleDevice.php`：误建垃圾文件（类名数字开头不可加载）。
- `admin/recycle_order/RecycleOrderService.php`：仅被上面死控制器引用。
- `admin/order/RecycleOrderSignService.php`：仅被上述死链引用（签收实际走 `RecycleOrderService::execute → SignHandler`）。
