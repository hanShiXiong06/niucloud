# 回收订单：PC / iPad 紧凑表格布局

## 问题与处理

原展开区在订单表格内嵌套设备表格，设备列固定宽度合计 1245px；外层区域还限制为约 52vh。iPad 上可用宽度不足时，需要横向拖表，展开内容又被内部滚动区域截断。

初版改为设备卡片后，用户反馈留白过多，希望保留 PC 表格操作。本版按此反馈改为紧凑行式布局。只调整回收插件管理端 UI，不改接口、数据库、财务及业务状态流转。

- 按列表实际宽度判断：1160px 及以上显示完整订单列；600–1159px 仍为表格，合并状态/设备进度列、将时间收进订单列。仅小于 600px 保留手机订单摘要。侧栏占用、浏览器缩放也计入判断。
- 展开设备一台一行。宽屏列为「设备型号、IMEI/SN、最终价格、当前进度、操作」；平板合并型号与串号列，保留完整串号，长内容自动换行。
- 普通设备行实测约 47px（桌面）/ 53px（平板），不再使用大卡片、并排卡片和大段留白。行高随客户串号、结算信息等实际内容增长，不裁切数据。
- 移除固定半屏高度，设备随主页面自然滚动。展开使用轻量表格，最小宽度 620px；更窄时仅设备表局部左右滚动，不撑宽整个页面。
- 紧凑订单中点击「时间」查看创建、签收、完成、打款时间；手机摘要仍复用 HsxFold，设备标题复用 HsxTitle。
- 订单与设备的「更多」均点击打开，不依赖鼠标悬停；设备触屏操作保留至少 36px 点击高度。
- 横竖屏、窄屏/表格切换共用展开状态及设备选择状态；收起不清空选择。
- 保留原有状态门槛、权限过滤和业务回调，不直接执行付款、打印或修改设备数据。

## 追加优化：当前进度只显示一个主状态

原来同一格并列「已回收 / 已确认 / 未打款」，三个维度混在一起，用户难以识别当前待办。本次使用已有 HsxTag 展示单个主状态，点击整块状态（含说明图标）查看设备、报价确认、回收打款明细和处理提示。

| 设备事实 | 表格主状态 |
| --- | --- |
| 已回收，未打款 | 待打款 |
| 已回收，部分打款（包括补差） | 待补款 |
| 已回收，回收款已结清 | 已打款 |
| 报价尚未确认 | 待客户确认 |
| 已质检尚未定价 | 待定价 |
| 已退回 / 已转代卖 | 保留对应状态，不归入待打款 |
| 已回收但打款状态缺失或无法识别 | 打款待核对，不推断为未付款 |

边界：这里仅归纳进度，不改数据库状态，不新增付款入口、不放宽付款资格；实际付款仍走原有后端校验。已打款不等于已入库/已销售。部分打款值为 2，不能按非 1 一律当成未打款。

追加验证：

- 定向编译、源码镜像一致、原 15 项设备选择回归通过。
- 18 组进度场景通过：数字/字符串状态、待付/部分付/已付、缺失/空/未知打款状态、待确认/拒绝、退回与代卖；另检查明细保留、数值优先和不修改原始设备。
- 本地已有已付款设备：只显示「已打款」，点击后明细为「已回收 / 已确认 / 已打款」。768×1024 浏览器视口下弹层可完整查看，设备行约 53px，无页面横向溢出。
- 本地暂无待打款和部分打款样本，这两类使用内存测试覆盖，没有为了 UI 验证修改付款数据。
- 本次业务代码仅更新 `RecycleOrderDeviceList.vue` 的开发源码与插件镜像；沿用已有 HsxTag 和回收状态字典，没有修改公共组件或框架。
