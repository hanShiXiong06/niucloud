# 设备桥下载与首次使用

## 员工入口

PC 回收签收 / 代客户下单的设备清单，在「读取本地设备」旁增加「安装与帮助」。

- 打开后才检测本机服务，不会一进签收页就触发本地网络授权。
- 分别提供 Windows 64 位、Mac Apple 芯片的安装包入口。
- 未配置地址时显示「待提供安装包」，不会下载旧包或跳转到虚构地址。
- 展示本机服务版本；平台发布版本更高且有对应安装包时提示更新。
- 内置连接步骤和常见问题，可选补充图文 / 视频教程链接。
- 安装完成可点击「已安装，检测连接」，连接正常后「返回并读取」。
- 手动读取失败时，在设备清单保留错误和帮助入口，不再只弹一条稍后消失的消息。

连接失败不能直接断言没有安装：未安装、未启动、浏览器拒绝本地网络访问、域名未加入白名单都可能导致失败。

## 平台统一配置

位置：SaaS admin → 系统设置 → 设备桥下载。
路径：`/admin/recycle/device-bridge`。这是平台菜单，不是站点菜单。

1. 将安装包上传到国内云盘或下载服务器；Mac 和 Windows 分别提供一个地址。
2. 填写各系统的下载地址、实际版本号，以及可选的教程地址。
3. 点击页面顶部「保存配置」。所有站点员工重新打开帮助即可读取新配置，无需逐站设置。

地址必须是完整 http(s) 链接，支持网盘分享页和文件直链；不支持站点相对路径，避免独立域名指向错误。
有提取码的网盘地址，需要在教程里提供提取码。配置接口不会验证网盘登录、提取码或实际文件内容。
版本使用 `0.2.0` 这样的数字格式。Mac 链接只对应 Apple 芯片，不向 Intel Mac 承诺可用。
不会替管理员上传文件、自动安装软件或替换客户电脑上的服务。

站点的「下单设置 → 设备与工具」只保留「安装与帮助」，不提供全局下载地址编辑。

## 配置与权限

复用框架配置存储 `sys_config`，固定在 `site_id=0` 保存 `recycle_device_bridge_downloads`：

| 配置项 | 含义 |
| --- | --- |
| `windows_url` | Windows x64 安装包地址 |
| `windows_version` | Windows 安装包版本 |
| `macos_arm64_url` | Mac Apple 芯片安装包地址 |
| `macos_arm64_version` | Mac 安装包版本 |
| `tutorial_url` | 可选图文 / 视频教程 |

这不是数据库列：**无新增表、无新增字段、无需 SQL 升级，无公共框架改动**。

平台通过 `GET/POST /adminapi/recycle/platform/device_bridge` 读取或保存，走框架登录、角色权限和操作日志。
服务层再次校验 `app_type=admin` 且 `site_id=0`，请求体传入其他 `site_id` 不会改变写入归属。
签收端通过登录后的 `GET /adminapi/recycle/device_bridge/downloads` 读取同一份平台五项下载信息。
该接口不读取企业微信 Webhook 等其他配置，不向消费者端公开。
前后端均拒绝脚本、文件、含账号密码的链接和协议相对地址。
不迁移各站点之前填写的地址；平台首次配置为空，避免把某个站点的包擅自发布给所有站点。

发布时同步更新插件 PHP、插件内 `admin` 发布副本及实际后台前端资源。
在目标环境的 `niucloud` 后端目录执行 `php think menu --addon hsx_recycle` 刷新插件菜单。
平台子管理员需要获授新增菜单和保存权限，刷新页面或重新登录后进入。
常驻 PHP / Workerman 环境按现有发布方式重启工作进程或刷新路由缓存。

本次下载配置只完成本地代码及隔离测试，未包含在设备桥发布提交中；没有对生产数据库刷新菜单或填写下载地址。

## 当前能力边界

不同操作系统的读取能力不能混为一谈：

- Mac 0.2.0 已接入三星 MTP。本地安装后的 `/v1/health` 和 `/v1/devices` 已读取到 S21，不需要 USB 调试；手机需要解锁并选择「文件传输」。
- Windows 0.2.0 目前仅支持 iPhone。Windows 安卓 WPD 读取尚未实现，不能承诺更新后就能读 S21。
- Mac MTP 可读到硬件型号、USB 序列号和部分基础信息。USB 序列号可填 SN 供人工核对，不代表必然可查保修；不推断 IMEI、电池健康度、颜色、容量等未提供数据。
- 帮助弹窗按服务返回的 `capabilities.android_mtp` 展示真实能力，不单凭版本号判断。
- 连接检测成功只表示桥服务可达，不表示已读到手机，更不表示保修查询成功。
- 读取只填入表单；签收保存和打印仍走现有业务确认流程。
- 安装包尚无 Apple Developer ID 公证和 Windows 代码签名，首次安装可能出现系统安全提示。
- 当前构建保留既有站点域名白名单和本地开发地址。平台统一下载不等于授权所有域名，其他客户域名需纳入允许列表；禁止为了省配置直接开放 `*`。

## 验证

在项目根目录执行：

```bash
php niucloud/addon/hsx_recycle/scripts/test_device_bridge_onboarding.php
node niucloud/addon/hsx_recycle/scripts/test_device_bridge_onboarding.cjs
node niucloud/addon/hsx_recycle/scripts/test_device_bridge_onboarding_browser.cjs
```

最后一项需要可解析的 Playwright 和已安装 Chrome，可通过 `NODE_PATH` 指向本机 Playwright 包目录。
浏览器脚本会启动并自动关闭临时 Vite 预览，使用真实帮助 / 配置组件，但所有下载信息和桥接口均为模拟。
不访问真实订单，不读取 USB 手机，不下载或执行安装包。

已覆盖：46 项 PHP 断言（含平台固定归属、越权拒绝、不回退站点旧地址）、危险 URL 拒绝、版本比较、发布副本一致、组件编译、未安装提示、更新提示、无效服务、白名单错误、失败重试、返回读取及桌面 / 390px 布局。
平台表单覆盖加载失败、验证阻止保存、保存失败保留输入、保存成功及离开提醒。
下单设置另通过 `scripts/test_order_submit_settings_browser.cjs` 验证六个分区和原字段保存，不会把共享地址写回站点配置。

仍需客户环境验收：网盘可下载性、GitHub 构建包在目标 Windows/Mac 的覆盖安装、自动启动、浏览器本地网络授权，以及读机后实际签收与打印。构建成功或隔离 UI 测试不能替代这些验收。
