# 预约取件通知

通知键：`hsx_recycle_pickup_update`。仅影响此预约通知，不改框架、不改变原有订单通知、不新增表和字段。

## 配置

在回收快递配置的预约通知设置中，分别填写小程序/公众号的真实模板 ID、启用开关和字段映射。
接口为 `GET/PUT hsx_recycle/pickup_notice/config`，管理端控制器为 `order/PickupNoticeConfig@info/save`，必须放在现有站点登录/权限中间件下。

保存结构：

```json
{
  "weapp": {"enabled": 0, "template_id": "", "content": []},
  "wechat": {"enabled": 0, "template_id": "", "content": []}
}
```

`content` 每项为 `label`（显示名称）、`variable`（业务变量）、`keyword`（微信真实模板中的字段编码）。变量包括 `order_no`、`state_name`、`carrier_name`、`pickup_time`、`courier_name`、`courier_phone`、`tracking_no`、`message`。字段编码必须依据当前账号已开通模板填写，不能照抄其他模板。此功能不自动申请或伪造微信模板。

开关和私有模板 ID 复用 `sys_notice`；动态字段映射复用 `sys_config` 的 `HSX_RECYCLE_PICKUP_NOTICE`，通过框架已有动态 notice 字典扩展点提供，无需修改 PHP 映射。所有配置按站点隔离。空模板/映射不可启用。小程序用户必须主动订阅且有可用次数；公众号必须关注/绑定。配置成功不等于客户已授权。

## 调用与结果

预约状态落库且业务事务提交后调用：

```php
(new CoreRecyclePickupNotifyService())->notify($siteId, $orderId, [
    'state' => 'confirmed',
    'carrier_name' => $carrierName,
    'pickup_time' => $pickupTime,
    'courier_name' => $courierName,
    'courier_phone' => $courierPhone,
    'tracking_no' => $trackingNo,
    'message' => $message,
    'attempt_id' => $stableAttemptId,
]);
```

支持 `confirmed/assigned/failed/cancelled/picked_up`。受理中状态不发“预约成功”。`attempt_id`（或 `provider_order_no`）应为本次预约稳定 ID，以便同一回收订单重新预约时区分新旧尝试。

复用 `CoreRecycleOrderNotifyService` 的本人订单详情跳转约定和 `CoreRecycleNoticeLogService` 现有日志，不改原有通知服务。会员从站点订单读取，不信任调用载荷指定收件人。每渠道独立日志；一个渠道失败不影响另一个，更不影响已保存的订单。

现有通用 `NoticeService/TemplateLoader` 未校验微信响应 `errcode`，因此本通知采用插件内的专用消息适配，复用框架 `CoreWeappService/CoreWechatService` 凭证与官方 SDK，只在返回 `errcode=0` 时记 `send_accepted=true`。`customer_read=false` 明确表示没有已读证据。未绑定、43101 未订阅、模板错误、接口异常均记录失败；网络结果未知不自动重发。

复用 `recycle_notice_log.scene` 存事件指纹，在订单行锁内创建 pending 记录，提交后才发送。相同状态、时段、承运商、快递员、运单和预约尝试 ID 的重放不重复发送；自由描述/回调时间变化不产生新通知。pending/失败记录同样阻止回调重试，避免重复消耗订阅次数；本次未提供自动重试或手动重发功能。

管理员异常消息/企业微信通知本次未实现，未改 `hsx_wecom`。可通过现有回收通知历史查此 notice_key 的失败原因；不能声称已提醒管理员。日志表不存在/写入失败时通知不发送，并写应用错误日志，不自动安装或升级数据库。

## 模拟验证

```sh
php niucloud/addon/hsx_recycle/scripts/verify_pickup_notification.php
```

测试执行真实预约通知服务、配置服务、专用消息类和回收日志服务，数据库/微信 SDK 均为替身；覆盖真实响应业务码、未授权/缺配置、多渠道独立结果、正确本人跳转、站点隔离、重入与重复回调去重。未发真实消息，真实账号模板、授权次数和手机点击仍需用户授权后的实机验收。
