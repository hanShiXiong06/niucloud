# 回收单打印、状态核对与可选条形码

日期：2026-09-28。修改范围：`hsx_recycle` 插件。

## 一、客户能看到的变化

### 1. 导出条形码由客户决定，默认不带

- 入口：设备导出列表 → 导出 → “附带 IMEI 条形码”。
- 每次打开导出窗口默认不勾选；勾选后才增加条形码图片列。
- 不勾选仍保留 IMEI、IMEI2、SN 等文字，完整串号及前导零不会丢失。
- 选中设备导出、筛选全量导出都支持这个选项。
- 不勾选不生成条码临时图片，也不要求 GD；Excel 仍需要 ZIP 扩展。
- 勾选后沿用 Code 128 图片；短串号或缺失串号不伪造完整 IMEI 条码。

### 2. 更多 → 打印回收单

- A4 纵向，浏览器原生打印，可选择普通打印机或另存 PDF。
- 内容：订单号、客户、当前状态、关键时间、每台设备型号、IMEI / SN / 自编号、当前进度、回收报价。
- 不打印长质检内容、原始数据、内部备注、付款账户。
- 从详情接口读取完整设备列表，不使用可能已被搜索条件裁剪的列表数据。
- 先显示加载窗口；弹窗被拦截或接口失败时有明确提示。
- 多页重复表头；取消打印不影响业务状态。
- 可复用入口：`hooks/useRecycleOrderPrint.ts`，样式和白名单内容在 `utils/recycleOrderPrint.ts`。

### 3. 更多 → 刷新订单状态

- 仅按设备流转的订单显示；沿用已有订单编辑权限。
- 根因：客户拒绝与付款使用了不同的父订单汇总逻辑，拒绝路径没有结合已付款事实判断完成。
- 现在客户确认/拒绝、管理端设备处理、手动核对复用同一汇总口径。
- 一台已打款、其余两台拒绝：回收订单可以完成。
- 仍有待质检、待确认、未打款或部分打款设备：不能误判全部完成。
- 已取消、已关闭、已完成及未签收订单不会被刷新重新打开或跳过签收。
- 只更新父订单进度、必要的完成时间及状态日志；不重放打款、ERP 入库或退货签收动作。
- **拒绝出售不等于实物已退回**：已有退货单继续独立处理，提示也会明确保留。此次不迁移或补建历史退货数据。
- 重复刷新不重复改变完成时间或追加同样的状态日志。

### 4. 时间列

- 普通表格时间列从 178px 调整为 220px。
- 日期时间禁止拆行，标签不被挤压；紧凑模式的创建时间同样保持一行。
- 紧凑模式的时间浮层加宽至 260px，保留既有 PC 表格操作方式。

### 更新步骤

1. 备份上述线上文件；一次性更新配套后端及前端源码，避免只传单个服务遗漏依赖。
2. 如果在服务器打包，要确认 `admin/src/addon/hsx_recycle/` 也已更新；仅上传插件源并不保证构建源自动同步。
3. 重新打包并发布 admin 静态资源；此次不需要重打客户或管理小程序。
4. 按现有部署方式重启常驻队列进程，使导出任务加载新代码；开启 OPcache 时按现有发布流程刷新 PHP 缓存。不要删除队列任务或清空业务数据。
5. 验收默认导出无条码、勾选后有条码；浏览器打印；已确认数据的混合终态订单点击“刷新订单状态”。

接口未传 `include_barcode` 的新任务默认不附带条码。已成功生成的旧导出文件不会被重写。
