# 退回统计口径修复与测试

## 结论

“退货待处理”原本表示当前待处理及退回中的设备台数，不是退回单数，也不受顶部日期筛选影响。本次改名为“退回未完成”，显示“当前全部 · 不限日期”，并提供可点击的统计说明。

旁边的“退货”改名为“已退回客户”，只统计所选日期内真正完成退回的设备。

本地站点 100000、100005 检查时没有退回单，因此不能据此认定线上具体多算或少算多少台。以下修复依据实际业务代码、内存数据回归及本地真实接口验证。

## 问题与修复

| 问题 | 修复 |
| --- | --- |
| 创建退回单时设备已被设置为退回状态，原统计会将申请中的设备当作已完成 | 完成统计同时核对当前关联退回单、设备明细均已完成 |
| 原完成统计使用设备更新时间，编辑资料可能改变统计日期 | 只使用退回单完成时间 `over_at` |
| 退回单完成时间实际为 DATETIME，而原责任分布按 Unix 秒数筛选 | 使用完整日期时间范围查询，未填写完成时间的不计入 |
| 重复关联、跨站或失效关联可能污染完成统计 | 限定同站点、同原订单和设备当前退回关联，排除删除单及孤儿数据，设备去重 |
| 责任分布“查看”直接跳转全部退回单，与数字不对应 | 与台账共用设备过滤条件，跳转对应原订单并仅展开命中的设备 |
| 一个原订单分多张退回单，数量单位容易混淆 | 台数按设备去重，单数按原回收订单去重 |

## 统计规则

- 退回未完成：当前有效退回单中待处理、退回中的设备；按台计数，不随日期变化。完成、取消及删除的退回单不计入。
- 已退回客户：当前有效退回单和设备明细均已完成，且完成时间落在所选日期内；按设备去重。
- 原回收订单因退回而关闭，不影响其有效退回设备统计。
- 这里只读现有业务事实，不修复、删除或回填历史数据，不更改退回、付款业务流程。
