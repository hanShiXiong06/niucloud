# 设备导出 IMEI 条形码：测试与更新说明

## 一、交付内容

入口：管理端「回收设备导出」`/site/device_export/list`。

- 导出选中设备或当前筛选条件下的全部设备时，固定生成 Code 128 条形码，不增加二维码/条形码选择项。
- 原有 IMEI 文本保留，在其右侧新增「IMEI 条形码」图片列，扫码内容为完整 IMEI；不是订单号、设备 ID 或后六位。
- 每台设备独占一行，条码下方也有 IMEI 文本。图片嵌入 Excel，不依赖外部图片链接或条码字体。
- IMEI、IMEI2、SN 按文本写入，保留前导零。用户输入的 `=1+1` 等内容不会作为公式执行。
- 缺失 IMEI 时显示「未填写 IMEI」；不是 15 位数字时保留原文并提示「非15位数字 IMEI，未生成条形码」。不补零、不截断，也不擅自替换成其他编号。
- 导出后进入现有「导出记录」页面下载。弹窗使用现有 HsxDialog，提交有 loading，重复点击不重复发起。
- 文件完整生成后才更新设备的导出时间。选中范围发生变化、混入其他站点设备或生成失败时，不提前标记已导出。

不改数据库、不新增依赖、不修改公共框架，不回填历史导出文件。需要重新导出才能获得新格式。

## 四、更新方式

1. 按第二节清单更新回收插件 PHP 文件，**两个新增类不能漏传**。
2. 保持插件前端源文件和 `admin/src/addon` 页面同步，按现有流程重新构建、发布 admin。不能只上传 Vue 源码期待线上已构建页面变化。
3. 不需要执行 SQL，不需要修改公共导出器，不需要 `composer update`。
4. PHP Web 运行环境需要 GD、ZIP；启用队列时，队列所用 PHP CLI 也需要这两个扩展。测试脚本额外需要 `pdo_sqlite`，生产导出不需要 SQLite。
5. 若启用了路由/应用缓存，按现有部署流程刷新缓存；若有常驻 PHP 队列，重启对应 worker 以加载新代码。不要清空业务表或队列数据。
6. 原有菜单已定义「导出设备」接口权限；若员工收到无权限提示，核对该角色是否拥有该权限。

## 五、更新后验收

1. 进入设备导出页，勾选两台有完整 IMEI 的设备，点击「导出选中」。无需选择条码类型。
2. 提交后在导出记录下载，确认只有勾选设备；每行 IMEI 右侧有条码，原有其他列仍保留。
3. 用扫码枪扫描两行条码，分别比对完整 IMEI；不是六位尾号。
4. 用未填写/不完整 IMEI 的设备验证提示，其他正常设备仍可导出。
5. 无勾选时按筛选范围导出，确认不限当前页；切回列表刷新，只有成功导出的设备更新导出状态。
6. 若记录长时间「导出中」，先检查原有队列 worker 是否运行。若显示失败，管理员检查该 `sys_export` 记录的 `fail_reason` 及对应 PHP/队列日志；现有公共导出页不展示详细失败原因，本次没有为此改动框架。
