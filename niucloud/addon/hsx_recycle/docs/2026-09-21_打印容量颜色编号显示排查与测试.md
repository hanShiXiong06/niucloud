# 打印容量、颜色显示编号：排查与测试

## 现场事实

- 打印计划接口的 `label_edit.fields` 已返回 `capacity="2"`、`color="2"`，不是前端把正确文字显示错了。
- 用户提供的质检模板是站点 100005 的模板 13170，`capacity=2` 对应 **256G**，`color=2` 对应 **银色**。该模板使用字段/选项明细表，`schema_json=null`，选项本身齐全。
- 打印计划里的 `template_binding.check_template_id=0` 是打印场景的绑定解析结果，不等同于设备表 `check_template_id=0`。
- 本地测试库没有设备 3036；本次未读取该设备的线上详情，也没有部署或修改线上数据。还需核对设备详情的 `check_template_id` 和 `info.check_meta`，才能确定该记录具体在哪个环节丢了关联。

## 本地已修复的解析缺口

1. 优先按设备已保存的质检模板查找本站字典；设备模板列为空时，读取同一设备已保存的 `info.check_meta.template_id`。
2. 容量、颜色未命中字典时，按同设备 `result_items` 保存的 value/label 对应关系补充映射；不拿不同原始值的旧标签替换当前值，不覆盖已有有效字典。
3. 导入模板省略选项 value 时，展示解析与质检表单采用相同的序号和临时 ID 规则。
4. 正式 option_value 优先于 option 主键别名，避免二者数值相同导致错误映射。

不写死“2=256G/银色”；不同模板各自解析。没有可验证映射时保留原值，不猜测设备属性。没有新增表、字段、SQL，不改框架、管理端界面或打印模板，不创建打印任务。

## 文件清单

生产逻辑只修改以下两个回收插件后端文件，应配套更新：

```text
app/service/admin/printer/RecyclePrinterTemplateService.php
app/service/core/recycle_order/DeviceSummaryHelper.php
```

均相对于 `niucloud/addon/hsx_recycle/`。不需要重打包管理端或小程序；如 PHP 开启不检查文件时间的 OPcache，发布时需按现有运维方式刷新 PHP 缓存。

使用本机 PHP 8.1.34；未执行线上 API 回归或真实纸张打印。上述测试不能代替设备 3036 的实际关联核对。

## 该设备的最终验收

核对 `/adminapi/recycle/recycle_device/3036` 的 `check_template_id`、`capacity`、`color`、`info`，不需要客户联系方式。

- 若设备关联或质检元数据明确指向 13170，重新获取打印计划应显示 256G、银色。
- 若线上仍返回编号，需确认两个配套文件均更新、PHP 进程未使用旧代码，再检查记录实际模板关联；不能仅根据打印场景的绑定结果直接改设备数据。
- 更新代码不自动重放历史打印任务。需重新打开打印弹窗、重新获取计划，旧弹窗缓存不作为验收依据。
