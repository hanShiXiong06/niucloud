# 打印容量、颜色显示编号：排查与测试

## 已确认的原因

用户补充了设备详情及质检模板 JSON，现已能复现，无需为了此问题提供生产账号。

- 设备 3036 属于站点 100005，型号节点 `category_id=22`，保存的容量、颜色均为 `"2"`。
- **设备 `check_template_id=0`，`info.check_meta` 也没有 `template_id`，`result_items=[]`，没有可供打印解析的模板编号或标签快照。**
- 质检页面的模板接口通过型号绑定找到了模板 13170，返回 `resolve.matched=true`、`source_type=model_dict`。该模板容量 `2 → 256G`，颜色 `2 → 银色`，选项明细齐全。
- 原打印代码只读取设备已存模板/标签，没有按型号绑定继续解析，因此 `label_edit.fields` 直接返回了编号。不是移动端显示组件把文字变成了编号。
- 打印场景 `custom_20260604123419_2218` 的 `template_binding.check_template_id=0` 与质检页面的默认绑定是两条路径。不能用本次打印布局模板 8 去解释质检选项，也不需要修改自定义打印场景来处理此问题。

补充检查：当前移动端质检提交代码已携带 `check_template_id` 和 `check_meta.template_id`。本次不调整保存流程，不对线上或历史记录回填；仅让读取打印计划能使用明确的型号绑定。

## 本地已修复的解析缺口

1. 优先按设备已保存的质检模板查找本站字典；设备模板列为空时，读取同一设备已保存的 `info.check_meta.template_id`。
2. 容量、颜色未命中字典时，按同设备 `result_items` 保存的 value/label 对应关系补充映射；不拿不同原始值的旧标签替换当前值，不覆盖已有有效字典。
3. 导入模板省略选项 value 时，展示解析与质检表单采用相同的序号和临时 ID 规则。
4. 正式 option_value 优先于 option 主键别名，避免二者数值相同导致错误映射。
5. **未保存模板 ID 时，读取本站明确启用的型号质检绑定（包含已开启继承的上级绑定），只补齐容量、颜色缺失的映射。** 已保存标签优先于此兜底，不修改电池等实测数值。
6. 此兜底禁用全局通用模板；未绑定、停用、模板被删除、跨站点或只有打印布局绑定时不猜测。其他业务原有的全局绑定规则不变。

不写死“2=256G/银色”；不同模板各自解析。没有可验证映射时保留原值，不猜测设备属性。只读绑定服务，不调用可能初始化默认模板的 schema 服务。没有新增表、字段、SQL，不改框架、管理端界面或打印模板，不创建打印任务。

1. 同步上述 PHP 文件，按部署方式确认 PHP 不再使用旧代码。
2. 关闭旧打印弹窗，重新扫码设备 3036，重新打开标签编辑弹窗；不点击实际打印也能验收。
3. 检查重新返回的 `/adminapi/recycle/print_scene/custom_20260604123419_2218/plan?device_id=3036&order_id=2527&biz_id=3036`：`label_edit.fields` 应为 `capacity=256G`、`color=银色`、`battery=75`。
4. 自定义打印场景的 `template_binding.check_template_id` 仍可能为 0，这是另一条绑定路径，不应据此判定容量/颜色解析失败。
5. 若仍是编号，先确认代码及 PHP 缓存，再核对本站型号 22 当前的质检模板绑定是否仍解析为 13170；不直接修改设备值、不重放打印任务。
