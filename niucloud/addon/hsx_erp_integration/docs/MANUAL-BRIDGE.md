# ERP → 集成桥 → 博远：首版操作与验收

这一版只做博远。本站 ERP 管库存、应付和已经发生的收付款；桥只记录原业务、关联博远任务、展示回执；博远插件负责资料匹配、制单和向博远发送。**把付款凭证同步到外部，不是让财务再付一次钱。**

## 店员怎么走

| 谁 | 在哪里操作 | 看到什么才算完成 |
| --- | --- | --- |
| 管理员（一次） | 在博远插件配置并验证本站账套、准备仓库、商品、供应商、人员等档案。在「ERP 集成 → 连接管理」选博远，核对测试/正式与账套，勾选采购和付款凭证，测试并启用。 | 桥复用已验证的博远连接，无需再填密钥。启用只跟踪之后发生的业务，不自动创建博远单，也不补发旧单。 |
| 录单员 | 按原回收流程确认设备并入库。在「ERP → 采购管理」打开原采购，查看该设备的外部同步记录。需要时选「关联已有原单」，在原博远采购任务核对资料并按既有流程确认发送。 | 回到原采购，可就地展开详情，点「核对原单回执」。只有单号和设备明细核实一致才显示已核实。 |
| 财务 | 在「ERP → 应付款」查看**这台设备**的应付。按既有流程完成一次付款登记；如果已有凭证，直接用原凭证。沿用博远付款任务核对原采购、金额、资金账户。 | ERP 的原单能显示**博远付款单号**。核对按钮读取原博远任务已取得的回执，不另开单、不重新付款。 |
| 财务核账 | 在同一份付款任务详情查看「原采购核销」。 | 没有核销证据：**待核对**，不显示零余额。有足够证据：显示已冲和剩余。多台设备的采购批次余额不能当成某一台的欠款。 |

同行挂账出库的入口仍是「ERP → 销售出库」，不用把机器上架商城。首版桥上的销售能力限博远测试账套，按串号核对销售回执；销售单号不等于客户已付款。

## 遇到异常怎么办

- **缺少档案或来源不匹配**：先核对这台机器、仓库、对方单位及账套，补齐关联，再处理原任务。不能拿同金额、同型号的另一张凭证替代。
- **超时、没有单号或返回结果不明确**：只核对原单，不重新发送。可在「ERP 集成 → 同步任务」找到原任务；打开详情本身不会下单。
- **暂停同步**：停止接收新业务，已存在的任务、原单号和回执仍可查询。切换账套不会把原单改投其他账套。

## 缺口怎么替换

现有付款回执只能证明付款凭证登记，不能证明归还了哪一笔应付。当前业务代码没有配置虚构的博远结算接口；模拟数据只在隔离测试进程中注入。

对接点：`hsx_boyuan/app/service/PurchaseSettlementPort.php` 的 `reader()`。拿到契约后，由博远插件把真实证据转成统一结构。桥与 PC 端已按统一结果展示，不需要在 ERP 采购页面再写博远专用判断。

可以直接向博远问：**付款单登记后，你们会自动冲抵指定采购，还是还要创建结算单？请给对应接口、权限及一组脱敏样例，能由采购单和付款单查到核销明细、已冲金额、剩余金额并识别撤销。** 如果还要创建结算单，要另外实现这一步的防重、超时查原单和撤销处理；不能只替换一个查询地址。

## 如何验证（不发真实单、不动业务库）

从项目根目录运行，PHP CLI 需有 PDO SQLite：

```sh
php niucloud/addon/hsx_erp_integration/tests/settlement-receipt-roundtrip.php --show
```

核销测试回执会写入内存测试库，再经任务详情接口读回。对照：无证据时两个金额均未知；应付 100.00、已冲 69.99 时剩余 30.01；只有已冲 100.00 且剩余 0.00 的有效证据才显示核销完成。这些均为**模拟样例**，不是博远返回的真实单据。

在测试账套做页面验收时，另用一张新采购，逐项记录同一设备的串号、本地采购单号、实际博远采购单号、本地已有付款凭证、实际博远付款单号和原采购核销状态。模拟测试通过不能代替这一项。

## 部署范围

协调更新本站 ERP 的 PC 原单展示组件、ERP 集成桥和博远插件；桥版本为 **1.1.0**。通过插件升级流程执行现有表的结构升级（连接启用时间、任务来源/去重、回执及必要字段宽度）；**不新增业务表、不回填旧单**。先备份、在测试库验证升级，再按环境发布。编译并发布 PC 管理端，刷新插件菜单与角色权限、重载常驻进程。启用人工连接前检查是否有同业务的旧自动连接，不能同时投递。此次实现不要求修改公共框架，也不会因发布代码而自动启用正式同步。
