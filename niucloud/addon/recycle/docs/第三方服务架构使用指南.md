# 第三方服务统一管理架构使用指南

## 一、架构概述

本架构提供了统一的第三方服务管理方案，支持：
- 多服务商配置与管理
- 自动主备切换
- API调用日志记录
- 费用统计与监控
- 余额告警

## 二、服务类型

系统支持以下服务类型：

| 服务类型 | 常量 | 说明 |
|---------|------|------|
| 设备查询 | `SERVICE_TYPE_DEVICE_QUERY` | 查询设备信息（如3023） |
| 快递下单 | `SERVICE_TYPE_EXPRESS_ORDER` | 创建快递订单（如安果ERP） |
| 快递查询 | `SERVICE_TYPE_EXPRESS_QUERY` | 查询快递物流信息（如阿里云） |
| 短信服务 | `SERVICE_TYPE_SMS` | 发送短信 |
| 支付网关 | `SERVICE_TYPE_PAYMENT` | 支付接口 |

### 3. 阿里云快递查询

## 四、使用方法

### 4.1 基础调用

```php
use addon\recycle\app\service\core\third_party\CoreThirdPartyService;
use addon\recycle\app\dict\third_party\ThirdPartyDict;

// 实例化服务
$service = new CoreThirdPartyService();

// 调用设备查询服务
$result = $service->call(
    100000,  // 站点ID
    ThirdPartyDict::SERVICE_TYPE_DEVICE_QUERY,  // 服务类型
    'queryByImei',  // 方法名
    ['imei' => '352000000000000']  // 参数
);

// 处理结果
if ($result['success']) {
    $data = $result['data'];
    // 处理数据
} else {
    $error = $result['message'];
    // 处理错误
}
```

## 五、配置管理

### 5.1 数据库配置

服务配置存储在 `third_party_service` 表中：

```sql
-- 查看所有配置
SELECT * FROM saas_third_party_service WHERE site_id = 100000;

-- 启用/禁用服务
UPDATE saas_third_party_service
SET status = 1  -- 1启用 0禁用
WHERE id = 1;

-- 更新优先级（数字越小优先级越高）
UPDATE saas_third_party_service
SET priority = 1
WHERE id = 1;
```

### 5.2 配置说明

| 字段 | 说明 |
|------|------|
| site_id | 站点ID |
| service_type | 服务类型 |
| provider_name | 服务商名称 |
| priority | 优先级（越小越优先，支持主备切换） |
| config | JSON配置（base_url, api_key等） |
| status | 状态（0禁用 1启用） |
| balance | 余额 |
| min_balance_alert | 最低余额告警阈值 |

## 六、主备切换机制

系统支持自动主备切换：

1. **配置多个服务商**: 为同一服务类型配置多个服务商，设置不同的优先级
2. **自动切换**: 当主服务商调用失败时，自动尝试备用服务商
3. **优先级恢复**: 下次调用时仍优先使用主服务商

示例配置：
```sql
-- 主服务商（优先级1）
INSERT INTO saas_third_party_service (site_id, service_type, provider_name, priority, status)
VALUES (100000, 'device_query', '3023', 1, 1);

-- 备用服务商（优先级2）
INSERT INTO saas_third_party_service (site_id, service_type, provider_name, priority, status)
VALUES (100000, 'device_query', 'backup_provider', 2, 1);
```

## 七、日志与监控

### 7.1 API调用日志

所有API调用都会记录在 `third_party_api_log` 表中：

```sql
-- 查看最近的调用日志
SELECT * FROM saas_third_party_api_log
WHERE site_id = 100000
ORDER BY create_at DESC
LIMIT 100;

-- 查看失败的调用
SELECT * FROM saas_third_party_api_log
WHERE site_id = 100000 AND status = 0
ORDER BY create_at DESC;

-- 统计调用次数
SELECT service_type, provider_name, COUNT(*) as total
FROM saas_third_party_api_log
WHERE site_id = 100000
GROUP BY service_type, provider_name;
```

### 7.2 费用统计

系统自动按天统计费用，存储在 `third_party_cost_stats` 表中：

```sql
-- 查看本月费用统计
SELECT * FROM saas_third_party_cost_stats
WHERE site_id = 100000
AND date >= DATE_FORMAT(NOW(), '%Y-%m-01')
ORDER BY date DESC;

-- 查看总费用
SELECT
    service_type,
    provider_name,
    SUM(total_cost) as total_cost,
    SUM(total_calls) as total_calls,
    SUM(success_calls) as success_calls
FROM saas_third_party_cost_stats
WHERE site_id = 100000
GROUP BY service_type, provider_name;
```

## 八、添加新服务商

添加新服务商只需3步：

### 步骤1: 创建Provider类

```php
<?php
namespace addon\recycle\app\service\core\third_party\provider\your_type;

use addon\recycle\app\service\core\third_party\provider\BaseProvider;
use addon\recycle\app\dict\third_party\ThirdPartyDict;

class ProviderYourService extends BaseProvider
{
    public function getName(): string
    {
        return '您的服务名称';
    }

    public function getServiceType(): string
    {
        return ThirdPartyDict::SERVICE_TYPE_XXX;
    }

    public function getProviderName(): string
    {
        return 'your_provider';
    }

    public function execute(string $method, array $params): array
    {
        // 实现具体的调用逻辑
        switch ($method) {
            case 'yourMethod':
                return $this->yourMethod($params);
            default:
                throw new \Exception("不支持的方法: {$method}");
        }
    }

    public function getBalance(): float
    {
        // 实现余额查询
        return 0.0;
    }

    public function healthCheck(): bool
    {
        // 实现健康检查
        return true;
    }

    protected function yourMethod(array $params): array
    {
        // 实现具体方法
        $url = $this->getConfig('base_url') . '/api/path';
        $response = $this->httpPost($url, $params);

        return [
            'success' => true,
            'data' => $response,
            'message' => '成功'
        ];
    }
}
```

### 步骤2: 在Dict中添加常量

```php
// app/dict/third_party/ThirdPartyDict.php

const PROVIDER_YOUR_SERVICE = 'your_provider';

const PROVIDER_TEXT = [
    // ... 其他提供商
    self::PROVIDER_YOUR_SERVICE => '您的服务名称',
];
```

### 步骤3: 在CoreThirdPartyService中注册

```php
// app/service/core/third_party/CoreThirdPartyService.php

protected function createProvider(string $serviceType, string $providerName, array $config, int $siteId): BaseProvider
{
    $className = '';

    switch ($serviceType) {
        // ... 其他服务类型
        case ThirdPartyDict::SERVICE_TYPE_YOUR_TYPE:
            if ($providerName === ThirdPartyDict::PROVIDER_YOUR_SERVICE) {
                $className = '\\addon\\recycle\\app\\service\\core\\third_party\\provider\\your_type\\ProviderYourService';
            }
            break;
    }

    // ...
}
```

完成！新服务商即可使用。

## 九、注意事项

1. **API密钥安全**: 所有API密钥存储在数据库的config字段中，建议加密存储
2. **余额监控**: 定期检查 `balance` 字段，当低于 `min_balance_alert` 时及时充值
3. **日志清理**: 定期清理 `third_party_api_log` 表，避免数据过大
4. **错误处理**: 所有调用都应该捕获异常并处理错误情况
5. **缓存策略**: 对于查询类接口，建议在业务层实现缓存机制

## 十、故障排查

### 10.1 调用失败

1. 检查服务配置是否启用
2. 检查API密钥是否正确
3. 查看 `third_party_api_log` 表中的错误信息
4. 检查网络连接和防火墙设置

### 10.2 主备切换不生效

1. 确认备用服务商的 `status` 为1（启用）
2. 确认备用服务商的 `priority` 大于主服务商
3. 检查备用服务商的配置是否正确

### 10.3 余额不更新

部分服务商不提供余额查询API，需要手动更新：

```sql
UPDATE saas_third_party_service
SET balance = 1000.00
WHERE id = 1;
```

## 十一、最佳实践

1. **统一错误处理**: 在业务层统一处理API调用的错误
2. **日志监控**: 定期查看失败日志，及时发现问题
3. **成本控制**: 定期查看费用统计，优化API调用策略
4. **测试环境**: 在测试环境配置测试服务商，避免产生不必要的费用
5. **文档维护**: 及时更新服务商的API文档和配置说明
