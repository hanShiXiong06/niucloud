# 第三方服务架构 - 业务代码集成完成

## 集成概述

已成功将新的第三方服务架构集成到现有业务代码中，保持了原有的业务逻辑，只是将API调用部分改为使用统一的架构。

## 修改的文件

### 1. DeviceQueryService.php
**位置**: `/addon/recycle/app/service/admin/device_query/DeviceQueryService.php`

**修改内容**:

#### 1.1 添加新的依赖
```php
use addon\recycle\app\service\core\third_party\CoreThirdPartyService;
use addon\recycle\app\dict\third_party\ThirdPartyDict;
```

#### 1.2 修改 `queryDevice` 方法
**原来的方式**:
- 从 DeviceQueryConfig 获取配置
- 使用 curl 直接调用 3023 API
- 手动解析响应

**新的方式**:
- 使用 CoreThirdPartyService 统一调用
- 自动支持主备切换
- 自动记录日志和费用
- 保持原有的本地缓存和结果保存逻辑

```php
// 使用新的第三方服务架构
$service = new CoreThirdPartyService();

$result = $service->call(
    ThirdPartyDict::SERVICE_TYPE_DEVICE_QUERY,
    'queryByImei',
    [
        'imei' => $queryCode,
        'api' => $api
    ],
    $siteId
);
```

#### 1.3 修改 `queryExpress` 方法
**原来的方式**:
- 从 DeviceQueryConfig 获取阿里云配置
- 使用 curl 直接调用阿里云 API

**新的方式**:
- 使用 CoreThirdPartyService 统一调用
- 自动记录日志和费用

```php
$result = $service->call(
    ThirdPartyDict::SERVICE_TYPE_EXPRESS_QUERY,
    'query',
    [
        'express_no' => $express_code,
        'mobile' => $mobile
    ],
    $this->site_id
);
```

## 保持的功能

### ✅ 本地缓存
设备查询仍然会先从 `DeviceQueryResult` 表查询本地缓存，如果有缓存直接返回。

### ✅ 结果保存
查询成功后仍然会保存到 `DeviceQueryResult` 表，供下次查询使用。

### ✅ 数据规范化
保持原有的 `normalizeDeviceData` 方法，确保返回的数据格式一致。

### ✅ 业务方法
所有原有的业务方法都保持不变：
- `getCoverage()` - 根据品牌查询保修信息
- `getActivationlock()` - 查询激活锁
- `getMdm()` - 查询MDM监管锁
- `getExpress()` - 查询快递物流

## 新增的功能

### 🎯 统一管理
所有第三方服务通过统一的 CoreThirdPartyService 调用。

### 🎯 主备切换
如果主服务商（3023）调用失败，会自动尝试备用服务商。

### 🎯 完整日志
所有API调用都会记录到 `third_party_api_log` 表：
- 请求参数
- 响应数据
- 耗时
- 费用
- 成功/失败状态

### 🎯 费用统计
自动按天统计到 `third_party_cost_stats` 表：
- 总调用次数
- 成功次数
- 失败次数
- 总费用
- 平均耗时

### 🎯 余额监控
可以查询服务商余额，支持余额告警。

## 使用示例

### 设备查询
```php
$service = new DeviceQueryService();

// 查询型号（默认）
$result = $service->queryDevice('352000000000000', 100000);

// 查询保修信息
$result = $service->queryDevice('352000000000000', 100000, '/apple/coverage');

// 查询激活锁
$result = $service->getActivationlock('352000000000000');

// 查询MDM
$result = $service->getMdm('352000000000000');
```

### 快递查询
```php
$service = new DeviceQueryService();

// 查询快递物流
$result = $service->getExpress('75******1234', '13800138000');
```

## 数据库查询

### 查看API调用日志
```sql
-- 查看最近的调用
SELECT * FROM saas_third_party_api_log
WHERE site_id = 100000
ORDER BY create_at DESC
LIMIT 20;

-- 查看失败的调用
SELECT * FROM saas_third_party_api_log
WHERE site_id = 100000 AND status = 0
ORDER BY create_at DESC;
```

### 查看费用统计
```sql
-- 查看今日统计
SELECT * FROM saas_third_party_cost_stats
WHERE site_id = 100000
AND date = CURDATE();

-- 查看本月统计
SELECT
    service_type,
    provider_name,
    SUM(total_calls) as total_calls,
    SUM(success_calls) as success_calls,
    SUM(total_cost) as total_cost
FROM saas_third_party_cost_stats
WHERE site_id = 100000
AND date >= DATE_FORMAT(NOW(), '%Y-%m-01')
GROUP BY service_type, provider_name;
```

## 兼容性说明

### ✅ 完全兼容
所有现有的业务代码调用方式保持不变，无需修改控制器或其他调用方的代码。

### ✅ 平滑过渡
新旧架构可以并存，如果需要回滚，只需恢复原来的代码即可。

### ✅ 数据独立
新架构使用独立的数据表（`third_party_*`），不影响原有的 `device_query_*` 表。
