# 手机报价接口功能需求文档

## 一、功能概述

在 recycle 插件中开发手机报价接口对接功能，该功能每天自动请求外部报价接口，将返回的数据进行二次处理和存储，并提供价格配置和查询功能。

## 二、接口信息

### 2.1 接口地址
```
GET https://dhmall.chaoniu.top/api/v1/quotation/detail
```

### 2.2 请求参数
| 参数名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| quotation_id | int | 报价单ID | 115, 114 |
| price_name | string | 价格名称（URL编码） | 花机/内爆, 靓机/小花 |
| default_price_value | int | 默认价格值 | 200 |
| default_percentage_value | int | 默认百分比值 | 3 |
| price_adjustment_type | int | 价格调整类型 | 2 |
| price_adjustment_value | int | 价格调整值 | -200 |
| quotation_background_color | string | 报价单背景色（URL编码） | linear-gradient(...) |
| quotation_text_color | string | 报价单文字颜色（URL编码） | #ffffff |

**说明：**
- 不同的 `quotation_id` 和 `price_name` 组合会返回不同的报价数据
- 示例1：`quotation_id=115&price_name=花机/内爆` - 返回花机/内爆的报价
- 示例2：`quotation_id=114&price_name=靓机/小花` - 返回靓机/小花的报价
- 系统需要支持多个报价单的配置和管理

### 2.3 请求头
| 头名称 | 说明 | 示例值 | 获取方式 |
|--------|------|--------|----------|
| Version | 版本号 | 2.2.3 | 固定值 |
| AppId | 应用ID | wxeff5f3c92ec08aff | 固定值 |
| Platform | 平台类型 | 2 | 固定值 |
| Authorization | JWT Token | eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... | 通过小程序抓包获取，需要手动更新 |
| OpenId | 用户OpenId | oOAyc7XHNqWZKsQk6AOxAQ_fydSY | 通过小程序抓包获取，需要手动更新 |

**Token管理说明：**
- Authorization Token 和 OpenId 通过小程序抓包获取
- Token 可能有时效性，需要定期更新
- 系统需要提供Token配置界面，支持手动更新
- 建议对Token进行加密存储

### 2.5 数据结构说明
- `sku` 是一个二维数组，外层数组表示不同的分组（group_key），内层数组表示同一分组下的不同型号
- 每个商品包含：
  - `goods_id`: 商品ID
  - `goods_name`: 商品名称（型号名称）
  - `general_attr`: 通用属性（如内存容量）
  - `config_attr`: 配置属性（包含价格），不同报价单的配置项不同：
    - 报价单115（花机/内爆）：`花机`、`内爆可测` 等
    - 报价单114（靓机/小花）：`全套充新 橙色`、`全套充新 白色`、`全套充新 蓝色` 等
  - `add_value_attr`: 加/扣钱项说明
  - `config_selected`: 配置项名称数组

## 三、核心功能需求

### 3.1 接口请求管理
1. **请求参数存储**
   - 需要存储每次请求的参数（quotation_id, price_name, default_price_value等）
   - 支持参数配置和修改
   - 记录请求历史

2. **定时任务**
   - 每天自动请求一次接口
   - 支持手动触发请求
   - 记录请求日志和错误信息

### 3.2 数据存储
1. **请求记录表**
   - 存储每次请求的参数、时间、状态、响应数据
   - 记录请求成功/失败状态

2. **报价数据表**
   - 存储解析后的报价数据
   - 包含：型号、容量、配置项、价格、分组信息
   - **重要：需要考虑时间维度，支持历史价格查询**

3. **报价型号表**
   - 存储报价接口返回的型号信息（goods_id, goods_name等）
   - 独立于现有的 recycle_device_model 表
   - 用于管理报价接口中的型号数据
   - **自动添加新型号**：解析接口数据时，如果发现新型号（goods_id不存在），自动添加到型号表

4. **型号自动添加功能**
   - 在解析接口返回数据时，检查每个商品的 goods_id 是否已存在于型号表中
   - 如果不存在，自动创建新的型号记录
   - 提取型号信息：goods_id, goods_name
   - 默认状态设置为启用（status=1）

### 3.3 价格配置功能
1. **配置表设计**
   - 支持精确到SKU的价格配置：型号 + 内存 + 等级（配置项）= 价格
   - 支持批量管理：型号 + 内存 = 价格（针对该型号+内存的所有配置项）
   - 支持针对特定型号的价格调整
   - 支持针对特定分组的价格调整
   - 支持价格加/减操作（有高有低）

2. **配置规则**
   - 配置类型：
     - **类型1**：按型号+内存+配置项（SKU级别，最精确）
     - **类型2**：按型号+内存（批量管理，针对该型号+内存的所有配置项）
     - **类型3**：按型号（针对该型号的所有内存和配置项）
     - **类型4**：按分组（针对分组内所有型号）
   - 调整方式：
     - 固定金额调整（+/-金额）
     - 百分比调整（+/-百分比）
     - 固定价格覆盖
   
3. **价格配置优先级规则**
   当同一个价格同时满足多个配置规则时，按以下优先级应用：
   1. **最高优先级**：型号+内存+配置项（goods_id + capacity + config_item_name）
   2. **高优先级**：型号+内存（goods_id + capacity）
   3. **中等优先级**：型号（goods_id）
   4. **最低优先级**：分组（group_key）
   
4. **批量配置功能**
   - 支持批量创建配置：选择型号+内存，批量应用到所有配置项
   - 例如：iPhone 16 Pro Max 256G 的所有配置项（花机、内爆可测等）统一+100元
   - 批量配置会创建一条 `config_type=2` 的记录
   - 如果某个SKU有单独的配置（config_type=1），则优先使用SKU配置

5. **配置冲突处理**
   - 当同时存在SKU级别配置和批量配置时，优先使用SKU级别配置
   - 例如：
     - 批量配置：iPhone 16 Pro Max 256G 所有配置项 +50元
     - SKU配置：iPhone 16 Pro Max 256G 花机 +100元
     - 结果：花机使用+100元，其他配置项使用+50元

### 3.4 缓存机制
1. **查询缓存**
   - 查询报价数据时优先使用缓存
   - 缓存key需要考虑查询条件（型号、配置项、日期等）
   - 缓存失效策略：数据更新时清除相关缓存

2. **缓存策略**
   - 当天的数据缓存时间较长
   - 历史数据缓存时间较短
   - 配置更新时清除所有相关缓存

### 3.5 数据查询
1. **报价查询**
   - 支持按型号查询
   - 支持按配置项查询
   - 支持按日期查询（历史价格）
   - 查询时应用价格配置规则

2. **价格对比标识**
   - 在返回给前端的数据中，需要标识价格对比信息
   - 对比逻辑：
     - 当前价格 = 原始价格（接口返回的价格）：显示黑色（normal，无变化）
     - 当前价格 > 原始价格：显示红色（high，高于大盘）
     - 当前价格 < 原始价格：显示绿色（low，低于大盘）
   - 标识字段：`price_status` 或 `price_compare`
   - 原始价格字段：`original_price`（接口返回的价格）
   - 当前价格字段：`final_price`（应用配置后的价格）

3. **数据统计和分析（未来扩展）**
   - 价格趋势分析
   - 型号价格对比
   - 配置项价格统计

```sql
  `id` int unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `site_id` int NOT NULL DEFAULT 0 COMMENT '站点ID',

  `price_name` varchar(100) NOT NULL DEFAULT '' COMMENT '价格名称',
  `default_price_value` int NOT NULL DEFAULT 0 COMMENT '默认价格值',
```

### 4.3 价格配置表 (recycle_quotation_price_config)
```sql
CREATE TABLE `{{prefix}}recycle_quotation_price_config` (
  `id` int unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `site_id` int NOT NULL DEFAULT 0 COMMENT '站点ID',
  `config_type` tinyint NOT NULL DEFAULT 1 COMMENT '配置类型：1-SKU级别(型号+内存+配置项)，2-批量管理(型号+内存)，3-按型号，4-按分组（使用QuotationDict::CONFIG_TYPE_*）',
  `goods_id` int NOT NULL DEFAULT 0 COMMENT '商品ID（goods_id）',
  `capacity` varchar(50) NOT NULL DEFAULT '' COMMENT '内存容量（如：256G，config_type=1或2时使用）',
  `capacity_answer_id` int NOT NULL DEFAULT 0 COMMENT '容量答案ID（从接口数据中获取）',
  `config_item_name` varchar(100) NOT NULL DEFAULT '' COMMENT '配置项名称（如：花机、内爆可测，config_type=1时使用）',
  `group_key` int NOT NULL DEFAULT 0 COMMENT '分组key（config_type=4时使用）',
  `adjustment_type` tinyint NOT NULL DEFAULT 1 COMMENT '调整方式：1-固定金额，2-百分比，3-固定价格覆盖（使用QuotationDict::ADJUSTMENT_TYPE_*）',
  `adjustment_value` decimal(10,2) NOT NULL DEFAULT 0 COMMENT '调整值（正数为加，负数为减）',
  `is_enable` tinyint(1) NOT NULL DEFAULT 1 COMMENT '是否启用：1-启用，0-禁用（使用QuotationDict::STATUS_ENABLED/DISABLED）',
  `remark` varchar(255) NOT NULL DEFAULT '' COMMENT '备注',
  `create_at` int NOT NULL DEFAULT 0 COMMENT '创建时间',
  `update_at` int NOT NULL DEFAULT 0 COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_site_id` (`site_id`),
  KEY `idx_config_type` (`config_type`),
  KEY `idx_goods_id` (`goods_id`),
  KEY `idx_capacity` (`capacity`),
  KEY `idx_group_key` (`group_key`),
  KEY `idx_goods_capacity` (`goods_id`, `capacity`),
  KEY `idx_goods_capacity_config` (`goods_id`, `capacity`, `config_item_name`)
) COMMENT='价格配置表';
```

**字段说明**：
- `config_type`：配置类型，决定配置的粒度
  - 1 = SKU级别：精确到 型号+内存+配置项
  - 2 = 批量管理：型号+内存（该型号+内存的所有配置项都应用此配置）
  - 3 = 按型号：型号（该型号的所有内存和配置项都应用此配置）
  - 4 = 按分组：分组（该分组的所有型号都应用此配置）
- `capacity`：内存容量，如 "256G"、"512G"、"1T" 等
- `capacity_answer_id`：从接口数据中获取的容量答案ID，用于精确匹配
- `config_item_name`：配置项名称，如 "花机"、"内爆可测"、"全套充新 橙色" 等

**配置示例**：
```php
// 示例1：SKU级别配置（精确到型号+内存+配置项）
[
    'config_type' => QuotationDict::CONFIG_TYPE_SKU,  // 1
    'goods_id' => 8334,  // iPhone 16 Pro Max
    'capacity' => '256G',
    'capacity_answer_id' => 9641,
    'config_item_name' => '花机',
    'adjustment_type' => QuotationDict::ADJUSTMENT_TYPE_FIXED,
    'adjustment_value' => 100,  // +100元
]

// 示例2：批量管理（型号+内存的所有配置项）
[
    'config_type' => QuotationDict::CONFIG_TYPE_MODEL_CAPACITY,  // 2
    'goods_id' => 8334,  // iPhone 16 Pro Max
    'capacity' => '256G',
    'capacity_answer_id' => 9641,
    'config_item_name' => '',  // 空，表示所有配置项
    'adjustment_type' => QuotationDict::ADJUSTMENT_TYPE_PERCENT,
    'adjustment_value' => 5,  // +5%
]

// 示例3：按型号配置
[
    'config_type' => QuotationDict::CONFIG_TYPE_MODEL,  // 3
    'goods_id' => 8334,
    'capacity' => '',
    'config_item_name' => '',
    'adjustment_type' => QuotationDict::ADJUSTMENT_TYPE_COVER,
    'adjustment_value' => 5000,  // 固定价格覆盖
]
```

**说明**：所有状态和类型字段使用数字标识，通过字典文件映射。

## 五、功能模块划分

### 5.1 Service层
1. **QuotationRequestService** - 报价请求服务
   - 发送请求到外部接口
   - 处理请求参数
   - 记录请求日志

## 六、技术要点

### 6.1 缓存策略
- 缓存key格式：`quotation_data:{site_id}:{goods_id}:{capacity}:{config_item}:{price_date}`
- 查询时优先从缓存获取
- 数据更新时清除相关缓存
- 当天数据缓存24小时，历史数据缓存1小时
- 配置更新时清除所有相关缓存（包括该SKU的所有缓存）

### 6.2 价格计算流程
1. 从接口获取基础价格（原始价格）
2. 提取SKU信息：goods_id, capacity, config_item_name
3. 查询价格配置规则，按优先级查询：
   - **首先查询**：型号+内存+配置项（goods_id + capacity + config_item_name）- SKU级别
   - **其次查询**：型号+内存（goods_id + capacity）- 批量管理
   - **再次查询**：型号（goods_id）
   - **最后查询**：分组（group_key）
4. 应用配置规则：
   - 如果找到配置，按 adjustment_type 计算：
     - 类型1（固定金额）：price = base_price + adjustment_value
     - 类型2（百分比）：price = base_price * (1 + adjustment_value / 100)
     - 类型3（固定价格覆盖）：price = adjustment_value
   - 如果多个配置同时匹配，按优先级只应用最高优先级的配置
5. 计算最终价格
6. 生成价格对比标识：
   - 对比原始价格和最终价格
   - 设置价格状态标识（normal/high/low）
7. 缓存结果

**优先级匹配示例**：
```php
// 假设有以下配置：
// 配置1：goods_id=8334, capacity='256G', config_item_name='花机', adjustment_value=+100 (SKU级别)
// 配置2：goods_id=8334, capacity='256G', config_item_name='', adjustment_value=+50 (批量管理)
// 配置3：goods_id=8334, capacity='', config_item_name='', adjustment_value=+20 (型号级别)

// 查询：goods_id=8334, capacity='256G', config_item_name='花机'
// 结果：应用配置1（SKU级别），最终价格 = 原始价格 + 100

// 查询：goods_id=8334, capacity='256G', config_item_name='内爆可测'
// 结果：应用配置2（批量管理），最终价格 = 原始价格 + 50

// 查询：goods_id=8334, capacity='512G', config_item_name='花机'
// 结果：应用配置3（型号级别），最终价格 = 原始价格 + 20
```

### 6.4 价格对比标识生成规则
1. **对比逻辑**
   ```php
   if ($final_price == $original_price) {

   } elseif ($final_price > $original_price) {
       $price_status = 'high';    // 红色显示（高于大盘）
   } else {
       $price_status = 'low';     // 绿色显示（低于大盘）
   }
   ```

   ```json
     "goods_id": 8334,
     "goods_name": "iPhone 16 Pro Max",
     "capacity": "256G",
   ```

4. 记录添加的型号数量

### 6.8 同一天多次请求的处理策略

**场景说明**：
- 用户可能一天内多次请求同一报价单（手动触发或自动请求）
- 需要保证数据的完整性和可追溯性

**处理方案（推荐方案）**：

1. **保留所有请求记录**
   - 每次请求都创建新的 `recycle_quotation_request` 记录
   - 每次请求都创建新的 `recycle_quotation_data` 记录
   - 通过 `request_id` 关联请求记录和报价数据

2. **标记当前价格（is_current字段）**
   - 第一次请求（当天）：所有数据 `is_current = 1`
   - 第二次请求（当天）：
     - 先将同一天的所有旧数据设置为 `is_current = 0`
     - 然后将新数据设置为 `is_current = 1`
   - 查询当前价格时，筛选 `is_current = 1` 的数据

3. **更新逻辑（伪代码）**：
   ```php
   // 1. 创建新的请求记录
   $requestId = $this->createRequestRecord($params);
   
   // 2. 查询当天是否已有请求
   $today = date('Y-m-d');
   $existingRequests = $this->getTodayRequests($quotationId, $priceName, $today);
   
   // 3. 如果当天已有请求，将旧数据标记为非当前
   if (!empty($existingRequests)) {
       $this->updateOldDataToNotCurrent($quotationId, $priceName, $today);
   }
   
   // 4. 解析并存储新数据，is_current = 1
   $this->saveQuotationData($requestId, $data, $isCurrent = 1);
   ```

4. **数据查询策略**：
   - **查询当前价格**：`WHERE is_current = 1 AND price_date = CURDATE()`
   - **查询历史价格**：`WHERE price_date = '2024-01-01'`（指定日期）
   - **查询所有请求记录**：按 `request_time` 倒序排列

5. **优势**：
   - ✅ 保留完整的历史数据，可追溯每次请求
   - ✅ 支持价格变化分析
   - ✅ 支持查看当天多次请求的对比
   - ✅ 不影响历史数据查询

6. **注意事项**：
   - 每次请求都存储完整数据，可能产生较多数据
   - 建议定期清理过期数据（超过保留期的历史数据）
   - 查询时明确区分"当前价格"和"历史价格"

**数据库操作示例**：
```sql
-- 第一次请求（上午10:00）
-- request_id = 1, price_date = '2024-01-15', is_current = 1

-- 第二次请求（下午15:00）
-- 1. 先将旧数据标记为非当前
UPDATE recycle_quotation_data 
SET is_current = 0 
WHERE quotation_id = 115 
  AND price_name = '花机/内爆' 
  AND price_date = '2024-01-15' 
  AND is_current = 1;

-- 2. 插入新数据，is_current = 1
-- request_id = 2, price_date = '2024-01-15', is_current = 1
```

**查询示例**：
```php

    ['quotation_id', '=', 115],
```

1. **功能说明**

   - 用于前端展示价格相对于大盘价格的对比情况

2. **实现方式**
   - 在查询报价数据时，对比原始价格和最终价格
   - 计算价格差异和差异百分比
   - 生成价格状态标识（normal/high/low）
   - 在返回数据中包含这些字段

3. **数据字段**
   - `original_price`: 原始价格（接口返回的价格）
   - `final_price`: 最终价格（应用配置后的价格）
   - `price_status`: 价格状态（normal/high/low）
   - `price_difference`: 价格差值（可选）
   - `price_diff_percent`: 价格差异百分比（可选）

4. **前端展示规则**
   - `normal`（黑色）：价格与大盘一致
   - `high`（红色）：价格高于大盘
   - `low`（绿色）：价格低于大盘
