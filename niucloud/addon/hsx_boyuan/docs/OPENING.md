# 期初建账：从博远准备本站 ERP 基础资料

适用场景：开始使用一个站点，博远已有商品、仓库和客户供应商，希望在本站 ERP 里直接选用，不导入历史欠款、库存或银行余额。

## 日常维护：改分类只改一处

站点接入博远后，**商品分类在博远 ERP 维护**。新增分类、改名、移动上级或删除时，先在博远保存，再打开本站 PC「ERP → 商品资料 → 商品分类」，点击「同步最新分类」。浏览目录、搜索和刷新页面只读本站数据，不会触发同步。暂停采购或销售投递不影响查阅与同步分类。

页面显示「同步完成」才代表本轮已经取全；若有「完整性待核对」，会显示具体原因。分类没取全时保留上次已有的数据；确认取全后，本轮不再返回的分类不再出现在当前目录。历史业务单和已建型号不会被删除。「本站已建型号」可查建档时的记录；已关联博远分类编号的型号在新业务中按最新分类取值。只同步分类不会建型号、制单或改变库存。

没有接入博远的站点仍在本站维护商品目录。只读员工请有同步权限的同事代为同步，不需要给员工增删改权限。

## 店长怎么操作

1. **先核对账套。** 确认是当前站点及目标博远公司；由有权限的管理员保存连接并完成只读账套核验。无需开启采购、付款或自动投递来下载档案。
2. **一类一类取回。** 电脑：ERP → 期初建账 → 从博远同步基础资料，或博远对接 → 期初建账。手机：博远对接 → 期初建账 → 挂账常用。两端都在需要的那行点「取回此项」，每次仅取一类。公司门店、仓库、客户供应商、商品型号、业务人员优先；其余在「其他资料」。可以离开再回来看进度。即使五类全取回，也不代表具体设备、制单人或仓库已匹配。
3. **核对要建立的主档。** 在电脑端选择要建入 ERP 的资料类型，点「预览建档结果」。核对当前站点、仓库用途、往来身份和同名冲突。已有正确关联的保留；明确冲突的交由管理员核实，不按同名自动合并。预览不写 ERP。
4. **确认后再验收。** 有权限的管理员点「确认建入 ERP（…条）」，在确认窗点「确认建档」，等待结果页显示本次新增数量。分别进入本站 ERP 商品目录、仓库及往来单位查看结果，验证采购可选用对应资料。只需检查资料，不必实际开单。模拟数据不能建入真实 ERP；本站有任何未结或状态不明的应收、应付都会被拦下。不要为了开通入口而删流水或清零。
5. **需要发单时，单独开启手动同步。** 已连接的测试站点，具备权限的管理员可在电脑页首展开「手动同步设置」，核对账套编号后开启。店员在 ERP 采购单或同行挂账销售单核对配置带出的关联，缺哪项才补哪项，再提交并查看博远回执。上面取回档案或建档都不会自动开这个开关。暂停投递后可查原单结果，也不会因此开放手工新建仓库、库位。

电脑清单中的「其他资料」默认收起：商品仅有分类或品牌编号、缺少名称时，取回对应分类、品牌，重新预览；如果源商品本身缺少必需的分类信息，先核对原档。收银方式和资金账户用于后续收付款，会员按需取回，均不要求在挂账前全部取齐。「业务人员」是博远制单/经办档案，不是本站员工登录账号。

## 哪些信息会同步

| 读取的博远档案 | 在本站的用途 |
| --- | --- |
| 商品型号、分类、品牌 | 符合条件的型号可建入本站 ERP 商品目录；分类和品牌用于产品归类。不按名称猜分类、合并不同来源的商品，也不在库存中添加实物。 |
| 仓库 | 每个本次新建的仓库自带一个「默认库位」（编码 `DEFAULT`），录入设备可直接选用。它是本站 ERP 的库位，不是博远库位，不会写回博远。仓库由本次经办人负责，待核实，默认禁止直售、调拨，也不会变为本站默认仓。 |
| 客户供应商 | 按博远明确标记建立 ERP 往来单位；同一档案的两种业务身份不应生成两笔欠款。 |
| 公司门店、业务人员、会员、收银方式、资金账户 | 可下载、查阅博远档案；本次不批量开员工账号、合并会员、创建银行账户或导入流水和余额。 |

**档案取回**、**已建立 ERP 主档**、**已发生业务**是三个不同结果。资料同步不创建采购单、销售单、应收或应付。也不自动更新店员后来修改过的 ERP 商品名、仓库设置或往来单位。

仓库和默认库位同时建成；任一保存失败，本批不生效。再次同步不会重复生成库位，也不会给已有仓库补建、改名或替换原有库位。在启用博远仓库统一管理的站点，请通过上述同步流程新增仓库，不要在 ERP 手工新增仓库或库位。

## 遇到提示

- **正在读取 / 等待重试**：让现有任务继续，页面可关闭，后台计划任务仍需正常运行。同类任务未完成时不要另外创建。
- **读取中断**：有重试权限的员工可从失败分页继续；之前已成功的其他类别不必重跑。
- **数量待核对**：远端报告的总数与实际收到的唯一档案数有差异，本轮不算完整。联系博远核实该类资料后再重同步本类；不要删档案或手工补数字来消除提示。
- **没有操作按钮**：先确认在正确的站点和账套。员工可能只有查看权限；档案下载、继续失败任务、预览和确认建账是独立操作。需要时联系管理员，不必授予整套财务权限。
- **预览过期、建档中断或回执不明**：预览超过一小时、资料发生变化或账款状态改变时，不会按旧预览继续写。已经完成的批次保留。保持原站点和账套，重新检查、预览当前结果，核对哪些已建、哪些未建。不要另换站点再次导入。

## 开发与运维交付

- 这是已有 ERP 和博远插件（本仓库 1.2.0 基线）的源码增量，目标博远版本 1.2.1。不是新站首次安装包，不包含密钥、数据库、真实业务记录或上一轮付款业务安装包。
- 先在预发布源码副本上比对、备份并合并；不要整目录覆盖其他插件改动。先更新插件的后端和前端源码，也要更新实际参与编译的 `admin/src/addon`、`site-uniapp/src/addon` 镜像。ERP 插件期初页增加可选扩展入口，未安装/无授权时不显示，不修改公共框架。
- 按 NiuCloud 正常流程升级博远插件、刷新站点菜单和权限并重新登录。升级刷新菜单，**不会自动执行期初建账**，无需新增表、字段或手工执行 SQL。
- 权限按岗位分配：查看进度、搜索档案、同步、重试、查看建档条件、预览和确认建档。确认除了博远权限，还需要 ERP「确认期初入账」权限；本次操作并不调用财务入账接口。默认不扩权。库连接、业务开关、原队列和定时调度保持原配置；按现有运维流程重载 PHP 常驻进程。
- PC 在 `admin` 目录按匹配的锁文件构建：`npm run build:compile`。移动管理端如发布微信小程序，在 `site-uniapp` 目录执行既有 `npm run build:mp-weixin` 流程，验证体验版后再发布。构建不等于上线。
- 发版前检查：新站实际角色能发现入口；只读人员不能确认建账；切账套需要重新读取；中断和缺数不显示成功；模拟预览不能写主档；同一页重复确认不重复建同一档；已存在的正常数据不被覆盖；成功后在 ERP 能选到记录但并无新增应收、应付、库存或资金流水。
- 回退时先停止新确认、记下已建批次，再恢复上一套插件源码与两端静态版本；不要卸载插件、清库或自动反向删除正常主档。代码回退不会自动撤销人工已确认的建档。
