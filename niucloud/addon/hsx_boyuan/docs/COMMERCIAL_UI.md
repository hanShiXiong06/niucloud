# 博远采购与付款同步｜更新、验收、回滚

这是一份 **已有项目的源码补丁**，不是插件首次安装包，也不是已经发布的管理端。业务从 ERP 的采购入库开始。采购员同步采购，财务处理本站应付并同步已确认的付款。博远付款回执一致后，该笔付款经办结束，不用再点一次核销。

## 安装前，先确认三件事

1. **版本与入口。** 项目已有博远插件 **1.2.0**、其采购同步菜单、权限、计划任务及六张原有业务表；兼容的 ERP 采购详情已提供 `HsxErpPurchaseActions` 入口，并可记录采购应付、结算分配及已确认付款。移动管理端已有 `/addon/hsx_boyuan/pages/workbench/index` 分包。未满足时，先按正常流程安装/升级对应基础版本，不能把本补丁当安装包。包清单的基线提交可用于源码比对。
2. **账号与运行环境。** 沿用项目的 PHP 8.0 运行时、依赖锁文件及现有 PHP 队列、分钟计划任务。测试账套应已核验，基础资料、公司与账户对应已建立。保留原连接和权限；不要因换 UI 重建账套、覆盖凭据或打开自动模式。付款登记只允许指定的独立测试账套，正式环境不因此开放；此包不包含资金支付能力。
3. **明确谁能操作。** 采购员应能查看、处理采购同步。账户与收付款仅对有相应财务权限的人员开放；登记还要求 ERP 的应付付款确认权限。不同角色的页面不同。管理员检查权限即可，不要给所有人开通财务权限。

## 发布：先离线准备，再切换

以下命令在**独立发布目录/构建机**执行，不在正在提供服务的线上目录直接解压。先核对交付人提供的 ZIP 校验值；将 ZIP、外部清单和本说明放在同一目录，Linux 可运行 `sha256sum -c SOURCE-SHA256SUMS.txt`，macOS 使用 `shasum -a 256 -c SOURCE-SHA256SUMS.txt`。解压到空目录，包中 `payload/` 按仓库根目录组织，`checks/` 仅供开发机回归。

1. 在解压目录运行 `python3 verify_release.py`，校验清单内所有文件。可用 `python3 verify_release.py --target /path/to/project` 只读检查目标代码基线、前置入口及同名文件冲突。失败时按列出的文件比对，保留本地修改，不要强制覆盖。校验器不会连接服务，也不会修改文件、数据库或配置。
2. 留存原发布版本的后端源码、PC 静态资源及手机端上一可用版本；记下原有开关状态和在途任务号。先暂停外部投递、避免受理新提交，让执行中的任务稳定并核对回执，再切换代码。不能用重启打断远端写请求。
3. 在完整的目标源码副本上按相对路径合入 `payload/`，**不要删除目录中未列出的文件**。同时更新博远后端、插件自带的两套页面，以及实际参与构建的 `admin/src/addon/hsx_boyuan` 和 `site-uniapp/src/addon/hsx_boyuan`。此补丁不含数据库脚本、框架改动、运行配置或密钥；不需要执行 SQL，不重新安装/卸载插件。合入后用 `python3 verify_release.py --target /path/to/project --installed` 对照补丁校验源码；已主动合并本地差异的文件需人工复核。
4. 在匹配锁文件的项目构建环境中，PC 执行 `cd admin && npm run build:compile`（只构建、不发布，产物为 `admin/dist/`）；微信移动管理端执行 `cd site-uniapp && npm run build:mp-weixin`（产物为 `site-uniapp/dist/build/mp-weixin/`）。两条命令分别从仓库根目录起步。在后台/手机切换前，一起验证对应后端版本。微信构建成功不等于上传、提审或发布。使用 H5 的站点请按原 H5 发布流程更新；其发布脚本会写入管理端静态目录，不要在未经备份的线上目录试跑。
5. 通过既有发布流程发布带新路由、服务和任务类的后端、PC 资源以及对应移动版本。按站点运维流程刷新需要的路由/事件/OPcache 缓存，平滑重载 PHP 队列和计划任务，确认工作台运行心跳更新。先保持暂停做只读验收；需写入时由有权限的负责人仅对已明确授权的账套启用。此次没有要求切换生产接口。

## 业务验收：看结果，不只看按钮

| 场景 | 验收标准 |
| --- | --- |
| 新采购入库 | PC 从采购单、手机从采购单或博远工作台进入同一批次。先核对公司、供应商、设备和仓库；保存对应不外发，明确提交后才排队。批次切换不会串单。 |
| 采购结果 | 取得博远采购单号不等于完成核验；核对原采购明细与入库串号后显示结果。需要了解当前在库时再查，库存核验不会重复入库，也不会阻断下一步处理应付。 |
| 采购挂账 | 有权限的财务能从本批待付金额找到 ERP 应付。登记本站实际付款后，只同步这笔财务已经确认的付款，不再扣款。普通采购员、未付款、未开通或不可操作时不能提交付款登记。 |
| 同步付款 | 核对本笔金额、公司、供应商、账户及制单人；保存核对不发送。允许登记且确有需要时才二次确认。若缺少博远应付/核销证据，测试登记还须逐笔明确同意。回执匹配后可看到本笔金额和博远付款单号，点“完成”即可。 |
| 分次付款或异常 | 一笔完成不表示整单付清。若超时、待核对或读失败，只查原任务和原单，不新建付款、不要求重复打款。回执不证明银行到账或博远已按采购明细核销；不把未取得的余额当成 0。 |

在桌面浏览器和手机真机各验收一次；手机可先用体验版。只有部署、真实岗位权限、队列处理和账套回执都吻合，才认定该环境交付完成。纯界面预览不代替这一步。

开发机可将 `checks/` 中的文件按相对路径置入独立的已合入补丁的源码副本。双端依赖已安装时，可在项目根目录运行 `node niucloud/addon/hsx_boyuan/tests/payment_ui.cjs` 与同目录的 `commercial_handoff.cjs`、`pc_purchase_ui.cjs`、`mobile_purchase_ui.cjs`、`workbench_inventory_link.cjs`；另有 PHP 纯模拟脚本 `purchase-sync.php`、`payment-gateway.php`、`inventory-gateway.php`。这些检查不需要真实账套或客户数据，不向网站发布脚本。

## 回滚

- 先暂停投递并记录在途任务、来源单号和已取得的博远单号。对结果不明的请求应先查原单；不要让旧任务处理器接管新版本创建的库存或付款任务，也不要用重建订单来恢复。
- 保留完整当前版本用于查询与恢复。确认没有未处理的新版任务后，按原发布记录成组恢复 PHP 插件源码、PC 静态版本及手机端上一可用版本，再平滑重载常驻进程。无法同时回退手机已发布版本时，先维持兼容后端和暂停状态，待客户端切换。
- 不删任务、映射、财务记录，也不复制或替换运行密钥。**代码回滚不会撤销博远已经建立的采购或付款单。** 需要更正账务时，由财务按原单核对处置；如需查询错误，只查现有框架 Log。
