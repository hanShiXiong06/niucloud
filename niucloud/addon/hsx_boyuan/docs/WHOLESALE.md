# 采购入库到挂账批发出库

适用范围：本站 ERP 的自有、一机一串号设备，采购入库后在原仓按「同行 / 挂账」销售。不需要重新创建博远客户、商品或仓库。本版销售同步只允许已核验的博远测试连接；零售、现结、跨仓、代卖和自动冲销不走这个出口。

**如果机器来自回收，不要再开一张采购单。** 店长先按[期初建账](OPENING.md)准备资料，并确认本站的新回收设备由 ERP 接管。店员只需走以下流程：

1. **在回收单定价。** 核对这台机器的串号、最终定价员、成交价和入库仓位。客户接受买断报价后，在 ERP 查这台机器的原采购、库存和应付。没有查到时回到原设备看入库结果，先排除仓位或接管设置问题，不手工补第二台设备。
2. **在原采购单核对博远。** 核对带出的公司、供应商、人员、仓库和商品，缺什么补什么。第一次手动选博远商品；有完整规格证据时可记住，下台同站同账套同规格的设备再用。缺销售版本、规格不一致或外档失效时仍需核对。只对本单例外，不勾「记住对应」。这不会改写回收型号库。提交后核对博远采购单号及对应串号。
3. **销售时选原设备。** 已上架商城的设备从手机商城收银台选买家、串号、「同行销售」「挂账」，实际交付时开单；收银结果可直达 ERP 原销售单。也可沿用原生 ERP 同行出库，但同一笔销售只选一个入口。原单上核对并提交博远，结果未明只查原单。门店零售和现结仍在本站办理，不走博远挂账批发接口。

**出库和收款是两张不同的单据。** 同行在 ERP「销售出库」开单，不要求上架商城。实际到账后，财务在本站应收款里登记一次。若本站已登记，不再点击收款。

在已核验的博远 UAT 手动收款连接下，打开 ERP 销售原单，点「同步已有收款凭证」。核对本站凭证号、金额、博远原销售单及资金账户，缺资料才补选；确认后仅登记一张博远收款凭证，不动本站资金。原单可查博远收款单号，暂停连接后仍可查。若响应超时或不匹配，仅核对原凭证，不能重新发送。

**「已登记」不是「已核销」。** 本站剩余应收取自本站账；博远创建收款单的回执不含指定原销售单的核销分摊。在取得关联到这两张博远单据的核销证据前，原单始终显示「待核对」。运营日志走 PHP Log，原单关联及回执保存在已有业务表中。

开发环境复验回收来源：在项目根目录执行 `sh niucloud/addon/hsx_boyuan/tests/run-local-cycle.sh --recycle-origin`。此用例从客户接受报价开始，检查重复确认、一机一入库、应付、同行销售、应收、回收原设备回写「已售」，以及暂停时原单还能看回执。使用新建后删除的本地隔离库和合成博远回执；不要把测试输出里的博远样本单号当作 UAT 实单号。

| 经办动作 | 完成后在哪里看 |
| --- | --- |

| 核对博远采购单并提交，再核对原采购明细、串号。 | 采购核对页显示原博远单号。只有已核验的采购行才能用于本流程；有需要可再查「本批次当前在库」。 |

| 财务在真正收付后，分别在本站 ERP 登记供应商付款、客户收款。 | 看对应应付、应收的已结金额和余额。仅同步出库不能代替客户收款，本站核销也不表示远端自动核销或已银行转账。 |

**没有准备按钮：** 先看是否已有核对记录；已有记录始终打开原任务，不另建。新任务只接受当前账套启用后有唯一原始确认事件、已完成、未收款的同行挂账出库，且每台自有设备都能回到同一账套已核验的采购行。看不到时也应核对权限、连接是否暂停。仅打开或刷新详情不创建任务；不支持补造历史出库。

**异常怎么处理：** 原单结果未知只允许查询，不能再点提交。博远查询只能找到候选单而没有原始串号回执时，不算成功。原销售撤销或退货后，要人工核对两边原单，系统不会再发一单或自动冲销。手动测试模式可在核对页只处理这笔单，无须启动全站队列；其他队列模式仍需后台工作进程。

**提交结果不明时如何联系客服：** 打开出库核对详情，复制这次提交使用的「博远手工单号」，连同业务日期、原销售单号、出库设备串号提供给博远，要求查快速批发 WSA（含草稿、未审核单），回告博远单号、原商品行 ID 和对应串号。手工单号是查询线索，不是博远出库单号。文档 v1.5.4 §4.2.13 的批发查询按日期分页，手工单号是可空返回字段，不支持把手工号或 IMEI 当查询参数。当前行没有手工号时，不用同日、同客户、同价或相同设备推定是本次订单。候选只作人工查证；没有匹配、接口未提供关联依据或读取失败都不表示未出单，均不得重提。

**如果提示「创建人不能为空」：** 先看是本站提交前提示，还是博远返回的错误。前者在销售核对页选好制单人再提交；后者若没有返回博远销售单号，请按完整串号、手工单号和业务日期在博远批发界面核对，查询范围要包含草稿、未审核单。手工单号不是防重凭证；不要新建第二张本地销售单或重新挂一次应收。

**如何在本机复验：** 在项目根目录执行 `sh niucloud/addon/hsx_boyuan/tests/run-local-cycle.sh`。脚本使用本机 PHP 8 和 MySQL，在随机隔离库调用项目真实的 ERP、任务和财务服务，禁用外部请求，并在结束时删除隔离库。追加 `--evidence` 可更新 `deliverables/boyuan-local-cycle-20261118` 下的 HTML 与 JSON 验收快照；上游响应来自本地样本，不是博远 UAT 或生产回执。

**版本和数据：** 本次链路涉及回收、ERP、手机商城、博远四个插件和对应的 PC 插件源码镜像。没有公共框架改动，没有为对接新增表或字段，也不补录旧销售或修改已有账款。技术日志只走框架 Log；单据关联和核对结果使用已有业务表。

**旧商城升级前置：** 如果从 ERP 上架提示「商品修改日志表未初始化」，先检查商城原有的 `price_changed_at` 字段及商品变更记录表。缺失时应先备份数据库，按当前库的实际表前缀执行商城自带的 `phone_shop/sql/upgrade_goods_change_log.sql`。这是商城原有升级，不是博远同步日志。已安装博远的站点若缺菜单，按插件升级流程刷新；首次安装仍走框架标准安装流程。
