# 电脑后台：基础资料

| 要做什么 | 入口 | 是否会写业务数据 |
| --- | --- | --- |
| 找公司、客户、商品、仓库等 | 博远对接 → 基础资料 | 否，默认只读取本站档案 |
| 看单条完整字段 | 点蓝色档案名称 → 抽屉内搜索字段 | 只读；旧档案仅存摘要时，有权限者可主动向博远核对 |
| 下载一类资料、建入本站 ERP | 博远对接 → 期初建账 | 下载只更新插件档案；预览并确认建账才建立本站主档 |
| 配置 URL、公司代码、AppID、AppSecret | 博远对接 → 连接设置 | 仅修改本站连接；不会发单 |

左侧按业务分四组。客户与供应商用同一往来单位档案；能同时拥有两个身份，无需重复建档。搜索接受名称、编码、档案 ID；约定电话支持输入完整号码精确查找。点名称可在侧边查看全部可展示字段，包括空值、零值和未收录的新字段。原字段名按需展开。关闭详情仍停在原列表；换账户、换类别、离开页面会清除明文电话。

**商品分类怎么找：** 默认只显示一级分类。有下级才显示展开箭头，点击分类名称查看原档。输入名称、编码、ID 或用 `/` 分隔的路径，也可以按一级、二级等筛选。结果显示完整路径；点「定位到层级」即可展开到该分类。浏览按一级分类分页，同一分支不会被拆开；同级按分类编码排列。

父子关系只认本账套的博远分类 ID，不按名称、名称里的标点或编号长度猜层级。缺上级或循环的记录可从「层级待核对」查看，仍能打开原档。需要平铺对比时可切回「明细列表」；超过 2,000 条时使用完整分页列表，不把截断的数据画成树。打开页面读取已保存的档案，不要求重新同步，不改数据库结构。

## 1.3.0 升级交付

- 新增十张专表：公司、仓库、员工、往来单位、会员、商品、分类、品牌、结算方式和资金账户（前缀为系统表前缀 + `hsx_boyuan_md_`）。每类以站点 + 连接 + 博远 ID 唯一；常用角色、归属、型号是可索引的存储生成列，扩展字段和加密展示快照保留在各自的档案表。没有新增日志表或修改 ERP 业务表。
- 准备数据库备份；MySQL 须支持 JSON 函数和 STORED 生成列，并具备建表、改表名权限。安排维护窗口，停旧版本的博远资料同步进程，避免新旧代码并行写入。升级只拆分已经同步的档案，不向博远拉取或做账。
- 更新 `hsx_components` 0.1.1 和博远插件 1.3.0，执行插件升级钩子并重编管理端。升级程序每批最多 1,000 条，核对数量和逐行内容后才同时发布新表；映射用的博远编号和档案记录 ID 保留。已有资产、单据、应收应付和任务不改。新菜单必须同时有查看同步进度和搜索档案的权限，既有角色不自动提权。
- 中断时保持维护窗口，检查错误后重跑升级；冻结表 `hsx_boyuan_reference_v123` 以及暂存表不能手工删。若新版本已产生档案更新，单独恢复旧表并不等于回滚；需要按备份与维护窗口处理。不要在一键重试时重发采购/销售。
- 查看目录只查本站。客户与供应商的约定手机号在列表和详情按助记码原样显示，点击即可复制；旧版本未存原值时需重新读取该类档案。只有主动核对缺失的历史原档才会读博远。列表不传出整份快照；暂停采购、销售投递不删除已存资料。
- 桌面样式参考 Ant Design 的数据展示和 Drawer 交互，不引入 React 依赖。目录导航是无业务依赖的 `HsxCatalogLayout`；表格、分页、搜索、状态标签、侧栏沿用 HSX 公共组件。核心框架和移动端均不需改动。
