# hsx_lead 移动端设计规范

> 适用范围：`niucloud/addon/hsx_lead/uni-app/` 下所有页面、组件和样式（微信小程序、H5）。
> 所有 agent（Claude、Codex 及其他）和开发者修改移动端代码时**必须遵守**。根目录 `AGENTS.md` 引用本文件。
> 令牌文件：`uni-app/styles/tokens.scss`。检查脚本：`tools/format/lint-mobile-ui.mjs`。
> 版本：2026-11-27 首版。修改本规范需用户确认，并同步更新令牌文件和检查脚本。

## 0. 设计原则

1. **可靠优先**：涉及付款、退款、接单的界面，宁可多一步确认，也不让用户误操作或误解结果。
2. **一眼看懂**：每个视图只有一个最重要的动作和一个最重要的信息（通常是状态或金额）。
3. **克制**：默认用更安静的样式。颜色只用来表达状态和主操作，不用来装饰。
4. **跟随站点**：主色来自站点主题（`--primary-color`），不写死品牌色；不覆盖框架全局样式。

方法借鉴 CDS（open-claude-ui 技能）的分层方式；外观保持本站蓝色主题与 NiuCloud / uview-plus。**不使用** CDS 的陶土色和温润低对比外观。

## 1. 令牌：唯一的样式来源

在组件样式顶部引入，路径按组件位置调整：

```scss
<style scoped lang="scss">
@import '../../styles/tokens.scss';
.order-card { @include hsx-card; color: $hsx-text-primary; }
</style>
```

| 类别 | 令牌 | 用途 |
| :--- | :--- | :--- |
| 表面 | `$hsx-surface-page` / `-card` / `-sunken` / `-overlay` | 页面底色 / 卡片 / 卡片内次级区块 / 弹层 |
| 文字 | `$hsx-text-primary` / `-secondary` / `-muted` / `-disabled` / `-on-fill` | 正文标题 / 辅助说明 / **仅元数据** / 禁用 / 实心底上的字 |
| 主色 | `$hsx-accent` / `-soft` / `-text` | 主操作、链接、选中态；跟随站点主题 |
| 语义色 | `$hsx-{success,warning,danger}` 及 `-soft` / `-text` / `-border` | 状态，见 §4 |
| 边框 | `$hsx-border` / `$hsx-border-strong` | 分隔线、卡片描边 / 次要按钮、输入框 |
| 阴影 | `$hsx-shadow-overlay` / `$hsx-shadow-float` | 只给弹层 / 悬浮元素；普通卡片不用阴影 |
| 字号 | `$hsx-font-caption`(12) / `body-sm`(13) / `body`(14) / `title-sm`(15) / `title`(17) / `display`(24) | 见 §3 |
| 间距 | `$hsx-space-1…6` = 4 / 8 / 12 / 16 / 20 / 24 | 页面左右边距和卡片内边距用 16 |
| 圆角 | `$hsx-radius-sm`(6) / `md`(8) / `lg`(12) / `pill` | 标签 / 按钮输入框 / 卡片弹层 / 胶囊 |
| 尺寸 | `$hsx-tap-min`(44) / `$hsx-control-h`(44) | 点击区、控件高度 |

**硬规则**

- **禁止在组件里写裸 hex 颜色**（`#xxxxxx`、`rgb()` 字面量）。需要新颜色时，先在 `tokens.scss` 加令牌，并在本文件登记用途。
- 不要用 `opacity` 弱化文字；用 `$hsx-text-secondary` / `$hsx-text-muted`。
- `$hsx-text-muted` 只给时间、编号、占位符这类元数据；需要用户阅读理解的句子用 `$hsx-text-secondary`。
- 主色只通过 `$hsx-accent*` 使用，不再写 `var(--primary-color, #3478cc)` 这类各自不同的兜底值。

**例外（可保留自有颜色，但不得扩散到其他组件）**

- 装修（DIY）组件：颜色、字号来自管理员配置的 `--lead-diy-*` 变量，继续使用。
- 会员等级卡面、徽章皮肤（`membership-skin` / `membership-visual`）：由等级外观配置驱动。
- 邀请海报：会被保存成图片，排版固定。

## 2. 布局

- 页面左右边距 16px；卡片内边距 16px；卡片之间 12px；区块之间 24px。
- 卡片用 `@include hsx-card`：白底 + 12px 圆角，**不加阴影、不加描边**。卡片内部的按钮和标签不再加描边（单描边原则）。
- 分隔线用 `1px solid $hsx-border`。不用 0.5px：部分安卓机会显示不出来。
- 同屏最多两层浮层（底部面板 + 一个确认弹窗）。需要第三层时，改为跳转页面。
- 适配最窄 320px、常用 375 / 390px 宽度；底部操作区要留出安全区（`env(safe-area-inset-bottom)`）。

## 3. 文字

| 档位 | 令牌 | 用于 |
| :--- | :--- | :--- |
| 24px | `$hsx-font-display` | 金额、关键数字（配合 `@include hsx-number`） |
| 17px | `$hsx-font-title` | 页面、面板标题 |
| 15px | `$hsx-font-title-sm` | 卡片标题、列表主文字 |
| 14px | `$hsx-font-body` | 正文、表单、主按钮 |
| 13px | `$hsx-font-body-sm` | 次要正文、次要按钮 |
| 12px | `$hsx-font-caption` | 元数据、标签、辅助说明 |

- **最小字号 12px。** 例外仅限数字角标、等级徽章内文字、海报。
- 字重只用 400 / 500 / 600。
- 金额、计数、倒计时用 `@include hsx-number`（等宽数字），避免跳动。

## 4. 状态与颜色语义

| 语义 | 令牌 | 用于 |
| :--- | :--- | :--- |
| 主色 accent | `$hsx-accent*` | 主操作、链接、选中、进行中 |
| 成功 success | `$hsx-success*` | 已完成、已到账、已接单、已支付 |
| 警告 warning | `$hsx-warning*` | 待处理、即将超时、待人工核对、待支付 |
| 危险 danger | `$hsx-danger*` | 失败、拒绝、删除、已超时 |
| 中性 neutral | `$hsx-neutral-*` | 已关闭、已过期、已取消 |

- 状态标签用 `@include hsx-status-tag(<tone>)`；页面内的说明或错误用 `@include hsx-notice-bar(<tone>)`。
- **颜色不能是唯一的信息载体**：状态必须同时有文字（如"待支付"），不能只靠颜色区分。

## 5. 按钮与交互

- **每个视图最多一个主按钮**（`@include hsx-button-primary`）。其余用次要按钮（`hsx-button-secondary`，默认档）或文字按钮（`hsx-button-text`）。
- **任何可点击元素的点击区域不小于 44×44px。**
  - 首选：元素本身做到 44px（按钮、列表行、筛选标签）。
  - 视觉上需要更小时：用 `@include hsx-tap-target`（伪元素扩大热区）。
  - **禁止用负外边距扩大点击区域**。在紧凑布局里，扩大的区域会盖住相邻按钮（2026-11-27 收益页实测：点"线索收益"打开了"全部状态"，点账户说明进入了提现）。
  - 相邻两个可点击元素的热区不能重叠。间距不足时，加大间距或把元素做大。
- 涉及资金的操作（付款、取消付款单、申请或撤回退款、提现）必须二次确认，确认框写清金额和后果。
- 提交中：按钮显示加载态并禁用，防止重复提交；页面其他会改变同一数据的按钮同时禁用。
- 交互反馈动效用 `$hsx-duration-fast` / `$hsx-duration` 和 `$hsx-ease-out`，不写 `transition: all`。

## 6. 加载、空状态、错误

- 每个异步区域都要有四种状态：加载中、有数据、空数据（说明为什么空，并给出下一步动作）、失败（说明原因，提供"重试"）。
- 列表用 `z-paging`。**操作后不要在本地删除或插入列表项来"刷新"**：列表按页码分页，本地增删会让下一页跳过或重复数据（2026-11-27 订单页实测：41 笔取消 1 笔后，翻页只能看到 39 笔）。
  - 同一条数据仍属于当前筛选时：原地替换这一项。
  - 数据离开当前筛选，或被另一条数据取代时：整页重载。
- 切换账号或站点、页面隐藏后返回：丢弃旧请求的结果，不显示其他身份的数据。

## 7. 反馈与文案

- 轻提示统一用 `coopNotice()`（`uni-app/utils/notice.ts`），不要直接调用 `uni.showToast` 显示动态文字。
  - 28 个字以内：toast。
  - 超过 28 个字：页面上已经显示了全文时，toast 只给一句短提示；否则用弹窗显示全文。微信的 toast 超过两行会被截断，关键的"请勿重复付款"常常在句尾。
- 文案写给门店老板看，不是写给开发看：
  - 一句话只说一件事，先说结果，再说下一步。✅"付款已确认，无需再付" ❌"服务商已受理，不代表用户已查看或终端已送达"
  - 不出现内部术语：受理、回执、快照、渠道、幂等、核验。
  - 不确定的结果要明确告诉用户"不要做什么"（如"请勿重复付款"），这一点比措辞简短更重要。
- 详细原因放在"查看明细"或展开区，不堆在卡片正面。

## 8. 无障碍

- 图标按钮必须有 `aria-label`；状态变化区域用 `role="status"`，错误用 `role="alert"`。
- 正文与背景的对比度不低于 4.5:1。`$hsx-text-muted` 约 3.9:1，所以只用于元数据。

## 9. 迁移策略（存量代码）

现有代码有大量裸 hex（约 600 种颜色）和不统一的字号，**不要求一次性改完**：

1. **改到哪里，规范到哪里**：修改某个组件时，你新增或改动的样式必须符合本规范。同一组件里与你的改动无关的旧样式，可以不动。
2. **批量迁移要单独立项**：参照 Q1 格式化的做法，分批提交，每批都要截图对比（375 / 390 两档宽度）、跑构建和测试，不和业务改动混在同一个提交里。
3. 检查脚本默认只检查相对 `origin/main` 新增或改动的行，所以存量代码不会阻塞提交。

## 10. 提交前自检

- [ ] `node niucloud/addon/hsx_lead/tools/format/lint-mobile-ui.mjs` 没有报错（检查新增行中的裸 hex、小于 12px 的字号、`transition: all`、直接调用 `showToast` 显示动态文字、按钮负外边距）。
- [ ] 每个视图最多一个主按钮；可点击区域 ≥ 44px，相邻热区不重叠。
- [ ] 375 / 390 宽度下没有文字溢出、截断或按钮挤压。
- [ ] 异步区域有加载、空、失败三种状态。
- [ ] 小程序构建、WXSS 编译和插件测试通过。
