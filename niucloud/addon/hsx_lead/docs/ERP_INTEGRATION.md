# ERP 接入与自动同步

适用：`hsx_lead 0.0.1`。ERP 是只读货盘来源，不是本插件的交易或付款系统。仅接入商户有权使用的账号和门店，不能借用其他商户授权；上游接口或认证方式发生变化时应停止并重新核验，不盲目试探或绕过验证。

## 1. 商户自行接入

入口：手机端“我的门店 → ERP 连接与采集进度”。平台有权限的人员也可在“合作商户 → 接入管理”协助。

1. 选择本站已开启的渠道，填写商户自己的登录资料。商户端以账号密码或正常验证为主，不要求商户复制临时 Token。
2. 按上游要求完成验证码或来源公司选择；核对只读预览的 ERP、公司/门店和读取范围。
3. 明确确认“接入并开启自动同步”。授权、启用周期和创建首次任务分别展示结果；部分成功时按界面继续，不重复授权。
4. 等待全部分页成功发布。首屏预览、登录成功、保存周期均不等于完成全量同步。
5. 后续在进度和日志中查看最后成功时间、任务阶段及失败原因。

密码和 Token 使用原连接密文字段保存，不向手机下发、不回显、不写普通日志。部署人员必须保留原 `app.auth_key`。仅有 Token 的连接无法反推出密码，需商户一次性补齐账号密码并验证。

## 2. 已接入渠道

| 渠道 | 正常授权 | 后台密码续登 | 读取边界 |
| --- | --- | --- | --- |
| 万机管家 | 账号密码，核对来源身份 | 支持 | 按适配器核验的门店范围读取库存 |
| 搜机客 | 账号密码，核对认证店铺 | 支持 | 逐行校验来源店铺及状态，不把全部商品当成在售 |
| 机小二 | 账号密码、会话及门店身份 | 支持 | 上架型号、上架串号和当前库存精确交集 |
| 爱管机 | 密码和图片验证码，必要时选择公司 | 不支持仅凭密码无人值守续登 | 只发布符合上架范围的设备；未上架字段可解析但不进入在售匹配 |
| JKB（默认展示K平台） | 手机号及主动获取的短信验证码 | 不支持；会话到期后用户重新验证 | 仅同步状态1的已上架库存，有货才参与匹配；状态5在库未上架暂不纳入 |

JKB 的手机号授权、分页台数与记录数区别、状态限制及替换文件详见 [JKB接入说明](JKB_INTEGRATION.md)。

爱管机的单次自动图片识别，不等于后台永久续登。短信、滑块、账号风控、额外确认或来源公司变化时停止，提示商户正常重新验证。

机小二解析认证身份需要 PHP DOM/XML 扩展。接口的 `0`、空值、待核实、在库与在售不是一个含义；适配器只采用已核验的明确状态，不用采购成本替代售价，不把平台图标当成产品照片。

## 3. 自动执行与恢复

管理员需在牛云计划任务中启用“商户ERP库存只读同步”（键 `hsx_lead_inventory_sync`），并确保项目调度进程正常运行。计划按分钟扫描到期连接，商户默认同步周期为 60 分钟，按界面可调整。

- 授权缺失、已过期，或渠道没有可靠到期时间且开始新一轮同步时，支持续登的渠道使用已保存资料正常登录。
- 登录成功后再次核对原来源店铺，再保存新授权。库存网络失败不应丢弃已经验证的新授权。
- 分页中明确授权失效时，重新登录一次并重试原失败页，不从头重复创建采集任务。
- 全部分页成功才发布新一代完整快照；失败保留上次完整结果并明确标注时间，不发布半批数据。
- 密码错误、限流、来源变化或额外验证时停止并退避，不每分钟重复试密码。
- 更换账号、关闭渠道或配置版本变化后，旧任务不能覆盖新授权、发布旧范围库存。

### 同步失败与重新登录提醒

所有 ERP 渠道使用同一套失败提示，手机“ERP 库存同步”和后台商户列表可查看原因及处理入口：

- 登录失效、密码错误或需要重新验证时，提示重新登录；JKB 需由用户主动获取短信验证码，不会因打开页面、刷新状态或定时同步自动发短信。
- 支持密码续登的渠道仍先按原规则自动尝试；最终失败后才提示人工处理，不能把正常续登过程当作失败。
- 网络异常或请求限流提示稍后重新同步，不误报成登录失效；来源数据结构、接口配置等问题提示联系平台核对。
- 提醒只取当前连接、当前配置对应的同步结果；重新验证及新一轮同步后不会继续用历史失败提示。渠道暂停优先显示暂停。
- 同步失败不覆盖上一批完整库存，最近成功时间仍可查看。本次为页面内提醒，不新增微信、短信等主动推送。

不需要额外建立守护脚本或把密码写在计划命令中。具体进程启动方式使用本项目原有部署命令，不把队列启动等同于计划任务已经启用。

## 4. 渠道开关

入口：“客资协作 → 业务配置 → ERP 登录渠道”。每个站点独立管理，可全部关闭。

关闭同时限制新授权、重新授权、验证码登录、手动采集和自动采集；已有连接显示暂停。账号密文、原自动同步开关、任务进度和历史库存保留，联系资料仍可维护。

已发送的外部请求无法撤回，但关闭后返回的在途结果不应写新 Token 或发布新库存。短暂停可以继续原任务；暂存分页超过安全窗口时重新完整采集，不能把旧页拼成今天的新库存。重新开启按商户原开关恢复，不替商户自动打开其自行关闭的同步。

关闭 ERP 渠道不等于设备已售，也不停止已有协作单处理。过期快照是否可用仍按库存有效期判断。

## 5. 可选图片验证码识别

默认关闭。爱管机普通图片验证码可由操作者手动输入，或由站点管理员在“合作商户 → 接入管理 → 自动登录设置”配置已获授权的 2Captcha 图片识别服务。

1. 管理员自行取得该服务的 32 位十六进制 API Key，确认费用及第三方处理规则，填写本站密钥。
2. 设置每日提交次数上限，明确勾选第三方识别同意后保存。默认上限 20 次；它是尝试次数，不是金额或成功次数。
3. 已保存密钥只显示遮罩；留空保留，输入新值替换；清除时须明确选择清除并关闭。
4. 查询余额是独立只读动作，不创建识别任务。保存配置不自动充值、不登录 ERP。
5. 操作者选择自动识别后只发起一次，按进度等待；页面中断优先恢复原请求，不重复创建可能收费的任务。

识别服务仅接收验证码图片及识别所需参数，不接收 ERP 密码、Token、客户或库存；图片可能由第三方人工处理，必须事先取得合法授权。识别按服务商规则可能计费，失败或取消不保证退款，也不返还本站已预留次数。次数按中国时间自然日累计，刷新或清缓存不重置。

采用异步查询结果，不需要公网验证码回调地址。当前仅处理支持的普通图片验证码，不处理或绕过短信、滑块、风控及锁定。余额不足、密码错误或额外校验时停止，不自动加钱、提额或无限试码。

## 6. 库存可信度与扩展

同步采用来源唯一标识及范围校验，保留安全白名单快照，不保存原始登录响应、客户对象或内部成本备注。新增 ERP 应实现插件的适配器契约、授权身份校验、分页和状态规范，不在框架硬编码来源。

默认匹配只使用符合在售规则、未过期的快照。诊断中扩大查询范围不代表把待核实、下架或未知状态提升为可售。完整同步后已不在在售范围的设备退出匹配，但这不证明一定已售，也可能是下架或转移。

库存是采集时刻的参考，不提供源 ERP 事务快照、实时数量、锁货或最终成交保证。门店接受线索前仍须核实货源和交付能力。
