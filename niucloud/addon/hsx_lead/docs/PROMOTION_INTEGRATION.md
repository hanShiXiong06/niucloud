# 一级推广真实接线与验收

本轮从本地原型转为真实牛云插件接口。原型的合成会员、合成收益、模拟支付与模拟提现不是正式业务实现，不随真实端接入。

## 数据变更（必须先安装后端）

新增 **1 张表**：`{{prefix}}hsx_lead_promotion_reward`，已加入 `sql/install.sql` 与相同内容的根目录 `install.sql`。

- 用途：固定已付款业务、直属上级、计佣来源、金额/比例/期限快照，保存待结算、已入账和人工核对状态；`site_id + coop_order_id` 唯一，防止重复奖励。
- 不新增钱包、提现表，不修改会员表字段。关系复用框架 `member.pid`；前端分享参数仍用 `mid`。
- 推广规则、服务商资格、插件明确确认的绑定时间使用框架 `sys_config`。
- 本轮不迁移/回填旧单，不改已有会员上级。执行安装 SQL 只补缺表，不清空历史数据。覆盖代码不等于执行了建表，已有安装需由框架升级入口执行该安装文件，或按实际表前缀执行其中新增表的 `CREATE TABLE IF NOT EXISTS` 段。

## 管理员如何启用

1. 在站点菜单“客资协作 → 推广管理”进入；委派工作人员还需全站数据权限和对应读写权限。入口、读取规则、改规则、读服务商、改资格、读奖励、结算、暂停奖励分别授权。
2. 在推广规则中开启总开关。默认关闭；发单权益、靠谱认证、平台维护费三项也默认关闭，分别设置比例。
3. 开通服务商：选择本站有效会员，设置负责城市与操作说明。服务商不必先创建商户门店。
4. 设置等待天数和获佣期限；0 个获佣月表示长期有效。发单权益/认证可选择仅首次或包含续费；维护费按每笔符合条件的成交付佣计算。
5. 客户明确确认邀请关系后，只能首次绑定；已有 `member.pid` 不覆盖，禁止自己邀请自己、循环和跨站绑定。分享 `mid` 只是待确认入口，读取页面不写关系。
6. 真实付款核对完成后生成奖励。管理员可结算已到期奖励；也可在框架计划任务启用“商户一级推广奖励到期结算”。**该任务新安装默认关闭**，与库存采集任务分开。记入会员佣金不是提现打款。

## 金额与业务规则

- `publishing`：基数为发单权益实际付款。
- `certification`：基数为靠谱认证实际付款。
- `maintenance`：基数仅为平台维护费 `fee_amount`，不是客户买机器的成交额，也不是承接商户支付的整笔协作佣金。
- 金额使用整数分，推广比例向下取到完整分。以 50 元协作佣金为例，平台维护费 9.90，发布方仍为 40.10；若维护费推广比例为 20%，推广奖励为 1.98，不扣减发布方 40.10。
- 付款事实核对的是框架 `pay`：站点、付款会员、业务类型/ID、流水、金额与已完成状态必须全部匹配。业务订单和奖励在同一事务中确认；迟到收款需要人工处理的原单不自动发推广奖励。
- 修改比例/停用来源/停用服务商只影响以后符合条件的新付款，既有已固定的奖励不改价。仅一级上级，不向上继续分配。
- 框架注册已有的上级关系继续保留；若没有本插件明确确认的绑定时间，有限获佣期限以该会员注册时间为保守起点，不虚构新的绑定日期。

## 退款、异常与提现边界

- 结算前重新核对原支付；存在待退款、退款中或成功退款凭据时，奖励暂停，不能入账。
- 监听框架 `RefundSuccess`：未入账奖励转为暂停；已入账奖励保留已入账事实，同时标记待人工追偿。**不会假称已追回，也不会直接改余额或自动从银行卡扣回**。即便只有部分退款，也先暂停/转人工核对，不擅自按未知退款业务比例重算。
- 本插件没有替代原业务的退款发起入口；退款原单及已提走奖励需平台按框架财务流程核对处理。
- 账户失效/精度容量不足会暂停奖励并留下原因；调用失败会回滚该笔奖励的账本与状态，不留下“已结算却没入账”。
- 人工核对后可“恢复结算”：只接受尚未入账的暂停奖励，须填原因，并再次核对原业务/支付、退款是否取消、账户状态与容量。恢复只改回待结算，保留原金额/比例/上级/到期时间，不立即付款；下次结算批次才记账。已入账或仍有待退款/退款中/成功退款的记录不能恢复。
- 收益与提现共用框架会员佣金账户、流水、冻结、审核与实际打款页面。推广概览中账户余额是整个框架佣金账户，不冒充仅推广余额；推广累计/待结算另列。

## 接口契约

接口均返回框架 `{code,msg,data}`。金额为元字符串；时间为 Unix 秒；分页为 `{data,total,per_page,current_page}`。身份来自登录上下文，不接受客户端指定当前会员或站点。

会员 `/api/hsx_lead/promotion`：

- `GET overview`：总开关、本人、服务商资格、原邀请人、直属团队数量、推广金额统计、框架佣金账户、规则与分享路径。
- `GET team`：直属会员分页、已登记门店/地区/进度；不暴露其客户、ERP 凭据、完整电话或余额。
- `GET rewards`：仅当前会员获佣记录，可按状态、来源、时间、关键词检索。
- `GET rules`；`GET invitation?mid=...`（只读）；`POST bind {mid,confirm:true}`（首次明确确认）。

管理员 `/adminapi/hsx_lead/promotion`：

- `GET/PUT config`：真实配置读写。
- `GET providers`、`PUT providers/:id`：按会员 ID 管理资格；支持关键词和 `enabled=1/0`，分页前筛选。
- `GET rewards`：跨服务商核对，支持来源、状态、会员、业务单号关键词及产生时间。
- `POST settle {limit:50}`：结算到期批次，返回整数 `{processed,settled,held}`；只记框架佣金，不提现。
- `POST rewards/:id/hold {reason}`：暂停待入账；对已入账记录只标核对，不伪装扣回。
- `POST rewards/:id/resume {reason}`：有独立恢复权限，核对通过的未入账暂停奖励回到待结算；不重算历史规则，不重复加钱。
