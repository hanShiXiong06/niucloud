## 用户接入/验收顺序

1. 更新插件后端；先补新增奖励记录表，再导入菜单/权限/计划任务。不要直接用旧演示小程序包验证真实接口。
2. 通过框架同步插件 `admin/uni-app` 源码及页面注册，重新编译前端。没有手改共享 `pages.json`。
3. 在“客资协作 → 业务配置”确认原业务，在“推广管理”设置规则并开通服务商；按需要开启推广到期结算计划。
4. 以真实测试会员走一遍首次入驻、邀请确认、双方交付、成单付佣、奖励到期结算、框架提现；真实付款和实际打款需要用户授权及验收，当前报告不宣称完成。
5. 验证已有上级不覆盖、重复回调不重复到账、未付款不记收益、退费/争议按财务核对，不把未知结果显示为成功。

## 历史移动样式隔离专项

本轮修复微信小程序的组件样式归属：原发布、付佣、门店资料、收益、详情与 ERP 连接依赖工作台父组件的 `:deep()`，H5 可以显示，但小程序自身没有对应样式。修复前实际产物 `CoopPublishForm.wxss` 与 `CoopCommissionForm.wxss` 都是 0 字节；源样式回归失败 11 项，真实产物检查也失败。

- 公共规则抽成插件内按需 Sass mixin，由实际使用者本地 `scoped` 引入。工作台仅保留自身布局，默认插槽和 footer 插槽的样式保留在各自调用方。
- 不给组件开启全局 `shared`，不向 App、框架、`hsx_components` 或 uview 内部注入业务样式。第三方按钮的布局使用插件原生容器负责。
- 按当前 uni-app 自动注入主题样式的构建方式使用 `@import`；不用必须出现在所有规则之前的 `@use`，不升级依赖。
- 浏览器走查发现发单权益按钮挤压价格，已为两种购买区统一设置原生容器宽度，价格保持单行。
- 框架底栏内部双占位仍撑高文档，改为插件外层保留实际高度、内层零高 fixed 挂载；不裁切底栏，不覆盖框架内部选择器。浏览器复测占位溢出从 101px 回到实际 51px，四个导航入口均可点击。预览本身的 18px 合成数据标识留白与生产插件无关。
- 21 个移动组件的业务 script 区块逐个 SHA-256 与本轮修改前比较，均未变化。仅四个模板增加布局容器，其余业务逻辑、API 和数据库保持不变。
