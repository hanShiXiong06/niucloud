# 主子站基础资料同步

## 操作入口

站点后台：二手商城 → 站点商品自动跟随 → 基础资料。
子站入口按钮为“基础资料同步”；主站可在对应子站行打开。

页面地址为 `/site/phone_shop/agent`。如果整个入口或同步按钮缺失，确认已更新 `app/dict/menu/site.php`；在后端 `niucloud/` 目录执行框架命令 `php think menu:refresh --addon phone_shop` 刷新插件菜单，然后重新登录。普通员工还需在角色中授权该页面及查看主站配置、基础资料查看、同步开始、同步批次和修改设置等所需权限。菜单刷新与发布前端是两个步骤，仅更新 Vue 文件不会注册菜单。已刷新并核对本地菜单，未直接刷新生产菜单或修改员工授权。

例如主站 100005、子站 100294：先建立或确认跟随关系，打开基础资料，选择同步方式，保存，再执行一次手动同步检查结果。本次开发没有直接配置这两个真实站点。

- 仅手动：不接收基础资料变更推送，不执行周期同步。
- 定时同步：每 15/30 分钟、1/3/6/12 小时或每天同步一次。
- 实时跟随：主站新增或编辑分类、品牌、参数、规格分组、规格值、成色等级时推送变更；商品分类关联通过队列校准。
- “自动新增并关联缺失分类”开启后，找不到可复用分类时自动创建；有多个候选或人工忽略时仍要求人工处理。
- 新建关系默认开启自动补建；已有关系新增字段默认关闭，不自动替用户改变旧设置。需要时保存开启。

商品同步保持原有自动跟随能力，基础资料设置不停止商品上下架和价格同步。商品同步为了保证引用有效，仍会按需解析/补齐所依赖的资料；这里设置的是独立的基础资料维护同步，不是冻结商品引用的开关。

## 已确认的分类规则

1. 已建立映射的分类跟随主站改名、父级、展示状态和排序，即使它原来是子站自建分类。保留子站分类 ID，不删掉重建。
2. 未关联的本地分类不覆盖、不删除。若它位于已关联分类下面，父级名称/层级变化时只刷新派生的完整路径与层级，不改它的名称或直接父级。
3. 缺失上级优先创建/关联，再处理下级。相同名称存在歧义、被人工忽略、层级成环时不猜测，不随意绑定。
4. 主站分类移动时修正主站商品的祖先分类集合；同步到子站时，将主站分类 ID 转换成子站 ID，并更新已有代理商品的分类关联。
5. 独立的基础资料同步不改代理商品价格、库存、售卖状态，不改子站自营商品。映射分类本身改名后，使用该分类的页面会展示新名称。
6. 规格组可绑定多个分类，所有分类 ID 都转换为子站 ID；组未关联成功时不写入失去分组的规格值。
7. 本次不做主站删除后自动删除子站分类/资料，不清理历史重复资料，不迁移历史订单。失效或冲突关系交由分类映射页处理。

## 进度与异常

手动执行每批最多 30 条。关闭抽屉或浏览器后，当前请求可能仍完成，后续批次暂停；再次进入可“继续同步”。已经处理的批次不会重复累计。

同步结果分为已完成、部分完成、未完成。单条失败继续后续记录，最多展示 20 条原因。修正映射后可以重新同步，稳定映射和来源公共键防止重复创建。

进度保存在数据库，不依赖本地缓存。定时任务使用相同执行器，同一关系同时只能有一个有效批次；30 分钟无进度的旧任务可被新批次接管，旧令牌不能继续写入。

## 数据库变更

复用 `phone_shop_agent` 关系表，新增 9 个字段和 1 个索引，没有新增业务表：

| 字段 | 类型/默认值 | 用途 |
| --- | --- | --- |
| ref_sync_mode | varchar(16), realtime | manual / interval / realtime |
| ref_sync_interval | int, 60 | 周期，分钟 |
| ref_auto_create_category | tinyint, 0 | 自动新增缺失分类 |
| ref_sync_next_time | int, 0 | 下次执行时间戳 |
| ref_sync_last_time | int, 0 | 最近结束时间戳 |
| ref_sync_status | varchar(20), idle | 最近批次状态 |
| ref_sync_token | varchar(32), 空串 | 批次令牌 |
| ref_sync_started_at | int, 0 | 最近执行心跳 |
| ref_sync_result | text, NULL | 当前进度、计数和失败样例 |

索引 `idx_ref_sync_due(master_site_id,status,ref_sync_mode,ref_sync_next_time)`。

独立 SQL：`sql/upgrade_agent_reference_sync.sql`。先选中正确数据库，将 `{{prefix}}` 替换为实际前缀后执行；支持重复执行，不更新业务数据。不要通过重新安装或执行卸载 SQL 升级。

## 发布步骤

1. 备份数据库和当前插件代码，更新 `niucloud/addon/phone_shop` 中本次改动及 `admin/src/addon/phone_shop` 前端文件。插件内 `admin/` 已同步发布副本。
2. 在后端 `niucloud` 根目录执行下列明确的升级命令：

```sh
php addon/phone_shop/scripts/upgrade_agent_reference_sync.php --apply
```

它仅补齐相关插件表结构、刷新 phone_shop 菜单和登记计划任务，不运行插件全量历史数据迁移。它与独立 SQL 可以重复执行；只执行 SQL 仍需刷新插件菜单并登记计划任务。

3. 重新加载现有队列与计划任务进程。分钟扫描任务 key 为 `phone_shop_agent_reference_sync`。需要框架原有计划任务调度及队列正常运行，不需要额外系统 cron。
4. 按项目现有方式发布 PC 前端，重新登录刷新菜单权限。普通角色需授权站点跟随页面及其“查看基础资料、手动同步、执行批次、修改设置”等相关按钮；站点隔离另由服务端验证。
5. 在关系设置中选择方式、开启缺失分类自动创建，手动同步并检查各项结果，再观察定时任务的下次执行和完成时间。

注意：当前根仓库 `.gitignore` 忽略了 `niucloud/addon/phone_shop/`。普通 `git diff` 或只提交根仓库的前端文件不会包含这些后端改动；应通过现有插件发布渠道一并交付。本次未改忽略规则，未提交 Git，未部署生产。
