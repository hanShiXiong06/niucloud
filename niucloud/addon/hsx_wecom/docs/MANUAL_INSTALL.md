# 企业微信通知接入与上线

完整的前置条件、角色分工、逐步操作及客户验收，请使用：

**[企业微信服务商接入操作指南](企业微信服务商接入操作指南.md)**

直接覆盖代码、不使用框架升级的部署方式，请使用 **[手动覆盖升级说明](手动覆盖升级说明.md)**，按说明执行增量 SQL 和运行配置检查。

## 准确入口

- 平台端：系统设置 → 企业微信服务商，`/admin/setting/hsx-wecom/provider`。
- 客户站点：企业微信 → 协同配置，`/site/hsx_wecom/config`。
- 客户站点页签：接入与通知、接收员工、消息日志。

## 最短实施顺序

1. 平台负责人核实服务商资格，在官方后台创建标准第三方应用，准备本套 SaaS 的后台管理小程序。
2. 技术人员完成插件安装／升级，配置通道、指令回调及授权回调，验证 SuiteTicket，检查队列和计划任务。
3. 甲方 SaaS 站点管理员发起“一键授权企业微信”，甲方企业微信管理员确认授权自己的企业，设置应用可见范围。
4. 甲方站点管理员准备员工账号、生成专属绑定码；员工用手机企业微信扫码，管理员核实本人后确认绑定。
5. 发送测试通知验证管理首页，再用一笔受控测试业务验证正确的工单入口和操作权限。

## 不要遗漏的边界

- 当前使用标准第三方应用 / Suite，不是代开发模板；注册服务商账号不等于应用已可正式授权。
- 同一套 SaaS 的客户共用域名和平台通道，各站点分别授权自己的企业，不用为每位客户新建域名或 Suite。
- 员工扫码只登记候选身份，管理员核对确认后才生效；二维码或链接不能公开发群、不能代扫。
- 绑定员工只解决通知身份，不等于管理小程序免登录；普通员工不需要企业微信配置权限。
- 事件回调需接收 SuiteTicket 和授权指令，不能只配置消息数据回调。完整地址及员工 OAuth 回调见操作指南。
- 安装／升级涉及已有插件表及字段索引的创建／补齐，使用实际数据库前缀；上传 PHP 不等于数据库已升级，不要删除旧授权数据。
- 两套独立 SaaS 建议配置独立 Suite；当前没有跨部署的统一回调中转，不要互相覆盖同一 Suite 的回调地址。
- 测试通知即时发送并打开管理首页，不证明业务队列或具体订单跳转正常。
- 普通消息失败累计尝试 5 次后停止自动重试；手动重试会真的重新投递消息。
- 消息日志的发送成功不等于员工已读。必须由甲方员工在手机企业微信实际收到并进入正确业务，才能确认闭环。

已有自建应用可继续使用“自建应用（高级）”，无需因为新增服务商模式就清空旧配置或统一迁移。
