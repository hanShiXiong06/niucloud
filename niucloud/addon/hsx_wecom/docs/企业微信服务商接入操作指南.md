# 企业微信服务商接入操作指南

适用范围：本项目 `hsx_wecom` 插件的标准第三方应用模式。核对日期：2026-09-29。

本文随 2026-09-29 接入引导及扫码绑定更新维护；本地实现与测试不能代替企业微信官方资质审核、应用发布及客户手机验收。覆盖升级请同时阅读 [手动覆盖升级说明](手动覆盖升级说明.md)。

## 一、先看明白：谁做什么

目标：**客户继续使用自己的企业微信，员工收到业务通知，点开你提供的后台管理小程序，处理自己有权限的任务。**

- 不需要为了收通知，把所有客户的员工加入你的企业。
- 企业授权、员工绑定、小程序登录是三件事，前一步成功不代表后两步自动完成。
- 小程序名称只是展示文字，不能代替 AppID、企业授权或页面权限配置。
- 当前代码使用“标准第三方应用 / Suite”，不是“代开发模板”。两种方式的密钥和教程不能混用。
- **同一套 SaaS 内客户共用域名：平台只配置一套通道，各客户按自己的站点分别授权自己的企业。** 不给每位客户新建域名或新建 Suite；只有独立部署的另一套 SaaS 才涉及第九节的部署隔离。

| 角色 | 负责什么 | 不需要做什么 |
| --- | --- | --- |
| 你／平台负责人 | 核实资质、创建应用、准备管理小程序、安排发布验收 | 不替所有员工完成身份绑定 |
| 技术／运维 | 部署插件、配置回调和通道、启动消息处理、排查错误 | 不索要客户企业 Secret 或员工密码 |
| 甲方企业微信管理员 | 安装授权应用、设置可见范围、处理企业侧权限 | 不开发小程序、不维护服务商密钥 |
| 甲方 SaaS 站点管理员 | 开通账号权限、配置通知、展示绑定码、确认员工身份、检查日志 | 不把配置权限开放给所有员工 |
| 收通知的员工 | 在本人企业微信中绑定身份，登录管理小程序、处理任务 | 不填写 SuiteID、Secret 或其他人的 UserID |

一人可以兼任多个角色，但要分别确认完成了每项工作。

## 二、准确入口

“本套 SaaS 域名”是当前部署的 HTTPS 根地址，例如 `https://你的域名`，不要跨系统复制使用。

| 谁进入 | 页面 | 地址／入口 |
| --- | --- | --- |
| 平台负责人 | 企业微信服务商后台 | [官方入口](https://open.work.weixin.qq.com/)，查看“提供 SaaS 应用”区域 |
| 小程序管理员 | 微信公众平台 | [官方入口](https://mp.weixin.qq.com/)，选择后台管理小程序 |
| 甲方企微管理员 | 企业微信管理后台 | [官方入口](https://work.weixin.qq.com/) |
| 平台管理员 | 系统设置 → 企业微信服务商 | 本套 SaaS 域名 + `/admin/setting/hsx-wecom/provider` |
| 客户站点管理员 | 企业微信 → 协同配置 | 本套 SaaS 域名 + `/site/hsx_wecom/config` |
| 客户站点管理员 | 权限管理 → 管理员 | 本套 SaaS 域名 + `/site/auth/user` |
| 客户站点管理员 | 权限管理 → 管理员角色 | 本套 SaaS 域名 + `/site/setting/auth/role` |
| 普通员工 | 本人专属绑定二维码／链接 | 管理员在“接收员工”生成，员工用自己的手机企业微信扫描／打开 |

协同配置的页签为 **接入与通知、接收员工、消息日志**。看不到菜单时，先检查插件菜单及账号权限，不要给所有人超级管理员权限。

## 三、先天条件：开始前准备好什么

### 你／平台负责人准备

- [ ] 服务商账号可登录，核实是否具备创建、测试、审核及正式提供标准第三方应用的资格。
- [ ] 在官方后台确认企业认证、服务商身份、应用审核及接口许可要求。注册账号不等于正式服务资格；认证费用、审核时间、测试限制以当前官方页面为准。
- [ ] 准备本套 SaaS 的后台管理小程序 AppID 及管理权限。这里不是每家门店面向消费者的销售小程序。
- [ ] 核实该 AppID 能按官方要求关联到本次第三方应用。涉及不同主体时完成相应授权，不能只填 AppID 就视为关联成功。
- [ ] 确认管理小程序包含所需业务页面，生产版本已发布，接口域名指向正确 SaaS。
- [ ] 准备一位客户企业管理员和一位试点员工参与手机验收。

### 技术／运维准备

- [ ] 对外可访问的 HTTPS 域名及有效证书；回调不被登录页、验证码、IP 防护或反向代理重写拦截。
- [ ] 服务器可请求 `qyapi.weixin.qq.com`，PHP cURL、OpenSSL 可用。
- [ ] 本部署的 `app.auth_key` 已安全备份且保持稳定，它用于凭据加密和入口签名，不得为排障随意重置。
- [ ] 插件、管理页面、后台管理小程序为对应版本，数据库已完成插件正常安装／升级。
- [ ] 消息队列及“企业微信消息补偿”计划任务有实际执行者，不能只有配置记录。
- [ ] 两套 SaaS 的域名、小程序、数据库和缓存配置可明确区分。

### 甲方准备

- [ ] 自己的企业微信组织，管理员可以完成安装授权。
- [ ] 接收通知的员工已加入正确企业，手机企业微信正常可用。
- [ ] 每位员工在本 SaaS 站点有独立账号及对应业务权限。
- [ ] 确定谁接收哪类任务；只开启通知开关不会自动决定所有订单的负责人。

### 甲方到底要提供哪些配置

| 当前方式 | 甲方提供／完成 | 平台提供／完成 |
| --- | --- | --- |
| 服务商一键授权（推荐） | 企业管理员完成官方安装授权、可见范围；提供实际员工和业务负责人名单 | Suite、回调、域名、管理小程序、平台通道；系统从授权结果取得客户企业身份 |
| 自建应用（高级） | 自己企业的 CorpID、应用 AgentId、Secret，以及必要的域名／应用关联配置；仅通过受控后台填写 | 协助核对填写及真实收信测试，不把服务商 SuiteSecret 当成客户 Secret |

甲方可以在自己的站点填写高级配置，也可以由获授权的平台实施人员协助。服务商模式**不需要收集甲方 Secret**；能否授权、是否有接口许可仍取决于官方资质和当前应用状态。不要把密钥发到微信群或写进交付文档。

## 四、平台首次开通：你和技术人员完成

### 第 1 步：安装／升级插件，确认入口能打开

**谁做：技术／运维。在哪里：服务器发布目录及数据库管理工具。**

已有插件按[手动覆盖升级说明](手动覆盖升级说明.md)执行：备份、覆盖插件、导入执行增量 SQL、补缺菜单和补偿任务、授予必要权限、打包前端。无需运行框架一键升级。尚未安装插件时仍需先正常安装和启用。

已有安装逻辑通过 `WecomSchema::migrate()` 创建／补齐以下表及必要字段索引：`wecom_provider_suite`、`wecom_corp_authorization`、`wecom_authorization_intent`、`wecom_callback_event`、`wecom_staff_binding`、`wecom_message_log`。

**表名使用实际数据库前缀。不要直接套用其他环境的 `ns_`、`saas_`，不要删表重建。仅上传 PHP 或 SQL 文件不等于完成升级。** 本次扫码功能复用现有字段；旧环境缺少服务商结构时，增量 SQL 会补齐，执行前须备份。

完成标准：两类配置页正常加载。表不存在等问题交给技术人员，不让客户反复扫码。

### 第 2 步：在官方后台创建标准第三方应用

**谁做：平台负责人，技术配合。在哪里：企业微信服务商官方后台。**

1. 在“提供 SaaS 应用”区域选择“创建应用”，按当前官方页面填写应用信息。
2. 使用与本项目对应的标准第三方应用方式，不拿代开发模板的凭据填入当前配置。
3. 记录服务商企业 ID、SuiteID、SuiteSecret，准备回调 Token、EncodingAESKey；密钥只交授权技术人员安全配置。
4. 按实际业务申请应用消息、成员身份授权等必要能力；普通内部通知不默认申请全部客户联系能力。
5. 按官方流程关联后台管理小程序，准备回调配置。

完成标准：拿到同一应用的有效凭据，并明确应用是测试状态还是已正式可授权。

当前代码没有“测试授权／正式授权”切换按钮。尚未发布的应用能授权给哪些测试企业，要在官方后台核实；不能承诺新建后任意客户都能安装。资格或应用类别不满足时停在此步处理，不让客户承担排查成本。

### 第 3 步：填写平台通道

**谁做：平台管理员／技术。在哪里：`/admin/setting/hsx-wecom/provider`。**

| 系统字段 | 填什么／从哪里来 |
| --- | --- |
| 启用服务商通道 | 必要配置准备好后开启 |
| 通道标识 | 本部署标识，如 `saas_a`；2–40 位，小写字母开头，可含小写字母、数字、下划线和连字符 |
| 服务商企业 ID | 你的服务商企业 CorpID，不是甲方企业 ID |
| SuiteID、SuiteSecret | 第 2 步同一个第三方应用的凭据 |
| 回调 Token、EncodingAESKey | 与官方回调配置一致；EncodingAESKey 为 43 位 |
| 管理小程序 AppID | 本套后台管理小程序 AppID |
| 管理小程序名称 | 员工能识别的名称；改名不能修复身份或页面权限问题 |
| 网页管理端地址 | 本套 SaaS HTTPS 根地址，不带 `/site`、`/adminapp` 或业务页面 |

点击 **保存服务商通道**，再操作验证。验证读取已保存配置，不是尚未保存的表单内容。

不要随意改投用通道的 SuiteID、企业 ID 或通道标识。更换应用或企业可能使原授权和员工绑定失效，需要安排重新授权。

### 第 4 步：把系统地址配置到官方后台

**谁做：技术＋平台负责人。在哪里：平台配置页、企业微信第三方应用设置。**

保存后复制系统显示的地址，避免手工拼接：

| 地址 | 用途 |
| --- | --- |
| 事件回调 URL：`https://本套域名/api/wecom/provider/event/通道标识` | 接收 SuiteTicket、授权变更等指令；配置到官方对应的指令回调，使用相同 Token、EncodingAESKey |
| 授权回调 URL：`https://本套域名/api/wecom/provider/authorize/complete/通道标识` | 企业管理员安装授权后的返回地址，按官方要求配置对应回调／域名 |
| 员工身份回调：`https://本套域名/api/wecom/provider/member/complete/通道标识` | 员工 OAuth 返回地址，由程序生成；当前页面未单独展示，技术须一并核对域名是否被允许 |

官方字段要求域名就填域名，要求完整 URL 就填完整地址。**不要只配置消息数据回调，就认为 SuiteTicket 指令回调已经完成。** 当前接入不是通用聊天消息接收系统。

可信域名、域名归属、可信 IP、小程序关联按当前应用类型和官方提示完成；不能将自建应用或代开发教程的要求直接代替当前配置。主体校验失败时处理对应资质／授权，不绕过校验。

回到系统点 **刷新状态**，确认收到 SuiteTicket，再点 **验证服务商通道**。

完成标准：验证可以取得服务商通道凭据。这里只证明基础通道可用，**不证明客户授权、员工收信或小程序可操作**。

### 第 5 步：准备正式消息处理

**谁做：技术／运维。在哪里：项目队列和计划任务环境。**

- `queue.state` 开启时普通通知入队，需要运行队列消费者。
- 确认“企业微信消息补偿”（`hsx_wecom_message_retry`）按分钟执行；关闭队列时尤其需要它处理待发送记录。
- 测试通知即时发送，收到测试卡片不能代替普通业务消息的队列验收。
- 失败记录累计尝试达到 5 次后停止自动重试，不是首发之外再重试 5 次。人工“重试”会重新投递，可能再次通知员工。

完成标准：后续业务测试中，普通通知能从待发送进入终态，不长期停留在队列。

## 五、每个客户开通：甲方管理员完成

### 第 6 步：授权甲方自己的企业

**谁做：甲方 SaaS 管理员发起，企微管理员确认。在哪里：`/site/hsx_wecom/config` → 接入与通知。**

1. 确认当前是正确客户站点，不是另一位客户或另一套 SaaS。
2. 选择 **服务商一键授权**，点击 **一键授权企业微信**。
3. 当前实现跳转官方安装授权页，按官方页面验证管理员身份、选择企业和授权范围。
4. 授权甲方自己的企业，确保应用可见范围包含需要收通知的员工。
5. 返回系统点 **检查授权状态**，核对授权企业、应用 AgentId、授权时间、所属通道和后台管理小程序。

完成标准：企业信息正确、授权有效。授权链接短期有效，过期重新发起，不复用旧链接。

当前边界：同一 Suite 下，一个企业目前只允许绑定一个 SaaS 站点。不要把所有客户授权到你的企业，也不要将同一企业重复绑定给多个站点；这种组织模式需要另行设计。

**站点页当前没有自带授权二维码弹窗**，不是“在本系统点击按钮就弹码”。官方安装页的验证交互以其实际页面为准。

### 第 7 步：启用通知，确定业务入口

**谁做：甲方 SaaS 管理员。在哪里：同页“通知规则”区域。**

开启 **启用企业微信通知**，按需开启 **任务分配通知、经营报告通知**；回收任务入口选择 **我的待办** 或 **订单详情**，点击 **保存通知设置**。

服务商模式跳转平台配置的后台管理小程序，客户不再填写 AppID。开关只控制已接入消息，不会自动接入全部插件或生成经营报告；业务还需产生任务、确定负责人并调用通知服务。

## 六、员工绑定：管理员出码，员工扫码，核对后生效

### 第 8 步：准备员工账号

**谁做：甲方站点管理员。在哪里：权限管理 → 管理员／管理员角色。**

为员工建立独立、启用的系统账号，分配实际工作权限，确认归属站点；回到协同配置的 **接收员工** 找到本人。

这里显示本 SaaS 员工，不是自动拉取整个企微通讯录。账号不存在时先建系统账号，不手填其他人的 UserID 凑数。

### 第 9 步：本人完成身份绑定

**谁做：站点管理员＋员工。在哪里：接收员工，随后手机企业微信。**

1. 管理员在目标员工行打开扫码绑定弹窗，本人和其他员工使用同一套流程。
2. 请这位员工用自己的手机企业微信扫描专属二维码；远程协助时，可复制绑定链接单聊发送给本人。
3. 员工完成企业微信授权，手机显示“等待管理员确认”的结果，不进入需要配置权限的后台页面。
4. 管理员弹窗自动更新扫码状态，显示客户企业及脱敏的成员标识。企业微信没有提供可验证姓名时，不把系统员工姓名冒充扫码人的姓名；应现场或单聊核实本人。
5. 确认是目标员工本人操作，勾选核对确认，再点击确认绑定。只有此时才正式写入通知身份。
6. 绑定完成后检查员工的通知开关，按需保存。再发送测试通知验证。

二维码有效期 10 分钟，到期重新生成。刷新码后旧码失效；撤销未生效入口不会删除员工原有的正常绑定。扫码不属于当前授权企业、员工已停用、成员已绑其他账号等情况会被拒绝。

**安全提示：链接不是公开招募码，不能发大群，不能代扫。管理员不能只看“有人扫码了”就确认。** 换绑前核实本人；扫码阶段不会直接覆盖旧的通知接收人。

### 仍然要区分的三件事

- 手机提示扫码完成：已取得候选身份，仍等待管理员确认，不是已开通通知。
- 管理员确认绑定：建立收信身份，仍需验证可见范围及通知开关。
- **通知身份绑定不等于小程序免登录**：管理小程序仍要求系统登录及站点权限，员工不需要获得配置权限。

## 七、怎样才算完成：分层验收

### 第 10 步：发送测试通知

**谁做：站点管理员＋试点员工。在哪里：接收员工页签。**

选择已经绑定且同意测试的员工，点 **发送测试通知**；员工在手机企业微信确认收到，点开后确认本套管理小程序能登录正确站点。

这是发送真实消息，不是只检查配置。**当前后端测试消息打开管理首页／工作台，不是订单详情**，必须继续下一步。

### 第 11 步：验证一笔业务路径

**谁做：业务负责人发起、员工验收、技术观察日志。**

1. 使用明确标为测试的业务，按正常流程分配给员工，不用真实付款验证跳转。
2. 确认普通业务通知发出，消息内订单、设备信息正确。
3. 用甲方自己的手机企业微信打开，核对正确站点、正确订单／待办及员工权限。
4. 检查按钮、返回、登录后跳转；需验证写操作时只使用已授权测试业务。
5. 确认无权限员工不会因此获得该业务访问权。

| 验收层级 | 由谁证明 | 成功证据 |
| --- | --- | --- |
| 通道可用 | 技术 | 服务商验证通过、回调票据正常 |
| 企业及员工绑定正确 | 甲方管理员 | 企业、站点、员工对应正确 |
| 消息送达 | 员工本人 | 手机企微实际收到该次卡片 |
| 业务可用 | 员工＋业务负责人 | 打开正确业务页、按钮可用、权限正确 |

**接口发送成功不等于员工已收到／已读；小程序打开不等于工单能处理。普通微信可用不能代替甲方手机企业微信验收。**

## 八、失败了去哪里看、找谁处理

在 **协同配置 → 消息日志** 查询标题、员工或错误内容，查看待发送、发送成功、发送失败、已跳过等状态。失败行可“重试”，先处理原因再投递。当前没有完整的阅读率、点击率、处理转化率看板。

| 现象 | 下一步 | 责任人 |
| --- | --- | --- |
| 数据库表不存在 | 检查插件安装／升级及实际前缀，不删库重装 | 技术 |
| 平台待配置／无 SuiteTicket | 检查保存、指令回调、HTTPS、Token、AESKey、拦截日志 | 技术＋平台负责人 |
| 官方不允许安装／授权 | 核实应用类别、资格、发布／测试范围、管理员权限 | 双方管理员 |
| 授权错企业／已绑其他站点 | 停止继续，核对归属，不强制迁移 | 双方管理员 |
| 员工不在列表 | 检查本 SaaS 站点账号是否存在并启用 | 甲方站点管理员 |
| 绑定失败／链接过期 | 重发本人链接，用正确企业打开，核对账号冲突 | 管理员＋员工 |
| 扫码后等待确认 | 管理员核实本人后确认；不要重复扫码或给员工开配置权限 | 站点管理员 |
| 轮询失败／未自动更新 | 检查网络和“查看绑定进度”权限，重试状态；未确认前不算绑定成功 | 站点管理员＋技术 |
| 一直待发送 | 检查消费者和补偿任务，不用连续重试代替修复 | 运维 |
| invaliduser／unlicenseduser 等 | 按错误核对成员、可见范围及适用接口许可 | 技术＋甲方企微管理员 |
| 接口成功但没收到 | 核对收件人、员工当前企业、应用入口，现场确认 | 管理员＋员工 |
| 打开后按钮无反应 | 检查版本、请求失败、登录、站点权限及导航错误 | 技术 |
| 页面不存在／进错列表 | 核对卡片路径、参数和已发布页面；不能将 PC 路径当小程序路径 | 技术 |
| 旧卡片失效 | 按错误核实入口票据是否过期，用新卡片验收，不关签名验证 | 技术＋管理员 |
| 取消授权后收不到 | 停止重试，确有需要时重新授权并核对绑定 | 甲方管理员 |

排障提供域名、站点、员工账号、发生时间、消息记录及脱敏错误截图。**不在群里发 Secret、永久授权码、完整 Token、app.auth_key、员工密码。** 后端更多记录由技术受控查看，当前界面未展示全部字段。

已有手机跳转修复及验证边界见：[手机企微跳转修复与测试](2026-09-29_手机企微跳转修复与测试.md)。服务商授权不能代替这些业务故障的排查。

## 九、两套 SaaS 怎样不串线

| 配置 | SaaS A | SaaS B |
| --- | --- | --- |
| 网页管理端地址 | A 的 HTTPS 根地址 | B 的 HTTPS 根地址 |
| 通道标识 | 如 `saas_a` | 如 `saas_b` |
| 后台管理小程序 | A 的 AppID | B 的 AppID |
| 服务商应用 | 建议独立 Suite A | 建议独立 Suite B |
| 数据库、缓存、凭据 | A 的独立配置 | B 的独立配置 |
| 客户、员工授权 | A 的正确站点 | B 的正确站点 |

每套部署当前管理一个有效通道。建议独立部署使用对应应用，各自核实小程序主体关联条件。

**同一 Suite 的官方回调先改 A、再改 B，不代表两套都能工作。** 当前没有统一回调中转和跨部署票据分发服务。必须共用 Suite 时先设计公共服务，不靠复制数据库或密钥解决。

正常工作的自建应用可继续“自建应用（高级）”，不要清空旧配置。切换客户前记录当前方式、员工及测试结果，再有计划地授权和复验。

## 十、本次升级的验收标准及边界

1. 平台、甲方管理员、员工可看到各自操作指引；同域名下客户只处理本站授权，不维护平台 Suite。
2. 字段已填写、通道已验证、企业已授权、员工已绑定、消息已受理必须区分，不宣称自动完成整条链路。
3. 绑定弹窗支持二维码、专属链接、过期刷新、扫码进度、人工核对及结果反馈。
4. 普通员工授权后看到独立结果页，不要求后台配置权限；管理员确认才正式生效。
5. 站点隔离、企业隔离、停用员工、重复身份、过期链接、撤销和重新生成需有回归检查。
6. 首页测试与具体业务测试分开验收，实际手机企业微信测试仍由你和甲方员工完成。
7. 本轮不增加已读／点击／转化率采集；发送成功仍不是员工已读，不新增业务营销自动化。

## 十二、依据及维护规则
