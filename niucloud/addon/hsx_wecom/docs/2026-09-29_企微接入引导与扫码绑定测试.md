# 企业微信接入引导与扫码绑定：交付及测试记录

日期：2026-09-29。范围：`hsx_wecom` 同域 SaaS 接入、员工扫码绑定、手动覆盖升级。

## 1. 交付结论与边界

本地开发、离线回归、隔离数据库 SQL 执行和管理端构建已完成。没有修改生产数据库、没有使用客户企业凭据、没有向真实员工发送通知。真实企业微信授权、回调、收信和手机任务跳转尚待部署后验收，不能用本报告代替官方应用资格审核或真机验收。

- 同一套 SaaS 共用一个平台服务商通道；每个站点分别授权甲方自己的企业。
- 平台、甲方管理员、本站管理员、员工的准备材料、入口、步骤和失败处理已写入页面折叠引导及操作指南。
- 服务商模式下，管理员为员工生成专属码；本人企微扫码仅取得候选身份，管理员核对后才正式绑定。
- 自建应用原有方式保留，使用甲方应用配置及手工 UserID；不把该方式宣传成服务商扫码绑定。
- 绑定只决定通知接收身份，不授予业务权限，也不替代管理小程序登录。
- 本轮扫码功能复用授权意图表的 `meta_json`，没有新增数据库表或字段。手动 SQL 用于旧部署补齐已有服务商结构。
- 本轮引导、绑定、权限兜底和升级工具均在插件层完成，未新增框架修改。工作区此前的移动导航修复另见[手机企微跳转修复与测试](2026-09-29_手机企微跳转修复与测试.md)，不能混称整个交付零框架改动。

## 2. 管理员可看到的流程

1. 平台入口 `/admin/setting/hsx-wecom/provider`：平台配置一次；明确区分“已保存”“本次凭据验证通过”。
2. 客户入口 `/site/hsx_wecom/config`：授权客户自己的企业，检查企业身份并保存通知规则。
3. “接收员工”：生成 10 分钟有效的专属二维码／链接，不公开发群。
4. 本人扫码：手机显示等待管理员确认，不强制进入无权限的配置后台。
5. 管理员核对：显示授权企业及脱敏成员标识，勾选核对后才能确认。
6. 确认成功：刷新员工列表，检查通知开关，再测试真实收信和业务任务。

异常有明确出口：企业不一致、员工停用、重复身份、权限不足、过期、重新生成、网络失败。确认响应丢失时显示“结果待核实”并查询最终状态，不承诺“未绑定”；无法核实时提醒刷新员工列表核对。

## 4. 重点回归场景

### 身份和权限

- 扫码不立即写正式员工绑定；只有配置管理员确认后才写入。
- 站点／员工／通道／授权企业快照不匹配时拒绝，不能跨租户确认。
- 员工停用、身份已被其他员工占用、入口被撤销、旧版本意图不能继续确认。
- 重新生成使旧入口失效；取消未确认入口不删除已有绑定；重新绑定保留原通知开关。
- 重复确认幂等；已绑定结果仍核对现有绑定，不把过时意图当成当前有效身份。
- 菜单权限未导入时，插件显式校验权限并拒绝普通员工敏感操作，不依赖框架对未知菜单 API 的默认放行。
- 检查真实 `SysUserRole`、`SysUser` 字段及权限服务契约；未改框架授权规则。
- 手机回调 HTML 转义外部内容，禁止缓存和引用来源泄漏，不输出 OAuth code、state 或密钥。

### 前端异步交互

- 关闭弹窗、切换员工、重新生成后，旧请求不能覆盖当前员工界面。
- 未勾选核对不能确认；确认进行中禁止关闭／换码。
- 倒计时使用服务端 `expires_in` 和单调时钟，电脑日期快慢不导致新码被误判失效。
- 确认请求超时不能等同于失败；最终查询成功时显示绑定成功。
- 到期仍核对服务端最终状态；确认事务和状态查询使用一致锁顺序。内存测试不能证明真实数据库所有并发情况，生产同等数据库下仍应补并发验收。
- 最终查询也失败时保持“待核实”，不擅自撤销可能已成功的绑定。
- 平台接口实际返回值没有站点 `configured` 字段，已按已保存平台配置快照判断可验证状态，未保存输入不能冒充有效配置。

### 手动 SQL

在 `/tmp` 下独立数据目录、专用 socket、关闭网络的 MySQL 实例中验证：全新执行、重复执行、6 张精简旧表补列／索引且旧行不变、替换前缀、`NO_BACKSLASH_ESCAPES`、非法前缀和未选数据库保护。测试完成后实例已关闭，未连接本地业务库或生产库。

边界：已有列类型错误、同名索引定义错误、唯一索引历史数据冲突不会自动清洗；DDL 不能整体回滚。必须先备份并按实际前缀执行，报错停止；目标服务器版本仍需运行只读核查。

## 5. 浏览器验证（模拟环境）

使用实际管理端组件、实际 Element Plus 和二维码库；请求层替换为本地模拟响应，页面持续标明“模拟数据，不连接企业微信，不发送真实通知”。没有使用连接生产接口的开发环境直接测试。

已观察：

- 平台共享通道引导和客户四步引导正确展示，详细说明默认折叠。
- 平台真实响应形状下，已保存配置可点击验证；显示的是凭据验证结果，不宣称员工已收信。
- 专属二维码生成、扫码候选身份展示、未核对时确认按钮禁用、确认后显示成功并回写员工列表。
- 过期提示和重新生成入口、网络错误后的“重新检查状态”入口可见，不误报成功。
- 模拟确认响应丢失时，先显示“绑定结果待核实”，最终状态查询确认后转为“员工绑定已确认”，列表显示已绑定。
- 1280 × 720 场景页面横向无溢出；390 × 844 下弹窗宽度适配、底部操作可见。该预览不包含完整系统侧栏，不代替全部后台页面适配测试。

这验证的是组件交互，不是企业微信 OAuth、手机扫码识别率或真实消息送达。

| 谁 | 操作 | 通过标准 |
