# 企业微信：先验证回调，再创建应用

## 这次解决什么

你刚注册服务商，正在创建应用，此时没有 SuiteID / SuiteSecret 是正常的。旧代码要求先启用通道才能响应回调，但启用又要求应用凭据，造成先后顺序互相卡住。

现在分为两个阶段：

1. **回调准备**：只需要服务商企业 ID、本站根地址、通道标识、Token、EncodingAESKey；允许企微验证回调地址，不启用通知，不处理客户授权。
2. **正式启用**：应用创建成功后，再补齐 SuiteID、SuiteSecret、管理小程序信息，启用并核验 SuiteTicket；随后完成客户授权、员工绑定及真机通知验收。

本轮只改 `hsx_wecom` 插件和对应的管理前端镜像。不改框架，不改业务数据，不加数据库表／字段。准备阶段复用现有 `wecom_provider_suite.status` 的 `preparing` 值（现有 varchar 字段），停用仍为 `disabled`，不会因准备逻辑绕过停用。

同时回归发现原三个员工绑定接口缺少权限字典，已补齐“查看绑定进度／确认绑定／撤销绑定”。它们是现有菜单表的记录补缺，不是加表或字段；需按下面部署步骤注册并按需授权。

在服务器 **PHP 根目录（含 think 的 niucloud 目录）**，使用网站相同 PHP 和运行账户检查：

```bash

```


补缺工具会写入缺少的菜单／计划任务记录，保留既有记录，不修改角色授权。检查有结构缺失或停用／自定义冲突时先处理输出，不强行覆盖。只给配置管理员分配上述三个绑定权限，普通员工不需要配置权限。

## 二、你现在怎么操作（平台负责人）

1. 更新完成后，打开 `https://gl.hsxbk.top/admin/setting/hsx-wecom/provider`，确认看到“第一步：先准备回调，再创建应用”。
2. 填写通道标识（新环境可用默认 `default`）、服务商企业 ID（你的服务商企业，不是客户企业）、网页管理端地址 `https://gl.hsxbk.top`。
3. 在企微创建页准备 Token 和 43 位 EncodingAESKey，把同一份值安全填写到我们平台。已保存后的 `******` 是掩码，不能复制到企微；不要在聊天中发送密钥。
4. 点击 **保存回调准备**。无需填写 SuiteID、SuiteSecret、小程序 AppID。成功后显示“回调准备已保存 · 未启用”，这还不代表企微已验证通过。
5. 按下表从平台的“官方创建页填写清单”复制字段到企微，完成其回调验证和应用创建。

下表仅以实际保存的通道为 `default` 举例；若你保存的是其他通道，以页面生成地址为准。

| 企微字段 | 本部署示例 |
| --- | --- |
| 安装完成回调域名 | `gl.hsxbk.top`（没有 https://、没有斜杠） |
| 数据回调 URL | `https://gl.hsxbk.top/api/wecom/provider/data/default` |
| 指令回调 URL | `https://gl.hsxbk.top/api/wecom/provider/event/default` |
| Token | 与平台保存的原始 Token 完全相同 |
| EncodingAESKey | 与平台保存的原始 43 位 AESKey 完全相同 |
| 应用设置 URL | `https://gl.hsxbk.top/site/hsx_wecom/config` |

应用设置 URL 是现有站点配置页面，需要正常登录 SaaS 并具备该站点权限；没有冒充企微管理员免登，也不会根据外部 URL 参数自动切换客户站点。域名归属验证文件、应用资质、可信域名/IP 和小程序关联仍按官方当前页面要求完成。

平台保存失败时不要去提交企微；回调字段不可复制或提示草稿未保存时，先保存对应基础配置。不能用网站首页替代回调 URL，也不能用假 ID／假 Secret 通过验证。

## 三、应用创建成功之后

1. 在企微获取此应用真正的 SuiteID／SuiteSecret，填回平台第二步；同时填写本套后台管理小程序 AppID 和名称。
2. 保存并启用通道。此后指令回调才处理 SuiteTicket 和授权变更。
3. 刷新状态，确认收到 SuiteTicket 后执行服务商验证。准备期间的 POST 不处理票据；若早先推送未被接收，启用后等待官方重试／后续推送，并核对指令地址，不能凭空补 Ticket。
4. 按官方测试／发布状态，在允许的客户企业中进行安装授权。应用创建或服务商认证不等于所有客户已可安装。
5. 客户站点管理员授权自己的企业，添加站点员工账号并生成绑定码；员工用自己的手机企微扫码，管理员核实确认。
6. 在手机企微收取测试通知并打开管理端，再用受控业务测试通知到具体工单，核对本站权限。完成后才能说该客户“可以正常使用”。

## 四、边界和失败排查

- preparing 仅接受带正确签名、密文和服务商接收身份的 GET；不会发送消息、处理授权或把收到的 SuiteID 自动当作可信配置。
- disabled 不能验证或接收消息。停用旧通道不是创建前准备；已有应用不能退回准备模式。
- 指令和数据分路：指令严格核对 Suite，数据严格核对当前 Suite 下的已授权企业及应用身份，拒绝串企业或把用户消息发到指令口。
- 数据回调目前是安全接收应答，不是聊天客服：不存消息正文，不执行自动回复，也不标记为某项聊天业务已处理。
- 裸打开回调 URL 没有官方签名，会失败，这是正常保护。浏览器返回网页／HTTP 200 本身也不证明企微回调验证成功。
- 地址验证失败时检查：线上是否部署本轮文件、基础配置是否已保存、通道是否一致、Token/AESKey是否一致、服务商企业 ID 是否填写正确、HTTPS与路由是否被代理或登录页拦截。
- 回调错误日志只记通道、接口类型和异常类别，不记录签名、密文、消息正文或密钥。
