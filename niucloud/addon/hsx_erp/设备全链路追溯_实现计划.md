# 设备全链路追溯 — 实现计划（待确认范围）

## 目标
在 **ERP 中台菜单** 下新增「设备追溯」页：输入**串号(IMEI)/资产号/回收单号**，一次性把这台机器从回收到卖出、收款的**完整时间线**展示出来——每个状态、每条日志、操作人、金额、关联单号。

## 串联思路（一台机器在系统里的多重身份）
- 总钥匙：**IMEI(串号)**
- 回收设备：`recycle_device.id`（= 回收侧主键）
- ERP 资产：`erp_asset`，其 `source_device_id` = 回收设备 id（两边靠它对应）
- 财务应付/应收：`source_device_id` = 回收设备 id
- 结算/折账：通过 `erp_finance_settlement_link` → 应付/应收 关联
- 资金流水：`erp_capital_ledger`（按 source / counterparty）

解析顺序：IMEI → 命中 `recycle_device` 取回收设备id+订单；→ 命中 `erp_asset`(同 IMEI 或 source_device_id)取资产；→ 用这两个 id 去各表捞记录。

## 页面构成
1. **顶部概览卡**：IMEI、型号、当前状态、所属主体/对接人、回收价 / 售价 / 毛利、当前所在（仓库 or 已售）。
2. **流转进度条**：未流转 → 已入库 → 转中台 → 已定价 → 已售/下架（复用回收 `downstream_stage`）。
3. **完整时间线**（按时间正序，分段着色：回收 / 中台 / 财务）：
   - 每条：时间、阶段、动作、状态变化(前→后)、操作人、金额、备注、关联单号。

## 数据来源（按段）
**回收段**（回收插件提供）
- 回收设备日志 `recycle_device_log`：下单、质检、定价确认、退回、打款、折账核销
- 打款记录 `recycle_device_payment`：打款/折账（金额、方式、单号、操作人）

**中台段**（ERP）
- 资产移动日志 `erp_asset_move_log`：入库确认、整备、调拨、出库（前后状态、仓库、操作人）
- 成本台账 `erp_cost_ledger`：成本变动（整备费、买断等）
- 定价：`erp` 定价记录 / 资产 `current_sale_price`

**财务段**（ERP）
- 应付 `erp_finance_payable`（我欠）、应收 `erp_finance_receivable`（欠我）：生成时间、金额、来源、状态
- 结算 `erp_finance_settlement` + `erp_finance_settlement_link`：折账/收款、结算单号、折账额/现金额
- 资金流水 `erp_capital_ledger`：收/付、走哪个户头

## 跨插件取数（解耦，符合现有架构）
不让 ERP 直接读回收表。新增一个**查询型事件**：
- ERP 追溯服务先汇总自己（资产+财务）的时间线；
- 再 `event('CollectRecycleDeviceTrace', ['imei'=>..., 'device_id'=>...])`；
- 回收侧加监听器，返回它那段时间线（设备日志+打款记录，统一成 {time,stage,title,detail,operator,amount,no} 结构）；
- ERP 合并两段、按时间排序后返回前端。

## 接口与文件（预计改动）
**ERP**
- `app/service/admin/DeviceTraceService.php`（新）：解析身份 + 汇总 ERP/财务时间线 + 调事件取回收段 + 合并排序
- `app/adminapi/controller/DeviceTrace.php`（新）：`GET erp/device_trace?keyword=IMEI`
- 路由 1 条；菜单 1 项（中台下「设备追溯」）
- 前端 `views/device_trace/index.vue`（新）：搜索框 + 概览卡 + 进度条 + 时间线；api 1 个

**回收**
- `app/listener/downstream/CollectDeviceTraceListener.php`（新）：返回回收段时间线
- `event.php` 注册 1 条

## 工作量（粗估）
- 后端：ERP 追溯服务 + 控制器 + 回收监听 ≈ 0.5~1 天
- 前端：时间线页 ≈ 0.5 天
- 联调 + 菜单/权限 ≈ 0.5 天

## 已确认的范围（定稿）
1. **颗粒度**：时间线分两层——**关键节点**(下单/入库/转中台/定价/出库/收款/折账)重点高亮展示；细节日志默认折叠，点"展开"看全量。
2. **金额小计(必须)**：概览卡展示这台机器本次生命周期的钱：回收成本、整备费、其它成本、**售价**、**毛利**、已收/未收；并标明**从谁收的(回收客户)**、**卖给了谁(同行/对接人)**。
3. **搜索改为"列表→详情"两步(解决 IMEI 重复)**：
   - 同一 IMEI 可能多次回收→出售(卖出又收回)，所以一个 IMEI 对应多条生命周期。
   - 搜索(IMEI / SN / 资产号 / 回收单号)→ 返回**生命周期列表**(每行=一次回收记录：IMEI、型号、回收单号、回收时间、当前状态、售价、买家)。
   - 点某一行 → 进入该次生命周期的**详情**(概览卡+进度条+时间线)。
   - 生命周期的唯一单元 = 一条 `recycle_device` 记录(对应一条 `erp_asset`，靠 source_device_id 关联)。
4. **操作人**：记录里有 operator_name 就直接用；没有(只存 uid)的，按 uid 关联系统用户表补全姓名。

## 调整后的接口
**ERP**
- `DeviceTraceService::searchList($keyword)` → 生命周期列表(跨插件：IMEI/资产号查 ERP 资产；回收单号/IMEI/SN 经事件问回收；按设备合并去重)
- `DeviceTraceService::detail($assetId 或 $deviceId)` → 概览(含金额小计)+ 时间线(关键节点+细节)
- 控制器：`GET erp/device_trace/search`、`GET erp/device_trace/detail`
- 前端：列表页 + 详情页(或同页两步)

**回收**
- `CollectDeviceTraceListener`：① 按关键词返回匹配的回收设备列表；② 按 device_id 返回该设备的回收段时间线 + 回收客户/回收价/打款折账金额
