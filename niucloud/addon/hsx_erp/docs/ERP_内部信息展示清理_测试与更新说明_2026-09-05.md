# ERP 内部信息展示清理：测试与更新说明

日期：2026-09-05

## 本次结果与边界

本版只清理管理端与移动管理端的展示噪声，不修改数据库、后端接口字段、业务状态流转、收付款操作、统计口径或检索参数。不是整套 ERP 的布局重做或全业务验收。

| 信息 | 处理方式 |
| --- | --- |
| IMEI、SN、型号、规格 | 保留；没有串号时明确提示，不用资产号冒充 |
| 采购、销售、退货、应收应付、结算及流水业务编号 | 保留展示、关联与检索 |
| 人员姓名、客户名称、仓库库位、业务来源、金额与结算状态 | 保留；缺少姓名或未知状态给出人话提示 |
| 数字 ID、UID、系统资产号、内部任务号、插件技术标识 | 移除日常界面展示与相关兜底，不删除接口数据和操作绑定 |
| 来源“回收插件采购” | 两端统一显示“回收入库”，接口原值不变 |
| 普通英文型号、人员名、已配置渠道名 | 保留，例如 iPhone、admin、eBay、Retail_US |
| 导入导出的匹配字段、打印模板实际占位符 | 保持原有契约，不在本轮删除 |

共用展示逻辑集中在各端的 `utils/display.ts`，避免各页面继续自行回退到内部 ID 或技术键。管理端动态台账也过滤内部展示列，原导出配置保留，公开列调整顺序时跳过隐藏内部列。

这里的“前端隐藏”不是权限隔离：内部字段按要求仍可由接口返回。敏感数据安全仍由后端权限控制，本次没有改变权限策略。

## 更新建议

1. 本次不需要执行 SQL，不需要为展示变化替换后端业务服务。
2. 管理端更新对应源码后重新构建；插件包的 `admin/` 镜像也已同步，避免后续插件更新把旧界面覆盖回来。
3. 移动管理端需更新 `site-uniapp` 并重新构建所用端（H5 或管理小程序），不是只上传 PHP 就生效。
4. 手工合并时必须带上新增 `utils/display.ts`，否则页面导入会失败。测试文件不参与运行界面。
5. 本轮没有升级依赖或改锁文件；不要为这次展示更新顺带升级 Vue、Element Plus 等依赖。
6. 上线前用真实样本复核库存检索、采购/销售详情、应收应付明细以及小程序真机，确认串号与业务单号没有被隐藏。
