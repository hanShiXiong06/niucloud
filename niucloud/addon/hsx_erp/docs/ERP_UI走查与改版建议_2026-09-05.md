# ERP 界面走查与改版建议

日期：2026-09-05  
范围：管理端、移动端 H5；本轮仅审查，不实施业务修改。

## 一、检查方式与边界

- 使用当前项目源码启动本地 PHP、管理端和移动端开发预览；接口仅连接本机数据库。
- 管理端在本地测试站点检查库存、应付款和 ERP 经营工作台；视口为 1280 × 720 CSS 像素。
- 移动端在同一站点检查采购列表、采购详情、库存列表、设备档案及应付款；视口为 390 × 844 CSS 像素。
- 结合两端源码检查字段、统计计算、跳转和公共组件。移动端为 H5 检查，不能替代真机小程序验收。
- 未执行打款、收款、出入库、退货、删除或数据库结构变更。测试数据较少，未做大量数据、多页汇总或大金额真机验证。
- 1280 × 720 用于覆盖常见紧凑工作区，不等于完整模拟某一 Windows 设备的 150% 缩放环境。

## 二、核心判断

当前主要问题是信息优先级：业务人员先看到单据结构、来源说明和编号，再找到设备、金额与下一步动作。

基础能力已有：设备身份展示、批次折叠、设备履历、结算展开、库存推荐操作。建议先统一这些公共能力的展示规则，再逐页替换，不需要重做整套流程。

## 三、实际页面发现

### 1. 管理端库存首屏看不到设备

实际在 1280 × 720 下，首屏被标题、六个统计块、优先处理提示、状态标签及多行筛选占满，尚未出现设备表头和记录。

源码表格最低列宽合计约 1833px（含财务列）；设备、入库、出库、库存流转、结算全部并列，常用工作区需要横向查找。

建议：

- 统计压缩为一行，完整经营统计放展开面板。
- 默认筛选保留关键词、仓库、状态；其他放“更多筛选”，已选条件仍显示标签。
- “我的待办”提升为快捷视图。
- 主表默认显示设备、当前阶段/负责人、位置、库龄、必要金额、下一步。
- 入库/出库详情、结算轨迹、长备注进入设备档案；允许按工作需要选择显示列。

证据：[库存列表](/Users/a123/Documents/1-work/niucloud/niucloud/admin/src/addon/hsx_erp/views/erp/stock/list.vue:70)。

### 2. 来源说明与编号重复，核账需要读太多文字

管理端应付款的一条记录同时显示设备采购支出、回收插件采购、手机回收、采购入库、来源插件、对象、方向、来源单号、ERP关联单号、应付原因。实际页面还直接显示 `hsx_recycle`。

这不是简单删除所有编号。建议默认回答四个问题：向谁付、什么业务、还欠多少、谁处理。来源归并成“回收入库”，关联单据集中展开，技术标识只进入系统记录。

证据：[管理端来源组件](/Users/a123/Documents/1-work/niucloud/niucloud/admin/src/addon/hsx_erp/components/ErpFinanceSourceMeta.vue:10)、[移动端来源组件](/Users/a123/Documents/1-work/niucloud/niucloud/site-uniapp/src/addon/hsx_erp/components/ErpFinanceSourceSummary.vue:15)。

### 3. 移动采购详情把设备和金额排在基础字段后面

390 × 844 首屏先展示采购号、供货方、M号、业务来源、原业务号、采购员、两种状态、创建和更新时间；设备明细接近屏幕底部才出现。

建议头部为“供货方 + 本单设备数 + 结算状态”，其次突出未付/已结算金额和设备。业务单号、时间、来源关系放“单据信息”折叠区。操作说明在用户打开相应操作时按需显示，不在每个正常单据上常驻整段教程。

证据：[采购详情](/Users/a123/Documents/1-work/niucloud/niucloud/site-uniapp/src/addon/hsx_erp/pages/purchase/detail.vue:15)。

### 4. “查看设备详情”与实际跳转不一致

实际点击采购设备卡的“查看设备详情”，进入的是采购单详情，携带采购单参数而没有设备定位参数。多设备批次会让用户再次查找设备。

建议分开“查看设备档案”和“查看采购单”；如果必须进入采购单，自动定位并突出刚点击的设备。

证据：[入口文案](/Users/a123/Documents/1-work/niucloud/niucloud/site-uniapp/src/addon/hsx_erp/pages/purchase/list.vue:91)、[跳转实现](/Users/a123/Documents/1-work/niucloud/niucloud/site-uniapp/src/addon/hsx_erp/pages/purchase/list.vue:299)。

### 5. 提示没有清楚区分“周转风险”和“上架条件”

实际库存设备有完整型号名称，却提示“缺少商品型号、图片、零售价”；该提示还跟在“周转预警”后面。用户很容易理解成系统把已有型号丢了，或者把缺图片当成库龄预警的原因。

建议两件事分别表达：

- 周转：在库多少天，超过哪条规则。
- 上架：还缺哪些资料/关联，点击后去哪里补齐。

后端已确认：这里判断的是 `catalog_product_id <= 0`，即尚未关联 ERP 商品目录中的标准型号，不是设备名称缺失，也不能直接认定为商城分类映射失败。

建议文案：“上架资料待完善：未关联目录型号、未上传商品图片、未设置零售价”；型号说明：“设备名称已录入，请从商品目录选择对应型号，用于分类与规格关联。”按钮统一指向“完善上架资料”。

另有新旧原因字段并存：后端后续流程更新 `turnover_action_reason`，库存页仍显示 `turnover_action`。应让按钮、原因说明使用同一次决策的结果，防止操作已变而提示仍旧。

证据：[目录型号判定](/Users/a123/Documents/1-work/niucloud/niucloud/niucloud/addon/hsx_erp/app/service/admin/ErpWarehousePolicyService.php:78)、[更新操作原因](/Users/a123/Documents/1-work/niucloud/niucloud/niucloud/addon/hsx_erp/app/service/admin/ErpStockService.php:1441)、[移动端读取原因](/Users/a123/Documents/1-work/niucloud/niucloud/site-uniapp/src/addon/hsx_erp/pages/stock/list.vue:117)。

### 6. 经营看板十二项指标同级，老板需要自己找重点

实际首屏由十二张等权重卡片组成，采购/销售单数在前，净利润、现金流分散；库存、今日和期间指标混排。

建议默认优先显示“期间净利润、期间净现金流、当前库存占资、超龄库存”，并明确时间范围。下接待办与异常，图表、绩效和最近单据后置。角色偏好可以切换，但不额外强制增加业务步骤。

证据：[看板指标](/Users/a123/Documents/1-work/niucloud/niucloud/admin/src/addon/hsx_erp/views/erp/workbench/index.vue:181)。

### 7. 移动应付款的重复维度与空状态

实际已结清记录仍展示业务来源、业务场景、方向、渠道、挂账约定、结算进度、插件、业务说明，再显示负责人和金额。顶部与底部各展示一次剩余应付。

建议默认保留对象、业务摘要、未结金额、结算状态和详情入口；原始来源、单据关系和解释性文字展开查看。默认“待付款”筛选下没有记录时，文案应为“当前没有待付款”，并可切换全部记录，而不是泛称“暂无应付记录”。

## 四、源码发现：需要与视觉优化一起处理的准确性问题

| 优先级 | 问题 | 建议 | 验证边界 |

| 高 | 应收/应付顶部写“总额”，实际只合计当前页列表 | 立即标“本页”；若需要全部，则由同一筛选条件的聚合结果提供，不必改表 | 源码确认；本地只有少量记录，未验证跨页变化 |

## 五、编号和信息层级的统一规则

| 信息 | 默认显示 | 详情/核对要求 |
| --- | --- | --- |
| 型号、规格、客户/供货商 | 主信息 | 身份缺失明确提示，不用内部 ID 假装姓名 |
| IMEI、SN | 核机信息，保留搜索和复制 | 扫码精确匹配；付款、出库、退货确认时展示完整标识，不能仅凭尾号操作 |
| 采购、销售、回收业务单号 | 次要信息或关联入口 | 完整保留、可检索、可复制、可追溯 |
| 内部资产 ID、用户 UID、插件键 | 不占日常主视觉 | 系统记录中保留，供管理排查 |
| 成本、成交、利润、已结算、现金 | 按业务阶段展示 | 明确本设备/整单、预计/实际、当前/期间，未知不显示为 0 |
| 状态与异常 | 一个主状态 + 必要风险 | 相同状态不重复；每个阻碍给原因和处理入口 |

## 六、建议优先维护三个公共组件

1. **列表工作区**：紧凑统计、关键词和快捷状态、更多筛选、已选条件、我的待办、字段选择；管理端首屏看到记录，手机首屏出现设备卡。
2. **业务身份名片**：设备型号/串号、往来人、中文来源；业务单号展开，技术 ID 进入系统记录。沿用并增强现有身份/来源组件，避免每页各写一套。
3. **设备经营摘要**：当前阶段、库位、库龄、成本/利润、结算状态、负责人和下一步。完整成本、维修、履历及凭证按需展开；移动端底部保留主要操作及“更多”。

两端统一信息规则，不强求使用同一种布局。管理端适合批量处理和对比，移动端适合扫码、快速核对和完成当前动作。

维修继续保持可选：无维修不强制走流程；发生维修才显示结果和费用。失败、零售价处理、报损等出口必须保留，机器成本与维修费用不能因流程关闭而消失。本轮不改变这些业务规则。

## 七、实施顺序与验收标准

### 第一批：准确性与最高频页面

- 修正统计范围、金额名称、负数图表、身份标签。
- 库存列表减负、财务来源组件精简。
- 移动采购详情调整顺序、修正设备详情入口。

### 第二批：统一体验

- 公共组件推广到采购、销售、退货、收付列表。
- 经营看板按利润、资金、周转和待办重新排序。
- 设备档案保留摘要，历史与次要操作按需展开。

### 验收清单

- 管理端 1280 × 720 首屏至少能看见设备表头和首条记录。
- 移动端 375/390/430 宽度能快速看到对象、状态、核心金额和下一步；大金额不省略。
- 看不到裸露的插件键/内部 UID；业务单号、完整 IMEI/SN 仍可核对追溯。
- 同一状态不重复；筛选折叠后仍知道当前使用哪些条件。
- 翻页不会让“全量总额”悄悄变成当前页数字；亏损不会被图形隐藏。
- 缺资料或不能处理时，说清缺什么、原因是什么、去哪里处理。
- 多设备采购进入详情能定位原设备；列表返回保留筛选、页码和滚动位置。
- 验收、维修等可选步骤关闭后不制造新的卡点，已发生费用仍完整保留。
- 本轮改版优先复用现有字段和接口；如需要全量汇总接口调整，单独列清变更，不改数据库结构。
