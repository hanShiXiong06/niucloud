# 采购、整备、退货与出库成本规则

## 一、成本口径

单台设备必须同时保留以下三个口径，禁止只用一个“成本”字段承载全部业务含义：

- 供应商结算本金：采购时与供应商确认的设备货款，也是应付、付款和采购退货的结算上限。
- 整备成本：维修、配件、人工、检测等已经实际发生且通常无法向原供应商收回的费用。
- 当前总成本：供应商结算本金 + 整备成本 + 合法的内部成本修正，用于库存估值和销售毛利。

供应商调价会改变供应商结算本金和应付；整备费用只增加设备总成本，不改变原供应商应付；内部成本修正只做库存纠错，不能静默改供应商往来。

## 二、岗位执行步骤

### 1. 采购员收货

1. 按设备录入采购价、IMEI/SN、仓库和库位。
2. 系统按设备生成应付，采购价成为供应商结算本金。
3. 采购后若供应商重新议价，使用“供应商调价”；已经付款的原应付不得直接改写，需由财务处理供应商补收或退款。

### 2. 仓库或整备人员登记费用

1. 在设备成本管理中选择“整备费用”。
2. 录入维修、配件、人工或检测费用及原因。
3. 系统增加 `refurbish_cost` 和 `total_cost`，设备标记为已整备；原采购本金、应付和已付款保持不变。
4. 每次登记必须带幂等请求号并生成资产流水、账目流水，重复提交不得重复加成本。

### 3. 采购退货判断

系统在设备级自动判断，不允许业务人员自行选择财务分流：

- 未发生整备且无未分类成本：允许标准采购退货。
- 已发生整备或整备已开始/完成：禁止标准采购退货，引导销售出库。
- 总成本与“供应商本金 + 整备成本”不一致：先归类差额，再决定是否可退。

供应商确认退回金额不得超过供应商结算本金。若供应商另给补偿，补偿部分走独立财务调账，不能抬高采购退货本金。

## 三、采购退货资金拆分

设供应商本金为 `P`，已付款为 `A`，供应商确认退回金额为 `R`：

- 未付款 `U = max(P - A, 0)`。
- 优先冲销未付款 `offset = min(U, R)`。
- 退款应收 `refund = max(R - offset, 0)`。
- 退货后保留应付 `retained = U - offset`。

完全没有付款或折账事实（`A = 0`）时采用简化规则：确认退货即整台取消采购往来，强制作废该设备全部应付，不填写供应商退款金额、不生成退款应收，也不允许保留应付尾款。

采购退货只有两个角色：业务管理员确认机器已经实际交还供货方；财务仅在产生退款应收时确认实际到账。业务管理员点击“确认退货”后，设备立即退出库存并自动处理往来，不再增加仓库或主管审批步骤。每台退货设备保存本金、冲销、退款应收、保留应付和策略快照，支持审计追溯。

## 四、整备后设备的销售处理

整备后的设备只能按销售出库处理，销售毛利必须使用当前总成本：

- 采购本金 5500，整备费用 100，当前总成本 5600。
- 售价 5500：毛利 -100，真实反映整备损失。
- 售价 5600：毛利 0。
- 售价高于 5600：差额为毛利。

销售人员只决定实际售价；系统不得因为希望不亏而自动把售价改为 5600。

## 五、权限和异常控制

- 业务管理员：录入采购、核对设备退货资格，并在机器实际交还供货方后确认退货。
- 仓库/整备人员：登记整备状态和整备费用，不得修改供应商应付。
- 财务：确认付款、供应商退款到账、额外补偿和财务调账。
- 销售员：按当前总成本查看预估毛利并销售出库。
- 管理员：处理历史未分类成本和异常数据修复，所有修复必须保留原流水并记录归类原因。

“确认退货”提交前必须再次展示设备、IMEI、供货方和预计财务结果，并要求操作人确认已经退机。提交后第一版不提供普通撤销或冲正入口；极低频录错由后续超级管理员纠错能力处理。

采购入库完成后，设备需要退出一律走采购退货。普通采购列表不再展示“撤销批次”；重复录入或采购事实从未发生属于管理员数据纠错，不与正常退货并列展示。列表和设备详情入口统一叫“采购退货”，退货页最终按钮统一叫“确认退货”。

禁止通过重新安装插件解决字段或幂等问题。开发库和商用升级均执行集中式增量迁移，只补字段与索引，不删除财务数据。
