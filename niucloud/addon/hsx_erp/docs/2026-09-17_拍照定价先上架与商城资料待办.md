## 一、本次明确的业务规则

客户已确认：拍照定价交接后，客户小程序立即可见、可购买；细节由商城运营后补。

本次将“能否销售”和“资料是否完善”拆开，不再用资料未补齐阻挡具备基本条件的销售。

1. ERP 人员只负责核对设备、拍照、销售定价并交接。
2. 分类已有有效对应、库存允许销售时，生成商城商品并上架，关联原 ERP 设备。
3. 商城运营看到独立的资料待办，补充容量、颜色、成色、电池、保修等展示资料。
4. 保存进度后为“处理中”，核对完成后为“已完成”。完成与否不改变价格、库存或交易状态。
5. 分类未对应、图片缺失、价格无效、设备已售/调走等情况，不能强行上架，必须显示具体原因。

这是面向新操作的修复和增量功能。不清库、不批量改历史商品、不补造历史待办，不重复创建采购应付或销售应收。

## 二、原报错的根因

报错：`Undefined array key "recycle_material_owner"`。

原代码在三元表达式的条件里使用了默认值，但满足条件后又直接读取不存在的数组键。新站点或未保存该项配置时就会报错。`category_mode`、`spec_mode`、`publish_mode` 存在同类风险，一并修复。

修复文件：`niucloud/addon/hsx_erp/app/service/admin/ErpConfigService.php`。

如果只需要紧急消除该配置报错，可以仅替换此文件并按现有部署流程刷新 PHP/应用缓存。但是本文的新业务模式必须成套更新 ERP 和商城插件，不能只换这一个文件就启用。

## 三、如何启用

入口：ERP → 业务规则 → 商城渠道 → 渠道发布方式 → **先上架，运营后补**。

配置值：`marketplace.channels.phone_shop.publish_mode = basic_first`。

原有“直接发布”和“运营逐台确认”保留。不会自动改变现有站点的默认配置。

同时确认：

- 商城渠道已开启，当前仓库允许商城销售，设备销售去向为商城。
- ERP 与商城分类已有对应关系，或允许在商城待办里人工选择有效分类。
- 拍摄、定价等岗位继续使用现有任务分工配置。
- 如希望保存资料后自动流转，可使用原有的自动发布配置；否则点击交接按钮进行确认。
- 给运营人员分配“商城资料运营”和“完善商品资料”权限；需要处理未匹配分类并上架的人员还需“货源建品上架”权限。

## 四、岗位操作 SOP

### 1. 拍照、定价人员

入口：ERP 库存中心 / 管理端小程序设备详情。

1. 使用完整串号、设备资料确认当前机器。
2. 上传商品图片、填写销售价格。
3. 点击“上架并交接资料”，确认提示中的销售影响。
4. 查看实际结果：
   - **已上架可售，资料待商城运营完善**：客户可在小程序分类中检索并购买。
   - **尚未上架，分类待对应**：照片、价格已交接，商城运营处理分类后才能销售。
   - **交接失败及具体原因**：资料仍保留，按提示处理，不需要重复录入整台设备。

图片和价格保存成功，不等于上架成功；最终以商城返回的上架结果为准。

### 2. 商城资料运营

入口：`site/phone_shop/intake/list`，菜单名称为“商城资料运营”，原路径和菜单主键不变。

1. 用型号、IMEI 搜索，或筛选资料进度。
2. 列表分别显示“商城状态”和“资料进度”，不要将两者混淆。
3. 对“已上架可售 / 待完善”的记录，点击“完善资料”打开抽屉。
4. 查看同步照片和折叠的质检资料，补充标题、副标题、容量、颜色、成色、电池、保修到期日。
5. 尚未处理完，点击“保存进度”；确认处理结束，点击“核对完成”。
6. 信息确实未知时可以保留未知；完成前会明确提醒仍未确认的项目，不会自动填写成 100% 电池、正常保修等虚假值。
7. 需要后续修正，可重新打开已完成记录继续编辑；保存进度会重新进入处理中。

抽屉包含加载、失败重试、保存中状态和未保存退出提醒；结构化质检、处理历史折叠展示。

资料待办当前记录处理人、版本、处理时间以及最近 20 次处理动作。它是共享岗位待办，不是新增独立的排班/派单系统，也没有新增外部通知发送。

### 3. 分类异常由谁处理

没有分类就不能实现“按分类找到商品”，因此分类属于最小上架条件，不属于可以完全省略的细节。

- 分类有对应：按已有 ERP 目录投影或商城独立映射自动使用。
- 没有对应：在商城资料运营页选择正确分类并上架，沿用原有映射回写机制。
- 分类已隐藏、被删除、属于其他站点或父子路径错误：阻止建品并显示原因。
- 商品已经建立后，资料抽屉不会偷偷修改分类。需调整分类时使用原商品管理入口和原有权限。

### 4. 财务

本次不新增财务操作步骤。补资料不改设备成本，不重复入库，不新建账款，不回写付款状态。

## 五、关键保护和限制

| 场景 | 处理结果 |
| --- | --- |
| 重复点击交接 | 同一货源不重复创建商品；以实际商城状态反馈 |
| 商品已售、订单占用或已下架 | 补资料不恢复库存、不自动重新上架 |
| 交接后 ERP 售价又改变 | 旧货源不得按旧价上架，提示重新交接最新价格 |
| 交接后设备已售或调走 | 建品前在同一事务重新锁定并核对 ERP 设备状态 |
| ERP 上架核对服务未响应 | 明确报错并保留货源，不绕过保护 |
| 两人同时编辑同一份资料 | 后提交的过期版本被拒绝，不覆盖先保存的结果 |
| ERP 再次发送已建品资料 | 保留商城运营已填写资料与待办进度 |
| 运营请求携带价格、库存或资产 ID | 不在允许修改的字段清单内，不写入 |
| 代理站点已有商品副本 | 仅同步展示资料，不重复铺货、不改代理库存及价格 |
| 代理资料同步失败 | 提示本站已保存、代理同步未完成，可重试资料保存；不会误报全部成功 |
| 关闭商城渠道 | 不能新建上架；已有资料待办可继续处理，不改变上下架状态 |
| 信息缺失 | 显示未知/待确认，不伪造数据 |

ERP 和商城仍通过事件契约对接。没有将商城模型依赖写进 ERP；商城建品沿用已有标准服务及显式站点入口。

质检报告沿用 ERP 传入的原始/结构化数据及原有展示规则，本次抽屉只读，不提供改写质检结果的入口。照片、价格仍由 ERP 主流程负责，运营资料抽屉不开放这两项编辑。

## 九、上线后的一台设备验收

由有权限的业务人员在已确认可使用的测试站点执行，不使用未知来源或有真实交易占用的设备：

1. 选一台 ERP 在库、允许商城销售且分类可对应的设备，确认原成本、完整串号。
2. 仅填照片和销售价格，交接后确认商城创建一个商品，串号、价格、图片、质检均对应。
3. 在客户小程序对应分类能找到，详情价格正确、购买入口可用。
4. 运营筛选“待完善”，保存电池/保修等资料，状态变为处理中；商品仍可售且售价未变化。
5. 核对完成，查看处理人和记录；再次交接不产生第二个商品。
6. 补资料前后比较 ERP 成本、库存与账目，应没有由补资料引起的变化。
7. 另用一台分类未对应的测试设备，确认只有待办而没有错误商品；补好分类后再发布。
8. 按现有成交验收流程检查下单、库存占用、ERP 出库/账务；不要通过补资料按钮恢复已售库存。

遇到异常，先记录设备、货源、实际提示与时间，保留原账款/商品，不清空数据或绕过上架保护。
