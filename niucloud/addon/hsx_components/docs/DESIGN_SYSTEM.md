# HSX 产品设计规范

版本：`0.1.0`　适用端：平台后台、站点后台、UniApp H5/小程序/App

这份规范是代码合同，不是效果图说明。颜色、字号、间距、圆角、阴影、动效和层级必须优先使用
组件库令牌；业务插件不得再建立一套相似变量。

## 1. 产品原则

1. 信息优先：先让用户看懂状态、价格、责任和下一步，再增加装饰。
2. 层级稳定：同一种信息在不同页面保持相同字号、颜色和间距。
3. 状态完整：默认、悬停、聚焦、加载、禁用、空态、错误、成功、溢出必须全部考虑。
4. 反馈可预期：操作前说明风险，操作中显示进度，操作后给出结果和恢复路径。
5. 动效克制：动效只解释层级变化和操作结果，不做无意义循环动画。
6. 双端一致：平台端和移动端表达同一种语义，但交互遵循各端习惯。
7. 无障碍默认开启：键盘焦点、语义标题、颜色对比、减少动画不作为后补工作。

## 2. 设计令牌

| 类别 | 规则 |
| --- | --- |
| 间距 | Web 使用 4/8/12/16/20/24/32/40/48/64px；移动端使用逻辑 px 与响应式间距令牌 |
| 圆角 | 输入 6px、普通卡片 10–14px、重点容器 20px、胶囊 9999px |
| 正文 | Web 14/22px；移动端按窗口等级使用 14–15px / 21–23px |
| 标题 | 卡片 16、区块 20、页面 28px；移动端使用响应式 15–28px 分级 |
| 动效 | 快速 120ms、常规 200ms、强调 320ms |
| 颜色 | 只使用 primary/success/warning/danger 和 text/bg/border 语义变量 |
| 层级 | sticky 20、dropdown 1000、overlay 2000、toast 3000 |

运行时代码可通过 `hsxDesignTokens`、`hsxMobileDesignTokens` 获取只读令牌。样式使用
`--hsx-*` 或 `--hsx-mobile-*` 变量。

UniApp 的字号、控件高度、卡片内边距和区块间距由 `HsxThemeProvider` 根据当前 App 窗口
统一下发。业务组件禁止通过页面级 `:deep()` 修改 uview-plus 内部字号；第三方组件存在内联样式时，
必须由 HSX 包装组件读取令牌后通过 Props 传入。

## 3. 排版和长文本

- 页面只允许一个页面级标题；区块标题按内容层级递进，不用字号模拟层级。
- 辅助文案不能比正文更抢眼；价格、风险和状态使用语义色，不使用随意色值。
- 单行截断使用 `HsxText ellipsis`，多行使用 `:lines="2"`；Web 端溢出后自动启用 Tooltip。
- 编号、金额和百分比使用等宽数字；重要金额保留单位，不只依赖颜色区分涨跌。
- 用户必须查看完整内容的字段不能截断，应进入详情、弹窗或 `HsxOverflow`。

## 4. 布局、列表和溢出

- 表单标签、操作区和列表行对齐到统一网格，不使用大量临时 margin 修补。
- Web 响应式页面使用 `HsxGrid`；UniApp 使用 `HsxResponsiveGrid/HsxSplitPane/HsxPageList columns`；连续动作使用 `HsxStack`，不得重复手写 flex 规则。
- 日期控件默认宽度：日期 180px、日期时间 220px、区间 360px；只有查询栏等明确场景使用
  `full-width`。
- 横向标签、表格工具和窄屏动作使用 `HsxOverflow`；滚动容器必须支持键盘焦点。
- 列表必须定义 Loading 骨架、空态、点击态和分隔规则，使用 `HsxList` 统一处理。

## 5. 动效规则

| 场景 | 动效 | 时长 |
| --- | --- | --- |
| Hover/按下/颜色切换 | 状态过渡 | 120ms |
| 弹窗、抽屉、列表插入 | fade/scale/slide | 200ms |
| 页面首屏重点模块 | fade-up | 260–320ms |
| 持续加载 | 进度或骨架 | 与真实任务绑定 |

禁止对正文、价格和核心按钮做持续漂浮、闪烁或无意义缩放。系统启用“减少动态效果”时，
`HsxMotion` 自动缩短到 1ms。

## 6. 进度、加载和结果

- 小于 1 秒的操作不弹全局 Loading；1 秒以上显示局部 Loading；阻断全局导航才使用全局 Loading。
- 有真实百分比时使用 `HsxProgress`；无法计算进度时使用骨架或不确定态，不伪造百分比。
- 失败反馈必须包含原因和下一步；危险操作使用二次确认，按钮文案写具体动作。
- 移动端震动不是装饰：普通选择 `light`、警告 `medium`、危险确认 `heavy`，被动刷新不震动。

## 7. 弹窗规范

- 普通确认使用中心弹窗；复杂表单使用底部/右侧抽屉；任务式长流程使用全屏。
- 标题说明“要做什么”，正文说明影响，主按钮使用动词，取消按钮保持稳定位置。
- 关闭遮罩是否可用由数据损失风险决定；未保存表单默认禁止误触遮罩关闭。
- Web 使用 `HsxDialog`，移动端使用 `HsxPopup` 或 `useModal`，不要直接散落调用底层库。

## 8. 暗黑模式

- 组件不能用纯白/纯黑硬编码背景；必须使用 surface/elevated/muted 三层语义背景。
- 阴影在暗黑模式降低存在感，边框承担更多层级表达。
- 图片背景必须增加可控渐变遮罩，保证标题和按钮在两种主题下可读。
- 新组件未在亮色和暗色下同时通过演示，不得进入公开出口。

## 9. 开发准入

每个公开组件必须具备：稳定命名、完整 Props/Events/Slots 类型、Template 与 TSX 调用示例、
亮暗主题、窄屏、长文本、Loading/Empty/Error 状态、键盘或触控反馈、测试和 API 文档。

业务组件只组合公共能力并绑定业务接口，不能复制公共组件源码。发现业务页第二次出现同类交互时，
先评估抽入公共层，再继续开发。
