## 3. 本次功能闭环

```text
A 分享给 B → B 首次绑定 A
B 分享给 C → C 首次绑定 B
C 的资料审核通过且已核对付款
        ↓
生成一张分销业务单
        ├─ 一级：B（项目一级基础佣金 × 当前准入模式系数）
        └─ 二级：A（项目二级基础佣金 × 当前准入模式系数）
        ↓
保护期结束 / 管理员立即结算
        ↓
进入会员佣金账户和账户流水
        ↓
退款申请：冻结未结算佣金
退款取消：恢复待结算
退款完成：按退款比例冲红；余额不足形成欠款；后续佣金优先抵扣欠款
```

核心规则：

1. 每个项目可选择“所有会员”或“按会员等级”两种推广资格模式。
2. “所有会员”不读取会员等级权益：当前站点已登录且状态正常的会员可直接分享，一级和二级佣金系数固定为 100%。
3. “按会员等级”由 `/site/member/level` 中的“项目推广分佣”权益控制资格、一级/二级开关及佣金系数。
4. 未保存资格模式的历史项目默认按会员等级判断，升级后不会自动扩大推广范围。
5. 项目控制基础佣金、固定金额/比例、保护期和是否要求审核前核对付款。
6. 推荐关系复用框架 `member.pid`，执行“首次有效关系优先”，后续邀请不得覆盖。
7. 自我邀请、循环邀请、跨站点数据均被拦截。
8. 分销开启前已通过的历史工单不追溯发佣。
9. 工单、佣金单、佣金明细、账户流水和退款冲红均具备幂等约束。

## 9. 测试过程中发现并修复的问题

| 问题 | 风险 | 处理结果 |
| --- | --- | --- |
| 当前 ThinkPHP 版本不支持 `innerJoin()` | 退款补偿任务运行时报错 | 改为框架支持的 `join()`，增加合同回归锁 |
| 会员等级已停用仍可能被当作有资格 | 停用等级继续获得佣金 | 资格查询加入等级 `status=1` 领域校验 |
| 只有审核服务校验付款，佣金核心层缺少兜底 | 脚本或未来入口可能绕过核款生成佣金 | 佣金创建核心层再次校验 `payment_confirmed_at` |
| 自绑/循环拒绝日志在事务内写入后又抛异常 | 审计日志随事务回滚而丢失 | 事务返回拒绝事实，事务结束后独立写审计再抛业务异常 |
| 会员端资格结果可能携带完整会员和权益结构 | 泄露手机号、账户或内部权益配置 | 会员端仅返回资格、等级、系数等展示必需字段 |
| 历史异常推荐链可能让同一人同时获得两级佣金 | 重复发佣 | 创建快照时排除自指和一、二级同人异常 |
| 补偿方法只能全局扫描，不利于隔离测试和定向运维 | 测试或人工补偿可能波及其他站点 | 补建、退款补偿、到期结算均支持可选 `site_id` 范围 |
| 仅在 `Addon::upgrade()` 中调用迁移 | 标准一键升级不会调用该方法，老站点可能缺少分销表 | 新增 `app/upgrade/v020/Upgrade.php`，调用幂等迁移并用 PHP 8.0 实跑通过 |
| 原 40 位邀请 token 超过微信小程序码 scene 可用长度 | 海报二维码无法稳定携带邀请关系 | 新增带 HMAC 的短签名凭证，保留旧 token 兼容，并增加篡改测试和服务端资格复核 |
| 推广资格被硬绑定会员等级 | 不想维护等级的项目无法做到“登录即可分享” | 新增项目级准入模式；所有会员模式固定 100% 系数，历史项目默认保留等级模式 |
| `GetPosterType` 无参数事件向监听器传入 `null` | `handle(array $data)` 在海报类型初始化阶段直接抛出 TypeError | 海报类型和海报数据监听器改为兼容空参数，并增加真实 `handle(null)` 回归测试 |

上述问题均已纳入自动化测试，复测通过。
