# 员工产出中心实施路径

## 第一阶段：准确的事实底座

- 扩展事实账本：契约版本、哈希、事实分类、方向、冲红关系、业务日期和追溯入口。
- 新增指标目录、员工日汇总、数据异常表。
- 实现接收校验、幂等冲突、完整冲红、投影重建和对账。
- 保持旧版会员卡事件兼容。

验收：

- 相同事件重复 100 次只产生一条事实。
- 相同事件 ID 改变任一关键字段会被拒绝并记录异常。
- 正向事实加完整冲红后的净产出为 0。
- 删除日汇总后可以从事实账本无损重建。

## 第二阶段：核心业务接入

- 回收：签收、完成质检、定价、确认回收及退回。
- ERP：采购入库、拍照完成、销售开单、收款确认、付款确认。
- 会员卡：开卡、核销及其冲红，升级为 v1 契约。

验收：

- 每个业务动作有稳定事件 ID、操作人和可打开的业务对象。
- 业务失败或事务回滚不产生事实。
- 绩效插件停用不阻断业务；恢复后 outbox 可补发。

## 第三阶段：可用的多端产品

- PC：产出总览、员工排行、指标分布、事实追溯、异常中心。
- 移动端：今日/本周/本月、员工列表、员工详情、业务明细。
- 保留原经营日报、周报、月报功能。

验收：

- 任何汇总数字都能下钻到事实。
- URL 查询参数可以复现当前时间范围、员工和指标筛选。
- 无数据、加载、失败、异常和冲红状态均有明确展示。

## 第四阶段：历史补数与发布治理

- 为已上线业务增加历史事实提供器。
- 提供按日期重建和全量重建命令。
- 上线前运行事实与源业务表的抽样对账。
- 增加定时异常扫描和管理员提醒。

## 暂缓范围

- 工资、提成、奖金、扣款的具体计算。
- 考勤系统。
- 主观评价和复杂评分模型。

上述能力只预留读取事实、规则版本和结算快照的扩展边界。
